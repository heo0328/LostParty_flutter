# Firebase 파티 제품 흐름 통합 기준

## 1. 문서 목적과 상태

이 문서는 LOSTPARTY의 Firebase 기반 다중 사용자 전환에 앞서 사용자, 게임 계정, 캐릭터, 파티 모집, 반복 파티, 회차 완료, 알림 및 개인 레이드 히스토리의 제품 흐름을 하나의 기준으로 정리한다.

현재 문서는 1차 설계 합의 문서다. 코드 구현 지시서나 Firestore 최종 스키마는 아니며, 각 Firebase 기능은 이 문서의 확정 정책을 해당 작업 단위의 데이터 계약과 서버 명령으로 구체화한 뒤 구현한다. 로컬 Fake 검증 기간에 적용했던 Firebase 전역 구현 보류 단계는 종료됐으며, 계약이 준비된 기능은 단계적으로 구현할 수 있다.

이 문서는 다음 기존 문서보다 이번 재설계에서 합의한 제품 흐름을 우선하여 기록한다.

- `BACKEND_PARTY_ARCHITECTURE.md`
- `../product/PARTY_PARTICIPATION_RULES.md`
- `PLAYER_FIREBASE_MIGRATION_REVIEW.md`
- `../integrations/FIREBASE_INITIAL_SETUP_REVIEW.md`

기존 문서의 Firebase UID 직접 사용, 파티 완료 및 주간 회차 관련 내용은 이 기준에 맞춰 정리한다.

## 2. 핵심 용어

### 인증 및 사용자

- `AuthUid`: Firebase Authentication이 발급하는 인증 주체 식별자
- `PlayerId`: LOSTPARTY 내부에서 한 명의 사용자를 영속적으로 식별하는 ID
- `GameAccountId`: 한 Player가 등록한 본계정 또는 부계정의 서버 식별자
- `CharacterId`: 한 게임 계정에 속한 캐릭터의 서버 식별자
- `Local Character Row ID`: Drift에서만 사용하는 기기 내부 행 식별자

식별 관계는 다음과 같다.

```text
Firebase AuthUid
-> Auth Binding
-> LOSTPARTY PlayerId
-> GameAccountId
-> CharacterId
```

### 파티 및 신청

- `파티장`: 4인 파티의 책임자 표시 명칭
- `공대장`: 8인 공격대의 책임자 표시 명칭
- 파티장과 공대장은 시스템 권한상 같은 책임자 역할이며 파티 규모에 따라 표시 명칭만 다르다.
- `승인 대기 신청`: 사용자가 파티에 신청했지만 아직 승인 또는 거절되지 않은 상태. 사용자 문서와 UI에서는 `pending` 대신 이 표현을 사용한다.
- `1회성 파티`: 이번 회차 완료 후 더 이상 다음 회차를 유지하지 않는 파티
- `다음 주도 함께하기 파티`: 완료 후에도 방과 다음 회차 준비 구성을 유지하는 반복 파티
- `회차`: 주간 초기화 경계 안에서 하나의 파티가 진행하는 특정 레이드 실행 단위

## 3. 식별자와 소유권 원칙

### 확정 원칙

- Firebase `AuthUid`는 인증과 `PlayerId` binding에만 사용한다.
- 파티, 신청, 투표, 그룹, 권한 및 중복 참가 판정에는 `PlayerId`를 사용한다.
- 한 Player는 여러 게임 계정을 소유할 수 있다.
- 한 게임 계정은 여러 캐릭터를 소유할 수 있다.
- 파티 참가의 실제 단위는 `CharacterId`이며 사람 단위 권한과 중복 판정은 `PlayerId`로 한다.
- Drift 자동 증가 ID는 서버 `CharacterId`로 사용하지 않는다.
- 대표 캐릭터는 최초 추천과 표시 설정이며 Player 식별자로 사용하지 않는다.
- 내부 `AuthUid`와 `PlayerId`는 일반 사용자 화면에 노출하지 않는다.
- 화면에는 필요한 경우 게임 계정 표시명, 캐릭터명, 직업, 역할과 참가 상태를 표시한다.

### 후속 설계가 필요한 항목

- 서버 `CharacterId` 발급 방식
- 동일 캐릭터 판정과 캐릭터명 변경 추적 방식
- Anonymous Auth 복구 및 새 AuthUid 재연결 정책
- 사용자 검색이 필요한 기능을 위한 공개용 고유 ID 제공 여부

## 4. 데이터 저장 경계

### 서버 기준 Current State

여러 사용자가 공유하거나 서버가 최종 판정해야 하는 데이터다.

- Player와 Auth binding
- 게임 계정과 캐릭터 소유 관계
- 파티방과 현재 회차
- 모집 활성화 상태
- 신청, 승인과 거절
- 현재 참가자, 역할과 자리
- 파티장 또는 공대장
- 다음 주도 함께하기 설정
- 회차 완료와 완료 취소 상태
- 완료 당시 참가자 스냅샷
- 다음 회차 준비 구성
- 사용자별 완료, 완료 취소, 구성 변경 및 해산 이벤트
- 그룹과 그룹 멤버십
- 전체 및 방별 알림 설정

### 로컬 개인 데이터

현재 디바이스에서만 사용하는 개인 데이터다.

- 캐릭터 개인 메모
- 캐릭터 카드 표시 여부와 순서
- 캐릭터별 표시 레이드 수, 선택 레이드와 표시 순서
- 개인 레이드 완료 기록
- 히스토리 표시 또는 숨김 상태
- 필터, 정렬과 접힘 상태 등의 UI 설정

로컬 데이터는 앱 재설치 또는 다른 기기에서 복원하지 않아도 된다.

### 행동 시점 Snapshot

특정 행동 당시의 값을 이후 변경과 무관하게 보존한다.

- 신청 당시 캐릭터와 역할 세팅
- 승인 당시 제출 정보
- 회차 완료 당시 참가 Player와 Character 구성
- 완료 당시 역할과 파티 위치
- 모집 생성 당시 레이드 카탈로그 버전

완료 후 참가 캐릭터나 파티 구성이 변경되어도 과거 완료 스냅샷은 바뀌지 않는다.

### 정적 기준정보

Git으로 버전 관리한다.

- 레이드 카탈로그
- 게임 및 직업 카탈로그
- 입장 레벨
- 일반 골드와 귀속 골드
- 역할 및 파티 구성 기준

## 5. 탭과 주요 사용자 화면

앱의 주요 하단 탭은 다음 네 영역으로 확정한다.

1. 레이드 현황
2. 내 계정
3. 레이드 모집
4. 설정

`레이드 현황`은 앱의 첫 화면이며 하나의 하단 탭 안에서 상단 페이지 전환으로 `진행 중 / 신청 중 / 완료 기록`을 구분한다. 완료 기록을 별도의 하단 탭으로 분리하지 않는다.

### 레이드 현황

#### 진행 중

- 내가 만들었거나 가입이 확정된 현재 레이드방
- 1회성 파티의 현재 회차
- 다음 주도 함께하기 파티와 다음 회차 준비 상태
- 현재 파티 구성, 참가 캐릭터 변경, 완료, 탈퇴 및 책임자 관리 진입

#### 신청 중

- 아직 가입이 확정되지 않은 승인 대기 신청
- 신청 상태 확인과 본인 철회
- 거절, 모집 종료 또는 다른 확정 참가로 종료된 신청 결과 안내
- 승인 대기 신청은 진행 중인 레이드와 섞지 않으며 참가 확정으로 취급하지 않음

#### 완료 기록

- 이번 주 완료 레이드와 지난 회차의 완료·미완료 종료 기록
- 파티 완료 이벤트로 생성된 로컬 기록
- 사용자가 직접 입력하거나 정정한 완료 기록
- 현재 주차와 과거 히스토리, 표시 중인 기록과 숨긴 기록 필터
- 새 회차로 전환된 이전 파티 상태는 활성 레이드방이 아니라 이 화면에서 확인

`레이드 현황`의 기본 상단 페이지는 `진행 중`이다. 상단 페이지 선택과 필터 상태는 개인 UI 설정으로 로컬에 유지할 수 있다.

### 내 계정

- 본계정과 부계정 관리
- 캐릭터 목록
- 캐릭터별 간략 데이터와 주간 레이드 표시
- 개인 완료 체크와 해제
- 캐릭터 설정 관리

### 레이드 모집

- 활성 모집 목록
- 공개·그룹 전용 모집 검색과 필터
- 다른 사용자의 레이드방 상세 확인과 가입 신청
- 새 레이드방 생성
- 모집에서 승인 대기 신청이 생성되면 `레이드 현황 > 신청 중`에서 관리
- 모집 생성 또는 가입 확정 후 현재 파티 관리는 `레이드 현황 > 진행 중`에서 수행

### 설정

- 내 게임계정 인증과 계정별 인증 상태 확인
- Lost Ark API 토큰 관리
- 전체 알림 기본값
- OS 알림 권한 상태와 설정 이동
- 완료 후 해산 확인 간소화 등 앱 공통 설정

## 6. 파티 생성, 신청과 승인

### 생성

- 파티는 기본적으로 1회성으로 생성한다.
- `다음 주도 함께하기` 기본값은 꺼짐이다.
- 파티 생성자는 선택한 캐릭터로 파티에 참가한다.
- 대표 캐릭터는 최초 추천값일 뿐 파티장 캐릭터로 강제하지 않는다.

### 신청

- 신청에는 `PlayerId`와 실제 참가할 `CharacterId`를 함께 제출한다.
- 신청은 승인형 또는 즉시 가입형일 수 있다.
- 승인 전 상태를 `승인 대기 신청`으로 표시한다.
- 신청 알림은 파티장 또는 공대장과 별도 승인권자에게 전달한다.
- 일반 참가자 전원에게 새 신청 알림을 보내지 않는다.

### 승인 이후

- 승인된 Player와 Character는 현재 참가 구성에 포함된다.
- 참가자 추가, 탈퇴, 참가 캐릭터 변경 및 책임자 변경은 현재 방 참가자에게 알림 대상이 된다.
- 기존 참가 충돌과 중복 참가 규칙은 `../product/PARTY_PARTICIPATION_RULES.md`를 기준으로 유지하되 PlayerId 의미와 회차 정책을 후속 갱신한다.

### 가입 승인 권한

- 파티장 또는 공대장은 현재 참가자 목록에서 `가입 승인 권한` 체크박스로 권한을 부여하거나 회수할 수 있다.
- 승인권자 수에는 제한을 두지 않는다.
- 현재 참가자에게만 권한을 부여할 수 있다.
- 승인권자는 승인 대기 신청을 확인하고 승인하거나 거절할 수 있다.
- 승인권자는 새 신청 알림을 받는다.
- 승인권자는 기존 참가자 추방, 다른 승인권자 지정, 모집 조건 수정, 다음 주도 함께하기 변경, 완료 취소, 책임자 위임 또는 파티 해산 권한을 갖지 않는다.
- 승인권자가 탈퇴하거나 추방되면 권한을 자동 회수한다.

## 7. 모집 활성화

- 모집 노출은 파티장 또는 공대장의 수동 설정과 실제 빈자리를 함께 판정한다.
- 내부적으로 `manualRecruitmentEnabled`와 `hasAvailableSlot`을 분리하고 두 조건이 모두 참일 때만 모집 목록에 노출한다.
- 파티장 또는 공대장이 직접 모집을 비활성화하면 자리가 생겨도 자동으로 노출하지 않는다.
- 수동 모집이 활성화된 상태에서 정원이 충족되면 자동으로 목록 노출을 중단한다.
- 정원 충족으로 노출이 중단된 뒤 탈퇴나 추방으로 자리가 생기면 자동으로 다시 노출한다.
- 새 회차 전환 시 자리가 남아 있고 수동 모집이 활성화되어 있으면 노출한다.
- 새 회차 전환 시 정원이 가득 차 있거나 수동 모집이 비활성화되어 있으면 노출하지 않는다.
- 모집 비활성화는 파티 완료나 해산을 의미하지 않는다.
- 정원이 충족되어도 파티 또는 회차를 자동 완료하지 않는다.
- 별도의 레이드 시작 선언은 사용하지 않는다.
- 수동 모집 활성화 변경 권한은 파티장 또는 공대장에게만 있다.

## 8. 다음 주도 함께하기

### 설정

- 모든 파티는 기본적으로 1회성이다.
- 파티장 또는 공대장은 참가자 승인 후에도 `다음 주도 함께하기`를 자유롭게 켜거나 끌 수 있다.
- 기존 참가자의 동의는 필요하지 않다.
- 일반 참가자는 이 설정을 변경할 수 없다.

### 꺼진 상태

- 파티는 1회성이다.
- 회차 완료 후 다음 회차를 유지하지 않는다.
- 완료 후 파티 데이터는 수정할 수 없다.
- 사용자 관점에서는 완료 후 해산 절차를 거쳐 방이 종료된다.

### 켜진 상태

- 완료 후에도 파티방과 참가자가 유지된다.
- 참가자는 완료를 이유로 자동 탈퇴하지 않는다.
- 원하지 않는 참가자는 직접 탈퇴할 수 있다.
- 완료 후부터 다음 수요일 오전 6시 전까지 참가자와 캐릭터 변경은 다음 회차 준비 구성에 반영한다.
- 파티 제목 아래에 빨간색으로 `다음 주 레이드 구성 현황입니다.`를 표시한다.

### 완료 후 설정 해제

- 완료된 반복 파티에서 파티장 또는 공대장이 `다음 주도 함께하기`를 끌 수 있다.
- 해제하면 다음 회차를 만들지 않고 1회성 완료 파티와 같은 종료 절차로 이동한다.
- 즉시 무확인 삭제하지 않고 해산 확인을 거친다.
- 설정 탭의 완료 후 해산 확인 간소화 여부와 관계없이 반복 설정 해제에는 항상 한 번의 종료 확인을 표시한다.
- 이번 회차 완료 스냅샷과 이미 생성된 개인 로컬 히스토리는 유지한다.

## 9. 현재 회차와 다음 회차 준비 구성

### 완료 전

- 별도의 다음 주 캐릭터 예약 항목을 만들지 않는다.
- 완료 전 참가자와 캐릭터 변경은 현재 회차에 적용한다.

### 반복 파티 완료 후

- 완료 당시 구성은 불변 Snapshot으로 보존한다.
- 이후 참가자 추가, 탈퇴와 캐릭터 변경은 다음 회차 준비 구성에 적용한다.
- 과거 완료 Snapshot은 변경하지 않는다.

### 수요일 오전 6시

- 기준 시간대는 `Asia/Seoul`이다.
- 완료되지 않은 현재 회차는 `미완료 종료`로 확정한다.
- 완료되지 않은 회차의 당시 참가자에게 미완료 종료 이벤트를 생성하고 각 앱의 로컬 히스토리에 지난주 결과를 반영한다.
- 1회성 파티의 미완료 회차는 서버 안전장치로 자동 종료하고 활성 파티와 모집 목록에서 제거한다.
- 반복 파티의 미완료 회차는 지난 회차만 종료하고 현재 참가 구성을 새로운 현재 회차로 승계한다.
- 완료된 반복 파티는 다음 회차 준비 구성이 새로운 현재 회차가 된다.
- 새 회차의 개인 진행 상태는 `미완료`에서 시작한다.
- 구성 점검 필요 상태에서 새 회차로 전환되면 현재 구성을 승계하되 모집 비활성화와 구성 점검 상태를 유지한다.
- 파티방 UI에서는 이전 회차 데이터를 더 이상 보여주지 않는다.
- 이전 완료 또는 미완료 종료 결과는 각 사용자의 `레이드 현황 > 완료 기록`에서만 확인한다.
- 서버는 알림 중복 방지와 동기화를 위한 최소 이벤트를 보관 기간 동안 유지할 수 있다.

## 10. 파티 완료

### 공통 원칙

- 정원 충족으로 자동 완료하지 않는다.
- 현재 파티원은 누구나 완료를 선언할 수 있다.
- 서버가 아직 완료되지 않은 회차인지 검증한다.
- 동시에 여러 사용자가 완료해도 최초 한 건만 성공한다.
- 완료 당시 방에 남아 있는 참가자만 완료 Snapshot에 포함한다.
- 완료 전에 탈퇴한 사용자는 완료 기록과 알림 대상에서 제외한다.
- 완료 시 현재 참가자에게 사용자별 완료 이벤트와 알림을 생성한다.

### 완료 확인

1회성 파티는 완료 전에 다음 결과를 안내한다.

- 현재 참가자에게 완료 알림 전달
- 완료 후 수정 불가
- 활성 모집 목록에서 제외
- 완료 후 해산 절차로 이동

반복 파티는 다음 결과를 안내한다.

- 이번 회차 완료
- 현재 참가자에게 완료 알림 전달
- 방과 다음 회차 준비 구성 유지
- 일반 파티원은 완료 취소 불가
- 파티장 또는 공대장은 허용 기한 전까지 완료 취소 가능

### 1회성 파티 완료 후

- 서버 회차를 최종 완료 상태로 전환한다.
- 모집, 참가자, 신청 및 캐릭터를 더 이상 수정할 수 없다.
- 완료 버튼을 해산 버튼으로 변경한다.
- 해산 확인 후 사용자 관점에서 방을 제거한다.

### 반복 파티 완료 후

- 방과 현재 참가자를 유지한다.
- 다음 회차 준비 상태로 전환한다.
- 참가자 탈퇴, 새 참가자 가입 및 다음 회차 캐릭터 변경을 허용한다.

## 11. 완료 후 해산 확인 간소화

### 기본 흐름

```text
완료 버튼
-> 완료 확인 알림창
-> 완료 처리
-> 해산 버튼으로 변경
-> 해산 확인 알림창
-> 해산
```

### 설정 활성화 시

```text
완료 버튼
-> 완료 확인 알림창
-> 완료 처리
-> 즉시 해산
```

- 최초 완료 확인은 항상 표시한다.
- 완료 자체를 무확인으로 실행하지 않는다.
- 설정은 완료 후 두 번째 해산 확인만 생략한다.
- 초기 적용 대상은 1회성 파티 완료 흐름이다.

## 12. 반복 파티 완료 취소

### 권한과 기한

- 파티장 또는 공대장만 완료를 취소할 수 있다.
- 일반 참가자는 완료를 선언할 수 있지만 취소할 수 없다.
- 완료 취소 마감은 `Asia/Seoul` 기준 매주 화요일 22:00이다.
- 화요일 22:00 이후 완료한 회차는 처음부터 취소할 수 없다.
- 화요일 22:00부터 수요일 오전 6시까지는 완료 상태 확정과 새 회차 전환을 위한 잠금 구간이다.
- 수요일 오전 6시 이후 이전 회차 완료 취소는 불가능하다.
- 시간 판정은 디바이스 시간이 아닌 서버 시간을 기준으로 한다.

### 완료 취소 확인

- 화요일 22:00 이전에는 취소 가능 기한을 완료 확인창에 안내한다.
- 화요일 22:00 이후에는 완료 후 취소할 수 없음을 명확히 안내한다.

### 구성 병합 복원

완료 취소 시 완료 당시 Snapshot과 현재 다음 회차 준비 구성을 비교한다.

- 완료 당시부터 계속 남아 있는 Player는 완료 당시 Character와 역할로 복원 시도한다.
- 완료 후 탈퇴한 Player는 자동 재가입시키지 않는다.
- 완료 후 새로 가입한 Player는 현재 참가 상태를 유지한다.
- 책임자가 변경된 경우 현재 책임자를 우선하고 탈퇴한 이전 책임자를 복원하지 않는다.
- 복원은 정원, 역할, 캐릭터 소유, 참가 충돌 및 주간 조건을 서버에서 다시 검증한다.

### 병합 복원 실패

- 병합 복원에 실패하면 현재 구성을 유지한 상태로 완료를 취소한다.
- 현재 구성이 이번 주 조건에 맞지 않으면 `구성 점검 필요` 상태로 전환한다.
- 구성 점검 중에는 모집을 비활성화한다.
- 문제가 있는 참가자 또는 캐릭터를 표시하고 조건을 해결한 뒤 모집을 다시 활성화한다.
- 각 참가자는 자기 캐릭터를 변경하거나 탈퇴할 수 있고 파티장 또는 공대장은 참가자를 추방할 수 있다.
- 모든 조건이 유효해지면 서버가 구성 점검 필요 상태를 자동으로 해제한다.
- 사용자가 별도 체크박스나 명령으로 검증을 우회해 강제로 해제할 수 없다.

### 완료 취소 이벤트

- 완료 당시 참가자에게 완료 취소 정정 이벤트와 알림을 보낸다.
- 현재 방 참가자 전체에게 회차 상태와 구성 변경 알림을 보낸다.
- 완료 후 새로 가입한 참가자에게는 다음 회차 준비 구성에서 현재 회차 구성으로 영향을 받을 수 있음을 안내한다.
- 완료 후 탈퇴한 완료 참가자에게는 개인 히스토리 정정 이벤트만 전달한다.
- 알림을 누르면 해당 캐릭터, 주차와 레이드의 로컬 기록 화면으로 이동한다.
- 화면에서 `완료 기록 유지` 또는 `미완료로 변경`을 선택한다.
- 초기 구현에서는 푸시 알림 액션 버튼으로 로컬 DB를 직접 변경하지 않는다.
- 사용자가 직접 관리한 로컬 완료 상태를 서버가 강제로 변경하지 않는다.

## 13. 탈퇴, 책임자 승계와 해산

### 일반 참가자 탈퇴

- 1회성 파티와 반복 파티 모두 완료 전 또는 허용 상태에서 개인 탈퇴를 제공한다.
- 일반 참가자의 탈퇴는 자기 자신에게만 적용된다.
- 일반 참가자는 방 전체를 해산할 수 없다.
- 탈퇴자는 이후 방 참가자 알림 대상에서 제외한다.
- 탈퇴 전 완료된 과거 Snapshot에서는 제거하지 않는다.

### 책임자 탈퇴

- 파티장 또는 공대장도 개인 탈퇴할 수 있다.
- 남은 참가자가 있으면 가입 시각이 가장 빠른 참가자에게 책임자 권한을 자동 이전한다.
- 가입 시각이 같으면 안정적인 보조 ID 정렬로 승계 순서를 결정한다.
- 남은 참가자가 없으면 방을 자동 해산한다.
- 책임자 변경은 현재 참가자 알림 대상이다.

### 참가자 추방

- 파티장 또는 공대장만 현재 참가자를 추방할 수 있다.
- 가입 승인권자는 참가자를 추방할 수 없다.
- 추방 전에 대상과 영향을 보여주는 확인창을 표시한다.
- 1회성 파티는 완료 전까지만 추방할 수 있다.
- 완료된 1회성 파티에서는 추방할 수 없다.
- 반복 파티 완료 전 추방은 현재 회차 구성에 적용한다.
- 반복 파티 완료 후 추방은 다음 회차 준비 구성에 적용한다.
- 화요일 22:00 이후에도 다음 회차 준비 구성의 추방은 허용한다.
- 추방된 사용자는 같은 방에 즉시 다시 신청할 수 있다. 잘못 선택한 Character를 바꿔 재신청하는 흐름을 막지 않는다.
- 추방된 사용자의 방별 알림 설정과 가입 승인 권한은 제거한다.
- 과거 완료 Snapshot에서는 추방된 사용자를 제거하지 않는다.
- 추방으로 자리가 생기면 모집 노출 조건을 다시 계산한다.
- 추방된 사용자와 현재 참가자에게 구성 변경 알림을 보낸다.

### 해산

- 파티장 또는 공대장만 방 전체를 해산할 수 있다.
- 반복 파티는 회차 완료 여부와 관계없이 해산할 수 있다.
- 1회성 파티는 완료 전에는 해산할 수 있고, 완료 후에는 완료 결과를 거쳐 해산 절차로 이동한다.
- 해산 시 현재 참가자와 승인 대기 신청자에게 알림을 보낸다.
- 사용자 관점에서는 방이 삭제되지만 서버는 이벤트 전달과 보존 정책을 위해 종료 상태를 일정 기간 유지할 수 있다.

## 14. 알림 정책

### 전체 알림

- 설정 탭에서 전체 알림 기본값을 켜거나 끌 수 있다.
- 기본값은 켜짐이다.
- 전체 알림 설정은 새로 참가하는 방의 방별 알림 초기값에만 적용한다.
- 전체 설정을 바꿔도 이미 참가한 방의 방별 설정은 변경하지 않는다.

### 방별 알림

- 각 파티방 우측 상단에 알림 아이콘을 표시한다.
- 최초 아이콘 상태는 방 참가 시점의 전체 알림 설정값으로 정한다.
- 방에서 아이콘을 변경하면 해당 방 설정만 바뀐다.
- 전체 알림이 꺼져 있어도 특정 방만 켤 수 있다.
- 전체 알림이 켜져 있어도 특정 방만 끌 수 있다.
- 탈퇴하면 해당 방의 알림 설정을 제거한다.
- 같은 방에 다시 참가하면 당시 전체 알림 설정을 기준으로 다시 초기화한다.

### OS 권한

- 앱 내부 알림이 켜져 있어도 OS 알림 권한이 꺼져 있으면 푸시가 표시되지 않는다.
- 사용자가 앱 또는 방 알림을 켤 때 OS 권한을 확인한다.
- 권한이 꺼져 있으면 알림을 받을 수 없음을 안내한다.
- 가능한 경우 권한 요청 또는 시스템 앱 설정 이동 버튼을 제공한다.

### 알림 대상 이벤트

- 새 신청: 파티장 또는 공대장과 승인권자
- 신청 승인과 즉시 가입: 관련 신청자 및 현재 방 참가자
- 참가자 탈퇴
- 참가 캐릭터 변경
- 책임자 변경
- 다음 주도 함께하기 설정 변경
- 파티 완료와 완료 취소
- 파티 해산
- 해산된 방의 승인 대기 신청자

## 15. 완료 이벤트와 서버 보관

### 사용자별 이벤트

푸시 알림만으로 로컬 동기화를 보장하지 않는다. 서버에 사용자별 이벤트를 생성한다.

```text
Player Event
  eventId
  type
  partyId
  cycleKey
  completionRevision
  playerId
  characterId
  raidId
  difficultyId
  occurredAt
  actorPlayerId
```

초기 이벤트 유형은 최소 다음을 포함한다.

- `partyCompleted`
- `partyCycleIncompleteEnded`
- `partyCompletionCancelled`
- `partyCompositionChanged`
- `partyDisbanded`

앱은 실행, 인증 및 Player 연결 완료, 관련 화면 진입 또는 푸시 진입 시 이벤트를 동기화한다.

### 중복 방지

- 한 회차의 완료는 `partyId + cycleKey + completionRevision`으로 구분한다.
- 동시에 여러 완료 요청이 와도 최초 한 건만 완료 이벤트를 생성한다.
- 클라이언트는 같은 `eventId`를 로컬에 중복 반영하지 않는다.

### 보관 기간

- 완료 이벤트는 생성 시점부터 4주, 즉 28일 동안 보관한다.
- 참가, 탈퇴, Character 변경, 책임자 변경, 추방과 해산 등 사용자 알림 이벤트도 생성 시점부터 28일 동안 보관한다.
- 보관 기간 이후 서버 TTL로 삭제한다.
- 사용자별 수신 확인 기반 삭제는 초기 구현에 포함하지 않는다.
- 수요일 오전 6시에 지난 회차를 활성 쿼리에서 즉시 제외하더라도 동기화용 최소 이벤트는 보관한다.
- 종료된 1회성 파티의 상세 원본과 완료 또는 미완료 종료 Snapshot은 종료 시점부터 28일 동안 보관한 뒤 삭제한다.
- 반복 파티방 Current State는 해산할 때까지 유지하며 회차 완료를 이유로 삭제하지 않는다.
- 반복 파티의 완료 또는 미완료 종료 회차 Snapshot은 회차 종료 시점부터 28일 동안 보관한다.
- 후속 사용자 평가 기능에 필요한 최소 완료 증명의 장기 보관 여부는 평가 기능 설계 시 별도로 결정하며 초기 범위에서는 영구 보관하지 않는다.

### 수요일 오전 6시 정리

즉시 만료 또는 새 회차 판정에서 제외할 대상:

- 지난주 활성 참가 점유
- 지난주 신청 충돌 판정 상태
- 지난주 현재 회차 편집 상태
- 완료 취소 가능 상태
- 다음 회차 병합 복원용 임시 비교 상태
- 종료된 1회성 파티의 활성 모집 상태

새 회차로 넘길 대상:

- 반복 파티방
- 다음 주도 함께하기 상태
- 다음 회차 참가자와 Character
- 역할과 파티 위치
- 모집 활성화 상태
- 방별 알림 설정

완료되지 않은 반복 파티도 현재 참가 구성을 새 회차로 승계한다. 완료되지 않은 1회성 파티는 새 회차로 재사용하지 않는다.

## 16. 개인 레이드 완료와 히스토리

### 서버 파티 완료와 개인 완료 분리

서버 파티 완료는 해당 방의 회차가 끝났다는 공동 상태다. 개인 레이드 완료는 사용자가 자기 캐릭터의 실제 인게임 현황을 관리하는 로컬 상태다.

- 서버 완료 이벤트를 받으면 로컬 기록을 자동 생성할 수 있다.
- 사용자는 LOSTPARTY 밖에서 완료한 레이드를 직접 체크할 수 있다.
- 사용자는 잘못 자동 반영된 완료를 직접 미완료로 변경할 수 있다.
- 로컬 변경은 서버 파티 완료와 다른 참가자의 기록에 영향을 주지 않는다.

### 개인 기록 우선순위

```text
1. 사용자가 직접 체크하거나 해제한 상태
2. 서버 파티 완료 또는 취소 이벤트로 자동 제안된 상태
3. 기록이 없으면 미완료
```

- 사용자가 직접 관리한 상태가 개인 화면의 최우선 기준이다.
- 로컬 완료 기록은 신청 화면의 1차 필터 또는 경고에 사용한다.
- 서버는 사용자가 수정할 수 있는 로컬 완료 기록을 최종 강제 판정 근거로 사용하지 않는다.
- 서버는 서버에서 확인 가능한 파티 중복 참가, 일정 충돌, 정원과 소유권 등을 최종 검증한다.

### 개인 진행 상태와 지난 회차 결과

현재 주차의 개인 진행 상태와 지난 회차 히스토리 결과를 분리한다.

```text
현재 주차 개인 상태
  incomplete
  completed

지난 회차 히스토리 결과
  completed
  incompleteEnded
```

- `미완료`: 현재 주차가 진행 중이며 아직 완료하지 않은 상태다.
- `완료`: 사용자 수동 체크 또는 파티 완료 이벤트로 완료된 상태다.
- `미완료 종료`: 수요일 오전 6시까지 완료하지 못한 지난 회차의 최종 결과다.
- 잘못된 파티 완료 이벤트를 사용자가 정정하면 현재 주차 상태를 `미완료`로 바꾸고 다시 신청할 수 있다.
- 정정 직후 바로 `미완료 종료`로 만들지 않는다. 수요일 오전 6시까지 완료하지 못했을 때만 미완료 종료가 된다.
- 서버 파티 회차 상태는 `active`, `completed`, `incompleteEnded`, `disbanded`를 구분한다.

### 신청 화면 처리

- 현재 주차에 완료 기록이 있는 Character를 후보에서 숨기지 않고 비활성 상태로 표시한다.
- `이번 주 완료 기록이 있습니다.`와 `레이드 기록 확인` 동작을 제공한다.
- 기록 화면에서 `기록 유지` 또는 `미완료로 변경하고 신청`을 선택할 수 있다.
- 미완료로 변경한 뒤 서버 확정 참가 점유와 기타 조건을 다시 검증해 신청한다.
- 로컬 완료 여부와 관계없이 같은 Character·raidId·cycleKey의 서버 확정 참가 점유는 사용자가 우회할 수 없다.

### 히스토리 출처

```text
source
  manual
  partyEvent
```

- `manual`: 사용자가 직접 입력
- `partyEvent`: 서버 완료 이벤트로 자동 생성

### 숨김

- 사용자 동작은 실제 삭제가 아니라 `숨김`으로 처리한다.
- 로컬 기록은 `visible` 또는 `hidden` 상태를 가진다.
- 기본 목록은 표시 중인 기록만 보여준다.
- `전체`, `표시 중`, `숨김` 필터 또는 `숨긴 기록 보기`를 제공한다.
- 숨김 기록은 `다시 표시`할 수 있다.
- 같은 서버 이벤트를 다시 동기화해도 기존 hidden 상태를 유지한다.
- 숨김 상태는 앱 재설치나 다른 기기에 동기화하지 않는다.

### 완료 취소 진입

- 완료 취소 푸시를 누르면 정확한 캐릭터, 주차와 레이드 기록 화면으로 이동한다.
- 앱 화면에서 기록 유지 또는 미완료 변경을 선택한다.
- 푸시 자체에서 로컬 DB를 수정하지 않는다.

## 17. 캐릭터 카드 주간 레이드 표시

### 표시 개수

- 캐릭터별로 독립 설정한다.
- 최소 0개, 최대 5개다.
- 사용자 설정이 없으면 기본 3개다.
- 0개는 캐릭터 카드의 주간 레이드 영역을 표시하지 않는다.
- 설정한 표시 개수와 선택한 레이드 수가 정확히 같을 때만 확인 버튼을 활성화한다.

예를 들어 표시 개수가 2개라면 정확히 2개를 선택해야 저장할 수 있다.

### 기본 추천

- 캐릭터가 입장 가능한 난이도만 후보로 계산한다.
- 최대 골드 획득량은 현재 단계에서 일반 골드와 귀속 골드를 합산한다.
- 같은 `raidId`의 여러 난이도 중 최대 골드를 얻을 수 있는 적정 난이도 하나만 후보로 사용한다.
- 서로 다른 `raidId` 사이에서 최대 골드 순으로 기본 표시 대상을 선택한다.
- 사용자가 직접 편집한 이후에는 자동 추천으로 덮어쓰지 않는다.
- 일반 골드와 귀속 골드 포함 여부 필터는 후속 기능이다.

### 완료 키와 난이도

- 주간 완료 여부는 `resetWeekKey + characterId + raidId`를 기준으로 한다.
- 같은 레이드의 노말, 하드와 나이트메어를 별도 주간 참가 대상으로 표시하지 않는다.
- 완료 난이도는 부가 이력으로 저장한다.

### 카드 접기

- 카드 기본 높이는 주간 레이드 3개를 자연스럽게 표시하는 크기를 기준으로 한다.
- 화면 높이의 비율로 접기 여부를 결정하지 않는다.
- 0개는 영역을 표시하지 않는다.
- 1~3개는 기본 상태에서 전부 표시한다.
- 4~5개는 처음 3개와 `나머지 N개 더보기`를 표시한다.
- 펼치면 전체를 표시하고 접기 동작을 제공한다.
- 실제 픽셀 높이와 반응형 배치는 UI 구현 단계에서 가용 폭과 접근성 글자 크기를 기준으로 검증한다.

## 22. 1차 설계 결론

- 인증 식별자와 제품 사용자 식별자를 분리한다.
- 공유 파티 상태는 서버를 기준으로 하고 개인 레이드 관리는 로컬을 기준으로 한다.
- 파티 완료와 개인 캐릭터 완료는 서로 다른 상태다.
- 반복 파티는 방과 주차별 회차를 분리한다.
- 회차 완료 당시 구성은 Snapshot으로 고정하고 완료 후 변경은 다음 회차 준비 구성에 적용한다.
- 완료되지 않은 회차는 수요일 오전 6시에 미완료 종료하고, 1회성 파티는 자동 종료하며 반복 파티는 현재 구성을 새 회차로 승계한다.
- 화요일 22:00에 반복 파티 완료 취소를 마감하고 수요일 오전 6시에 새 회차로 전환한다.
- 새 회차 파티방에서는 이전 회차를 보여주지 않는다.
- 완료·미완료 종료 및 기타 사용자 이벤트는 28일 동안 서버에 보관해 오프라인 사용자의 로컬 히스토리 동기화를 지원한다.
- 전체 알림은 새 방의 초기값이며 방별 설정은 독립적으로 유지한다.
- 캐릭터별 레이드 표시는 0~5개, 기본 3개이며 같은 레이드의 여러 난이도를 중복 표시하지 않는다.
- 구현은 기능 단위로 이 제품 흐름을 데이터 계약, 서버 명령, Security Rules와 테스트 시나리오로 구체화한 뒤 진행한다.
