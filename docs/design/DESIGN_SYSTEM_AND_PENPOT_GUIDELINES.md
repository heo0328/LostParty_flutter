# LostParty 디자인 시스템·Penpot 작업 지침

이 문서는 디자인 공통 기준과 Penpot 작업 방식의 지속 관리 원본이다. 날짜별 요청서를 새로 만들지 않고 유효한 내용을 수정·추가·삭제한다. 화면별 현재 결과는 [구현 화면·Penpot 대응표](PENPOT_IMPLEMENTED_SCREEN_MAP.md), 현재 작업은 [NEXT_WORK](../project/NEXT_WORK.md)를 따른다.

최신 정비: 2026-11-18. 종전 설계 요청서의 유효 지침을 통합했으며, [과거 판단 근거](../project/history/design-system-and-penpot-before-normalization-2026-11-18.md)는 현재 실행 지시와 구분한다. Firebase 전용 자료는 [레거시 원문](../../legacy/firebase/extracted/docs/design/LOSTPARTY_DESIGN_SYSTEM_V1_REQUEST.md)에 보존한다.

## 작업 목적과 수정 범위 (2026-11-18 사용자 확정)

**구현 화면 재현:** 이미 완성된 앱을 디자이너가 먼저 설계했다고 가정하고, 실제 구현된 모습을 Penpot의 최종 디자인으로 역으로 재현한다. 느낌만 전달하는 러프 시안이 아니라 픽셀 수준의 시각적 일치를 목표로 한다. 보기 좋은 임의 배치·아이콘·문구·스타일로 대체하거나 개선하지 않는다.

**신규 디자인 제안:** 사용자가 별도로 새 화면/개선을 요청할 때는 제안임을 표시하고 기존 디자인 시스템·확정 UX를 따른다. 재현 작업의 미확인 요소를 신규 제안으로 채우지 않는다. 과거 제안→확인→구현 절차는 이 경우에 적용한다.

- 이 디자인 작업에서 프로젝트의 Flutter 코드·테스트·원본 이미지/폰트·설정은 수정하지 않는다. 프로젝트 코드는 읽기 전용 근거로 조사하며 관련 Markdown 문서는 아래 범위에서 갱신한다.
- 실제 수정은 로컬 MCP를 통한 Penpot 작업과, 그 작업에 필요한 Markdown 지침·대응표·결과·참조 갱신에 한정한다. 앱 변경이 필요해 보여도 불일치를 기록하고 별도 개발 범위로 남긴다.
- 문서는 Flutter 코드와 같은 저장소에서 GitHub에 보관해 다음 작업으로 이어간다. 커밋·푸시·통합·배포는 각각 사용자 지시 범위에 따른다. 문서 작성 허용을 게시·배포 승인으로 해석하지 않는다.

## 현재 표시 화면만 다루는 작업 방식

일반 사용자에게 현재 웹·앱에서 표시되는 화면과 실제로 열리는 상태를 재현한다. 코드에 남아 있는 화면이라도 사용자 진입점에서 접근할 수 있는지 먼저 확인한다. 폐지·숨김 메뉴, 과거 시안, 비교용 캡처와 내부 검수 설명을 공개 프레임에 넣지 않는다. 앱의 현행 UI에서 사용자가 직접 조회하는 이력 화면은 현재 제공되는 기능 화면으로 취급한다.

02는 외부 공개와 개발 인계에 사용할 최종 화면만 둔다. 현재 화면을 대조한 뒤 기존 메인 안에서 대표 화면을 갱신한다. 웹과 Android가 다르게 표시되는 구간만 각각 보여준다. 불확실한 상태는 NEXT_WORK에 확인 항목으로 남기고 해당 상태를 완료 화면으로 게시하지 않는다.

## 구현 근거와 시각적 일치

1. 대상 코드 커밋과 미커밋 변경 유무를 기록하고 실제 Router/DI가 선택하는 화면부터 확인한다. 과거 캡처·설계와 현재 코드를 혼동하지 않는다.
2. 화면 위젯, 공통 Theme/토큰, 지역 Theme·위젯 override, 레이아웃 제약·조건 분기를 함께 읽는다. 공통 수치를 화면별 명시 설정보다 우선해 덮어쓰지 않는다.
3. 색상·글꼴/굵기·줄높이·글자배율·텍스트 줄바꿈/축소/말줄임, 크기·간격·정렬·곡률·테두리·그림자, 아이콘·상하단 고정 영역을 구현대로 재현한다. elevation 숫자를 임의의 단일 그림자 수치로 바꾸어 일치로 판정하지 않는다.
4. viewport와 콘텐츠 가용폭, 플랫폼, 글자배율, 안전 영역, 스크롤 위치, 선택/권한/로딩·빈 상태·오류 상태를 명시한다. 반응형은 코드의 min/max·열 전환·스크롤 소유를 따르며 모바일을 비례 확대해 웹을 만들지 않는다.
5. 같은 조건의 제공된 실행 화면과 Penpot PNG를 시각 대조한다. 코드 대조만 했으면 그 사실을 명시한다. 기기·브라우저 조작은 기존 사용자 수행 원칙을 따른다.
6. 글꼴 대체·동적 이미지 부재·실행 상태 미확인 등으로 모습을 확정할 수 없으면 필요한 근거와 차이를 기록한다. 실제 자산이 없는 요소를 유사 이미지로 채우거나 알려진 앱 문제를 디자인에서만 고쳐 완료로 표시하지 않는다.

문서의 일반 규칙과 실제 구현이 다르면 구현 재현의 기준은 해당 코드다. 차이와 근거를 대응표에 남기며 코드·제품 정책을 임의로 수정하지 않는다. 완료 판정은 코드 대조, 자산 확인, 정적 시각 검수, 실행 화면 대조, 사용자 확인을 구분한다. 일부 확인만으로 전 화면·기기 픽셀 일치를 주장하지 않는다.

## 프로젝트 자산을 Penpot에 재사용

- 프로젝트 PNG/JPEG/WebP/SVG와 실제 사용 폰트를 읽어 원본 자산을 Penpot으로 가져온다. 이미지의 표시 크기·fit/crop·비율·투명도·tint·클리핑도 코드대로 적용한다.
- `Icons.*` 등 아이콘 폰트는 실제 SDK/패키지의 폰트 파일·code point·스타일을 확인해 같은 글리프를 SVG 경로 등으로 변환하거나 정확한 원본을 사용한다. 닮은 다른 아이콘·Unicode 문자·손그림으로 대체하지 않는다.
- 코드로 그리는 도형/CustomPainter는 실제 경로와 그리기 규칙을 근거로 재현한다. 네트워크 이미지는 실제 사용 자산을 확보한 경우에만 원본으로 기록하고, 접근 불가이면 미확인으로 남긴다.
- 원본은 변경하지 않는다. 추출·렌더링용 임시 산출물은 기존 추적 제외 작업 영역을 사용하고 앱 자산으로 추가하지 않는다. Penpot에 가져온 객체의 원본 경로·글리프/변환 방식·객체 ID를 대응표에 남긴다.
- 확보한 동일 자산은 재사용한다. 파일 접근이나 MCP 업로드가 불가능하면 필요한 자산과 이유를 알리고, 임의 대체해 완료로 보고하지 않는다.

### 내 계정·생성·탐색 폭과 정렬 (2026-11-15 구현 기준)

회원 본문 최대1600·중앙 배치를 사용하고 자동갱신결과는 최대640 내 내용폭으로 수축한다. 캐릭터용 게임주차 제목/선택/날짜·복구는 메인원정대 카드 내부 최상단에 모으고 내부 전체폭으로 배치하며 시간표의 달력주차와 분리한다. 메인원정대가 없으면 목록 위에 한 번 표시한다. 원정대는 실제 표시카드 수·가용열·기존190~280/글자배율로 외곽폭을 계산한다. 2026-11-15 후속 시범 적용으로 자동갱신결과·시간표·메인/부원정대·계정 도구는 본문 내부 왼쪽 기준으로 정렬한다. 본문 자체의 최대1600/화면 중앙은 유지하며 각 영역을 독립적으로 중앙 배치하던 방식을 대체한다. 박스 최소폭은 제목/기능을 고려한320×글자배율이며 가용폭을 넘지 않는다. 내부간격12·외곽padding은 유지하고 마지막행 카드수로 폭을 다시 줄이지 않는다. 시간표/도구는 기존 자연폭을 유지한다. 남는 모니터폭은 콘텐츠 밖 여백으로 두고 AppBar/비회원·다른 페이지는 그대로다.

생성 화면 폭 제한 시범(2026-11-15): BoundedPageBody를 계정과 공유하며 입력 본문 내부 최대1600/화면 중앙을 적용했다. 계정16·생성12의 기존 좌우 여백과 스크롤/항목 순서는 유지한다. 후속 승인으로 모집 탐색도 공용 본문 내부1600+좌우16의 viewport1632를 적용하고 생성 버튼의 우측끝을 해당 본문 경계에 맞췄다. 기존600/1100×글자배율 분할과 낮은 높이 동작은 유지한다. 기기별 확인 범위와 이후 변경은 화면 대응표·NEXT_WORK의 기준일을 따른다.

### 공통 구현 디자인 보완 (2026-11-15 사용자 확정)

공통 Material Card는 elevation3·검정 shadow alpha20%(#33000000), Filled/Elevated/OutlinedButton과 Chip은 elevation2·검정 shadow 약15%(#26000000)를 사용한다. surfaceTint는 투명이고 기존 색/테두리/곡률은 유지한다. OutlinedButton은 그림자를 드러내는 흰 surface 배경을 사용한다. 별도 BoxDecoration/위젯별 override·AlertDialog는 이 CardTheme 변경과 구분하며 전 화면에 같은 그림자가 있다고 해석하지 않는다.

내 계정은 AccountPageTypography의 제목18/본문·버튼16/보조14와 시스템 글자 확대를 사용한다. 여백을 비례 확대하지 않고 내용에 맞춰 영역/버튼 높이·자연폭이 정해진다. 회원 캐릭터 카드의 이름/직업·역할/레이드명/참가상태·일반요약은 한줄에서 기본크기70%까지 제한축소 후 말줄임한다(2026-11-15 후속 승인). 숫자는 필요시 줄바꿈하되 말줄임하지 않는다. 카드전체/터치영역은 축소하지 않는다. 상단인증은 로그인/로그아웃 버튼만 두고 로그인정보·ID복사는 설정에 유지한다. 화면폭보다 커지는 경우 감싸기/영역 내부 스크롤을 사용한다. 요일 그래프 간격8·외곽곡률6·단색 배경에1시간 세로선(1px·14%)을 막대 위에 표시한다. 공통 선택 컨트롤은 비활성에도 흐림을 넣지 않으며 실제 입력 차단은 유지한다. 펜폿03/02의 기존 보드 이관은 별도 지시다.

### 기존 디자인·사용 흐름 유지 원칙 (2026-10-17 사용자 확정)

기존 디자인과 UI/UX, 사용자가 설명한 개발 의도를 최대한 유지하며 개발한다. 최신 사용자 승인 변경을 포함한 화면/흐름이 기준이며, 이 원칙을 이유로 이미 승인한 개선을 과거 상태로 일괄 되돌리지 않는다.

- API·데이터 저장·내부 구조를 바꾸더라도 화면 정보 순서, 카드/그리드 형태, 버튼 위치와 기능 진입, 캐릭터 상세 직접 진입, 선택/정렬/취소 방식을 임의로 변경하지 않는다.
- 아직 서버에 연결하지 않은 기능도 기존 진입점과 후속 확장 영역을 보존한다. 미연결 상태가 디자인 삭제·축소의 근거가 되지 않는다.
- 개발자에게 구현하기 좋은 구조인지와 앱 사용자가 이해하고 조작하기 좋은 구조인지를 구분한다. 불필요한 중간 화면·클릭·숫자 입력·장문 안내를 추가하지 않는다.
- 개선이 필요하면 영향받는 기존 흐름, 변경 전후, 사용자의 이점과 추가 조작/영향을 짧게 제안하고 동의한 범위에서 반영한다. 사용자가 이미 지시한 변경은 중복 확인하지 않는다.
- 기존 승인 동작의 버그/레이아웃 깨짐은 최소 수정으로 복구한다. 관련 없는 정상 화면의 재설계를 끼워 넣지 않는다. 서버 권한/오류 복구에 필요한 내부 처리를 장황한 사용자 단계로 노출하지 않는다.

## 반응형 디자인 지향점과 단계적 개선 (2026-11-12 사용자 확정)

이 절의 제안→구현 절차는 별도로 승인된 신규 디자인/개발에 적용한다. 구현 재현은 위 구현 근거·시각적 일치 절차로 현재 코드의 조건을 그대로 따르며 앱 코드를 수정하지 않는다. 일반 바형 스마트폰, 접힌·펼친 폴드와 웹 창의 크기에 맞춰 정보 배치가 자연스럽게 달라지도록 개선한다. 넓은 공간에서는 관련 정보를 함께 보여주어 과도한 세로 스크롤과 화면 왕복을 줄인다. 전체 개선 순서와 페이지별 착수 상태는 [차후 수정안](../product/DETAIL_IMPROVEMENTS.md#responsive-design-roadmap), 현재 실행 범위는 NEXT_WORK를 따른다.

- 기기명이나 플랫폼보다 화면 영역에 실제로 주어진 가용 공간을 기준으로 판단한다. 영역별 최소·최대 너비 안에서 비율로 조절하고, 필요한 공간을 확보할 수 없으면 배치 구조를 전환한다. 전환 수치는 페이지별로 확정하며 파티 구성판의 기존 기준을 앱 전체에 일괄 적용하지 않는다.
- 글자·아이콘·터치 영역을 화면 비율대로 축소하지 않는다. 글자 확대, 안전 영역과 분할 화면을 함께 고려한다. 기존 모바일 시안 규격은 실행 해상도나 고정 너비 제한이 아니다.
- 접기·펼치기·회전·웹 창 크기 변경 중에도 선택 조건, 작성 내용과 현재 작업 맥락을 유지한다. 크기 변화만으로 조회·명령을 중복 실행하지 않도록 데이터 소유와 상태 수명을 설계한다.
- 기존 색상·카드·기능·권한·확정된 사용 흐름을 기준으로 개선한다. 넓은 화면은 정보 관계에 따라 본문·보조 영역 또는 목록·선택 상세로 나누며 일괄 50:50이나 상시 다중 열을 강제하지 않는다. 필터·목록·상세를 함께 표시할 공간이 부족하면 일부 영역을 별도 화면이나 패널로 제공한다.
- 한 페이지 그룹의 **실제 화면·Router·데이터 흐름 조사 → Penpot03 시안 → 사용자 확인 → 구현 → 검증**을 마친 뒤 다음 그룹으로 진행한다. 모든 페이지를 동시에 수정하거나 전체 시안을 먼저 일괄 제작하지 않는다. 후속 페이지의 배치·구현을 일괄 승인한 것으로 취급하지 않는다.
- 페이지별 시안에서 좁은 화면·펼친 화면·넓은 웹과 필요한 상태를 비교한다. 영역별 최소·최대 너비, 비율, 전환 기준, 스크롤 소유와 주요 버튼 위치를 확정해 구현 전에 기록한다. 기존 보드에서 피드백을 반영하며02 이관은 아래 공통 지침을 따른다.
- 페이지별 검증은 좁은·넓은 배치, 글자 확대·긴 문구, 로딩·빈 결과·실패 상태를 포함한다. 구현 후 크기 전환 중 입력·선택·목록 맥락 보존과 중복 요청 여부를 확인한다. 실기기 설치·조작·접기·펼치기는 사용자가 수행하며 자동 검증과 기기 인수를 구분한다.

## Penpot 작업·완료 화면 관리 공통 지침

2026-10-28 사용자 확정. 이 절은 기능별 Penpot 러프디자인부터 구현 완료 화면 관리까지 공통 적용한다. 새 작업 방식 문서를 따로 만들지 않고 이 절을 갱신한다.

- **03 작업 중인 화면:** 사용자가 구현 재현 결과 또는 별도 요청된 신규 시안을 눈으로 검토하는 공간이다. 구현 예정 화면도 아이콘·배치·문구를 검토 가능한 완성도로 작성하고, 미결정 부분은 화면 밖에 명시한다. 현재 앱을 옮기는 작업은 실제 구현과 일치시킨다. 실제 작업 시작 시 파일/페이지 이름과 식별자를 조회하며 과거 명칭만으로 페이지를 추정하거나 중복 생성하지 않는다.
- **02 구현 운용 화면:** 외부 공개 또는 개발 인계에 사용할 수 있는 최종 화면만 둔다. 구현된 웹·앱 화면을 현재 코드에 맞춰 보여주며, 구현 전이라면 사용자에게 확정된 최종 디자인만 표시한다. 작업 중인 레이어·검수용 자료·이전 화면 비교·폐지된 기능은 02에서 제외한다. 실제 개발 완료·확인된 화면을 관리하는 동시에, 앱을 모르거나 설치하지 않은 사람도 ‘무슨 앱이며 무엇을 어떻게 사용하는가’를 이해할 수 있는 디자인 안내서다. 기능 목적·화면 순서·주요 행동과 결과를 디자인 안에서 설명한다. 디자인을 그렸다는 이유만으로 완료 화면으로 분류하지 않는다.
- **현행 대조·외부 열람 (2026-11-12 사용자 확정):** 현재 프로젝트 코드의 디자인이 대조의 최종 기준이다. 과거 문서·03 시안이 코드와 다르면 실제 Router/DI가 선택하는 화면 코드를 확인해02를 고친다. 외부 링크에서는6개 최상위 메인 보드를 각각 한 페이지로 읽고 하위 객체를 하나씩 열지 않는다. 각 메인 보드 안에서 섹션별 기능·진입·행동·결과를 이해할 수 있게 유지하며, 이 열람 방식을 전체 앱 클릭 프로토타입 제작 요구로 바꾸지 않는다.
- **보드 구조 (2026-10-31 사용자 확정):**02는 앱 시작·내 계정·레이드 현황·레이드 모집·설정/로그인/인증·그룹을 각각 독립된 기능 설명 보드로 둔다. 전체 앱을 감싸는 거대한 메인 보드는 만들지 않는다.03에서는 작업 단위(예: 그룹 전체 흐름)당 하나의 메인 보드를 두고, 그 안에 화면·기능 섹션별 하위 보드를 배치한다. 목록·요청·상세·생성/가입·관리와 필요한 상태는 해당 섹션에서 구분한다. 메인 보드는 섹션 보드들을 담는 상위 구조이며 섹션을 무관한 최상위 보드로 흩뜨리지 않는다.
- **UX 설명:** 메인 보드에는 전체 진입·이동 흐름과 현재 작업 상태를, 섹션 보드에는 진입→주요 행동→결과·역할/상태 차이·구현 의도를 짧게 표시한다. 사람이 디자인만 보고 동작을 이해할 수 있게 하며, 설명은 앱 화면 바깥의 주석 영역에 두어 실제 사용자 문구/버튼과 구분한다. 설명마다 별도 보드를 추가하지 않고 해당 메인/섹션 안에서 갱신한다.
- **수정 방식:** 기존 기능 보드 안의 대상 섹션을 확인해 직접 갱신한다. 섹션 증감에 따른 상위 크기·아래 섹션 위치와 보드 간 여백도 함께 조정한다. 피드백·버전·날짜별 새 메인 보드나 같은 화면 사본을 계속 추가하지 않는다. 상태 차이 표현이 필요한 하위 보드는 같은 섹션 안에서 필요한 만큼만 둔다. 이전 안 보관이 필요한 경우에도 명시적인 필요 범위만 보존하며 자동 복제하지 않는다.
- **완료 이관 (2026-10-31 사용자 확정):** 개발·화면 확인 완료만으로 자동 이관하지 않는다. 사용자가 별도로 이관을 지시한 경우에만, 실제 구현과 일치하도록03의 기존 메인 보드·하위 섹션을 정리한 뒤 **동일한 메인 보드 묶음을02로 이동**한다.02용 완성본을 자동 복제·재작성하지 않는다. 사용자가 직접 복사한 보드가 있으면 그 객체를 우선 재사용하고 재복제하지 않는다. 따라서03에서부터 완료 화면으로 바로 이관할 수 있는 구조와 이름을 유지한다.
- **부분 완료:** 일부 섹션만 구현됐거나 서버 연결/기기 확인이 남았으면 전체 그룹 보드를 완료로 이동하지 않는다. 작업 중 상태를 기존 섹션에 표시하고, 전체 작업 단위 완료 후에도 사용자 별도 이관 지시까지03에 유지한다.
- **중복/참조 확인:** 이동 시02의 같은 작업 보드와 중복 여부, 하위 계층·섹션 순서·이동 후 실제 화면 대응을 확인한다. 기존 완료 화면이나 다른 작업 보드를 임의 삭제하지 않는다. 가능한 동일 객체/식별자와 연결을 유지하고 이동 결과를 확인한다.
- **MCP 연결:** 로컬 PowerShell MCP를 우선 사용한다. 시간 초과만으로 연결 단절을 확정하지 않는다. 화면/섹션 단위로 명령을 분할하고 응답 시간 초과 뒤에는 읽기로 반영 여부를 확인해 중복 실행을 피한다. 실제 연결 단절·읽기/명령 실행 불능이 확인되면 작업을 중단하고 사용자에게 MCP 재연결 확인을 요청한다. Chrome 직접 제어로 전환하지 않는다.
- **설명과 프로토타입:** 설명 보드와 실제 화면 실행을 구분한다. 전체 앱 프로토타입은 별도 연결 단계이며 설명 보드 완성을 클릭/스크롤 검증 완료로 주장하지 않는다.
- **문서 책임:** 디자인 작업 방식은 이 문서, 현재 화면·코드·자산 대응은 화면 대응표, 진행 계획은 NEXT_WORK에 유지한다. 현행화할 때 현재 항목을 교체한다. 폐지 화면·이전 디자인·작업용 캡처를 Penpot에 보관하거나 이번 디자인 작업의 날짜별 과거 기록을 추가하지 않는다.

실제 디자인 작업 때 현재 페이지/보드를 확인하고 위 방식을 적용한다. 문서 갱신만으로 보드 생성·수정·이동 완료를 보고하지 않는다.

### 화면 규격·자산·디자이너 역할 (2026-10-29 사용자 확정)

- **공통 화면:** 비교용 기본 모바일 화면은390×844 디자인 단위, 모서리 반경16, 중립색 `#A8A4AD` 1px 안쪽 테두리로 통일한다. 기기 몸체·카메라 모형 대신 액정 디스플레이 영역을 표현한다. 앱의 실행 해상도를 고정하는 규칙은 아니다. 프레임의 반경/테두리는 캔버스의 화면 구분 표현이며 앱 내부에 같은 장식을 추가하는 지시가 아니다. 구현 재현에서는 지정한 실제 viewport·배율·안전 영역을 우선한다. 현재03에 먼저 적용하고 사용자 확인 후02에 적용하며, 기존02를 일괄 변경한 것으로 간주하지 않는다. 이후 기본 모바일 작업도 같은 규격을 사용한다. 태블릿·폴드 등의 별도 반응형 예시는 크기와 목적을 명시한다.
- **화면 수명과 영역:** 긴 내용은 프레임을 무제한 늘리지 않고 스크롤 화면으로 표현한다. 추가 상태·스크롤 위치는 같은 섹션에서 최소한으로 구분한다. 다이얼로그·선택창은 같은 화면 규격 안에서 맥락과 함께 표현한다. 상태바·하단 안전 영역은 같은 기준으로 관리하고 실제 내비게이션·고정 버튼의 위치와 구분한다. 디자인 장식을 앱 UI로 오해하게 하지 않는다.
- **동일 자산:** 프로젝트에서 사용하는 PNG/JPEG/WebP/SVG 등의 로컬 자산을 필요시 Penpot에 업로드·가져와 재사용한다. Flutter `Icons.*`는 동일한 Material 아이콘·스타일의 원본이나 해당 글리프를 정확히 변환한 자산을 사용한다. `○`, `♧` 같은 문자나 닮은 임시 그림으로 대체하지 않는다. 원본의 색·선택/비선택 상태·비율을 확인하고, 확보한 유효 자산은 재사용한다. 파일·접근·업로드 권한이 부족하면 필요한 대상과 이유를 알리고 요청한다. 확보하지 못한 자산을 임의 대체해 완료로 보고하지 않는다.
- **실제 앱 대조:** 현재 화면은 Flutter의 실제 아이콘·크기·간격·색·정렬·버튼/내비게이션 배치와 제공된 실행 화면을 근거로 작성한다. 코드 대조와 기기 확인은 구분하며, 편의를 위한 수동 배치나 러프디자인이라는 명칭으로 괴리를 허용하지 않는다. 향후 화면은 동일한 디자인 시스템과 확정 UX를 따르고 미결정 사항을 실제 구현처럼 보이게 하지 않는다.
- **이해 가능한 안내서:** 메인에 앱/기능의 목적·대상 사용자·읽는 순서를 간결히 두고 섹션에는 진입→행동→결과와 필요한 역할·상태 차이를 설명한다. 내부 API·DB 용어를 이용 설명 대신 나열하지 않는다. 화면 안은 실제 사용자 문구, 화면 밖은 디자인 설명으로 구분한다. 가상 인물·수치는 예시임을 표시하고 개인정보·실제 인증정보를 사용하지 않는다. 기존 메인/섹션 안에서 정리하며 소개용 보드를 계속 추가하지 않는다.
- **검수와 책임:** 디자이너 역할에는 자산 확보·일관된 시각 구성·흐름 전달·실제 구현 대조·최종 눈검수가 포함된다. 섹션별 PNG와 전체 보드를 눈으로 확인해 잘림·겹침·프레임 이탈·가독성을 검사하고, 아이콘/배치/문구/이동 흐름은 실제 앱 근거와 별도로 대조한다. PNG 출력 성공만으로 앱 일치를 선언하지 않는다. 기기 확인은 사용자가 수행하며 미확인·불일치·개선 예정은 명시한다. 기존 구현의 알려진 문제를 디자인에서만 고쳐 완료로 표시하지 않는다.02 이관 전에는 앱을 처음 보는 사람이 목적·핵심 흐름·결과를 이해할 수 있는지도 검토한다.

## 숫자·원정대 상태 공통 표시 원칙 (2026-10-17)

아이템레벨·전투력은 소수점 이하를 버린 정수부와 천 단위 쉼표로 표시한다. 시간은 초까지만 표시한다. 원본/API/서버·로컬 저장 및 정렬·자격 판정에는 소수점 정밀도를 유지하며 표시 문자열을 다시 저장하지 않는다. 미확인 값은 기존 미확인 안내를 유지한다. 원정대 상태는 인증·활동 선택 완료 문구를 반복하지 않고 인증 필요/활동 캐릭터 미선택·재선택처럼 필요한 행동만 표시한다. 로그인 회원의 미인증 등록도 서버에 저장되며 같은 회원의 다른 기기/재설치 로그인에서 조회된다.
