# 파티 구성판 반응형 레이아웃 계약

## 1. 목적

2026-10-21 신규 서버 디자인 추가: [설계37 §36.9](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md)를 우선해 캐릭터 앞 첫 글자 아바타를 실제 자리 번호로 교체한다. 4인은1~4,8인은1-1~2-4이며 빈자리 번호도 유지한다. 공대장 배지는 별도, 자료가 없으면 자리 미정이다. 선택 주차의 공대장/참가만 표시하고 직접 위임과 N탈퇴·자동 승계도 해당주차 범위다. 이는 Penpot03 v4에 반영된 후속 구현 기준이며 아래 기존 반응형 배치와 슬롯 데이터는 그대로 보존한다.

모집 현황 상세의 파티원 Slot Card 구성은 유지하되, 화면이 넓어질 때 Card가 자동으로 작아지는 문제를 해결한다.

반응형 배치의 기준은 기기 종류가 아니라 파티 구성판에 실제로 주어진 가용 폭이다. 바형 스마트폰, 폴더블의 펼친 화면, 태블릿, 가로 모드와 분할 화면을 같은 규칙으로 처리한다.

## 2. 적용 범위

- 모집 현황 상세의 `파티 구성` 영역
- 4인 레이드의 1파티 고정 Slot 4개
- 8인 레이드의 1파티·2파티 고정 Slot 각 4개
- 점유 Slot Card, 빈 Slot Card와 파티 제목
- `slotIndex`가 없는 기존 membership의 `자리 미정` 영역

다음 항목은 이번 레이아웃 작업의 범위가 아니다.

- Slot Card 내부 정보 구성 및 시각 디자인 변경
- 파티 및 슬롯 이동·스왑
- 빈 슬롯별 역할·직업·시너지 조건 설정
- membership 데이터나 `PartySlotBoard` 규칙 변경
- 폴더블 힌지 영역을 직접 감지하는 전용 구현

## 3. 현재 상태와 문제

현재 `_PartyCompositionSection`은 가용 폭이 600dp 이상이면 파티 내부 Slot Card를 2열로 배치한다.

이 방식은 넓은 화면에서 다음 문제가 있다.

- Card가 화면 확장과 함께 충분히 넓어지지 않고 반으로 축소된다.
- 8인 공격대에서 1파티와 2파티가 세로로 이어져 파티 간 비교가 어렵다.
- 4인 파티에서도 화면 전체에 작은 Card 2개가 배치되어 남는 공간의 의도가 불명확하다.

## 4. 확정 레이아웃 원칙

### 4.1 공통 원칙

- Slot Card의 열 수를 반응형으로 바꾸지 않는다.
- 한 파티 안의 Slot Card 4개는 항상 세로 1열이며 해당 파티 열의 전체 폭을 사용한다.
- 넓은 화면에서는 Card가 아니라 파티 그룹을 좌우로 배치한다.
- 파티 제목과 Slot Card는 같은 파티 열 안에 포함한다.
- 화면 폭이 아니라 부모 `LayoutBuilder`가 제공하는 실제 `maxWidth`를 사용한다.
- 기기명, 플랫폼 또는 폴더블 여부를 직접 조건으로 사용하지 않는다.

### 4.2 좁은 레이아웃

파티 그룹 두 개를 나란히 두기에 폭이 부족하면 다음처럼 표시한다.

- 4인: 1파티가 구성판의 전체 가용 폭 사용
- 8인: 1파티 전체 폭 다음에 2파티 전체 폭을 세로 배치
- 각 Slot Card는 파티 열의 전체 폭 사용

```text
1파티
┌────────────────────────────┐
│ 1번 Slot Card              │
├────────────────────────────┤
│ 2번 Slot Card              │
├────────────────────────────┤
│ 3번 Slot Card              │
├────────────────────────────┤
│ 4번 Slot Card              │
└────────────────────────────┘

2파티 (8인 레이드만)
┌────────────────────────────┐
│ 1번 Slot Card              │
└────────────────────────────┘
...
```

### 4.3 넓은 레이아웃

파티 그룹 두 개를 배치할 수 있는 폭에서는 구성판을 동일한 폭의 두 파티 열로 나눈다.

- 4인: 1파티를 왼쪽 열에 배치하고 오른쪽 열은 비워 둔다.
- 8인: 1파티는 왼쪽 열, 2파티는 오른쪽 열에 배치한다.
- 두 열 사이에는 Design System spacing token을 사용한 일정한 간격을 둔다.
- 양쪽 파티의 시작 위치와 제목 위치를 맞춘다.

```text
┌────────── 1파티 ──────────┐  ┌────────── 2파티 ──────────┐
│ 1번 Slot Card             │  │ 1번 Slot Card             │
│ 2번 Slot Card             │  │ 2번 Slot Card             │
│ 3번 Slot Card             │  │ 3번 Slot Card             │
│ 4번 Slot Card             │  │ 4번 Slot Card             │
└───────────────────────────┘  └───────────────────────────┘
```

4인 파티의 비어 있는 오른쪽 열에는 장식, 안내, 광고나 빈 Card를 추가하지 않는다. 향후 별도 기능이 확정되기 전까지 의도적인 여백으로 유지한다.

## 5. 반응형 전환 기준

초기 구현은 하나의 가용 폭 breakpoint만 사용한다.

- 좁은 레이아웃: 파티 그룹 1열
- 넓은 레이아웃: 파티 그룹 2열
- 초기 후보 breakpoint: 가용 폭 `600dp`

`600dp`는 제품 계약의 영구 고정값이 아니라 실기기 검증으로 조정한 후보값이다. 펼친 폴드의 구성판 가용 폭(화면 패딩 제외)이 보통 650~690dp라 `720dp`는 미달했고, 바형 가로·펼친 폴드가 같은 넓은 레이아웃을 쓰도록 `600dp`로 낮췄다. 다음 조건을 만족하는 가장 단순한 값으로 표적 위젯 테스트와 실기기에서 다시 조정할 수 있다.

- 각 파티 열에서 긴 캐릭터명과 배지가 과도하게 줄바꿈되지 않는다.
- 4인 파티의 Card가 현재 모바일 Card보다 불필요하게 좁아지지 않는다.
- 펼친 폴드에서 8인 레이드의 두 파티가 안정적으로 나란히 보인다.
- 분할 화면처럼 실제 가용 폭이 줄어들면 자동으로 좁은 레이아웃으로 복귀한다.

breakpoint를 여러 단계로 늘리거나 폴더블 전용 패키지를 도입하지 않는다. 실제 검증에서 단일 breakpoint로 해결할 수 없는 문제가 확인될 때만 별도 설계한다.

## 6. 구현 방향

현재 `PartySlotBoard`와 Slot Card는 유지한다. 프레젠테이션 계층의 그룹 배치만 변경한다.

1. `_PartyCompositionSection`에서 가용 폭으로 파티 그룹의 열 수를 결정한다.
2. 좁은 레이아웃은 파티 제목과 Slot Card 4개를 하나의 파티 그룹으로 묶어 세로로 배치한다.
3. 넓은 레이아웃은 1파티·2파티 제목을 좌우로 두고, 같은 자리 번호의 Slot Card를 한 행에 배치한다.
4. 넓은 레이아웃의 같은 자리 좌우 Card는 `IntrinsicHeight`로 높이를 맞춘다.
5. `_SlotCardGrid`는 좁은 레이아웃에서만 사용하며 Card는 항상 1열 전체 폭을 사용한다.
6. `자리 미정`은 파티 그룹과 분리하여 두 파티 아래에서 구성판 전체 폭을 사용한다.

새로운 상태 관리, Repository, Domain 객체 또는 외부 패키지는 필요하지 않다.

## 7. 접근성 및 안정성

- 시스템 글자 크기가 커져도 Card 내부 텍스트를 고정 높이로 자르지 않는다.
- 긴 캐릭터명 처리와 접근 가능한 전체 이름 표시는 기존 Slot Card 정책을 유지한다.
- 좌우 배치는 시각적 표현만 바꾸며 읽기·포커스 순서는 1파티의 1~4번 다음 2파티의 1~4번을 유지한다.
- 로딩, 실패, 오프라인 캐시 안내와 `자리 미정` 표시 조건은 변경하지 않는다.
- 화면 회전이나 창 크기 변경 시 현재 가용 폭에 따라 즉시 다시 배치한다.

## 8. 검증 시나리오

### 자동 위젯 테스트

- breakpoint 미만의 4인 구성판에서 Slot Card 4개가 전체 폭의 1열로 배치된다.
- breakpoint 미만의 8인 구성판에서 1파티 다음 2파티가 세로로 배치된다.
- breakpoint 이상의 4인 구성판에서 1파티가 왼쪽 절반을 사용하고 Card는 파티 열 안에서 1열이다.
- breakpoint 이상의 8인 구성판에서 1파티와 2파티가 좌우 동일 폭으로 배치된다.
- 넓은 8인 구성판의 읽기 순서와 Slot key가 기존과 동일하다.
- `자리 미정` Card는 넓은 화면에서도 두 파티 아래 전체 폭에 표시된다.
- 로딩·실패·캐시 안내 분기가 기존과 동일하게 유지된다.

### 실기기 확인

- 일반 바형 스마트폰 세로 화면에서 Card가 구성판 가로 폭을 충분히 사용한다.
- 일반 스마트폰 가로 화면에서 실제 가용 폭에 맞춰 자연스럽게 전환된다.
- 펼친 폴드에서 4인 파티가 왼쪽 절반에 정렬되고 오른쪽은 불필요한 UI 없이 비어 있다.
- 펼친 폴드에서 8인 공격대의 1파티와 2파티가 좌우로 구분된다.
- 폴드 분할 화면에서는 기기 종류와 관계없이 좁은 레이아웃으로 복귀한다.
- 긴 캐릭터명, 파티장·공대장 배지와 역할 배지가 잘리거나 심하게 겹치지 않는다.

## 9. 완료 조건

- 좁은 화면의 모든 Slot Card가 구성판의 전체 가용 폭을 사용한다.
- 넓은 4인 화면은 1파티를 왼쪽 파티 열에 표시한다.
- 넓은 8인 화면은 1파티와 2파티를 좌우 파티 열에 표시한다.
- 파티 내부 Slot Card는 화면 크기와 관계없이 1열을 유지한다.
- 파티 데이터, 슬롯 계산, 가입과 승인 동작에는 변화가 없다.
- 관련 위젯 테스트와 `flutter analyze`가 통과한다.
- 바형 스마트폰과 펼친 폴드에서 실기기 레이아웃 확인을 완료한다.
