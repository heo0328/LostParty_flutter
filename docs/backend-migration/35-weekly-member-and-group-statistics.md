# 사용자·그룹 주간 이용 통계 요구

기준: 2026-10-17 사용자 요청. **설계/협업 단계, 미구현**. 현재한도/주간완료원장/현재방membership과별개인통계다. #10 서버주차, #12그룹, #13모집·반복방 계약을 재사용한다. BM/대시보드/새화면/배포는 이번범위가 아니다.

## 확정 목적과 기간

2026-10-19 [Issue19 검토 회신](https://github.com/heo0328/lostparty-backend/issues/19#issuecomment-6259127594): 원천·coverage 및 관측된0/집계불가null 구분은 소비 구조로 검토했다. 한 주 최초 참가 type 고정, 함께 집계의 경계 참가 중 조건/해산 OFF, 평균 기본 분모의 일부·미확정 주차 제외, 현재 그룹 구성원 전용 조회 권한 상세는 **Backend 제안이며 사용자 확정 정책이 아니다**. 최종 계약에서 확정 기준과 분리하고 경계 예시로 검토한다.

- Asia/Seoul 매주 수요일06:00부터 다음수요일06:00 직전까지 한주다. 서버주차ID와 DB서버시각을 사용하며 경계06:00은 다음주에 속한다. 저장시각은UTC/화면은기존KST초단위 원칙을 따른다.
- 앱 사용자UUID의 모든 원정대/캐릭터를 합산하고 계정에 연결한 주차별 이력을 보관한다. 현재카운터만덮어쓰지않고 향후 주별추이/평균을 재계산할 수 있어야 한다.
- 공개/그룹전용 레이드, 완료/미완료종료는 각각분리저장한다. 운영상 `완료+미완료종료` 합계를 함께볼수있지만 **미완료종료를실제게임클리어/주간완료Claim으로승격하지않는다.** 개인수동체크는모집완료통계에서제외한다.
- 반복방은 room과주차/회차를구분한다. 이번주관계/결과를다음주회차로중복이월하지않으며 잔류참가관계가있으면새주차의이용현황으로평가한다. 통계마감은방진행/현재한도/참가관계를자동초기화하는권한이아니다.

## 사용자별 필수 항목

| 항목 | 보관할 값 |
|---|---|
| 생성·참가 공개 모집 | 공개 레이드 이용 방 수 |
| 생성·참가 그룹전용 모집 | 그룹 레이드 이용 방 수 |
| 생성·참가 그룹 | 기존가입/신규생성·가입을구분하지않는그룹총수 |
| 공개 모집 결과 | 완료 수 / 미완료종료 수 / 둘의합계 |
| 그룹전용 모집 결과 | 완료 수 / 미완료종료 수 / 둘의합계 |
| 다음주 함께하기 | 위각유형결과중함께하기활성방 수. 공개/그룹과완료/미완료별기초값을보존해부분합가능 |

생성자는참가와중복집계하지않고, 여러캐릭터/탈퇴후재가입/명령재시도 때문에 같은사용자·방·회차가중복되지않는다. 확정참가와승인대기신청은구분한다. 대기신청은참가로계산하지않는명세안을 Backend가명시한다.

## 그룹별 필수 항목

- 해당그룹에서생성한그룹전용레이드방수.
- 해당그룹전용레이드의주차별완료수/미완료종료수/합계.
- 그결과중다음주함께하기활성수(결과별기초값보존).
- 그룹통계는회원별통계합계가아니다. 방1개를참가인원만큼세지않고groupUUID/roomUUID/cycle기준중복을막는다. 신규방생성과기존반복방의이번주회차진행은구분가능한원천을보존해‘생성수’를부풀리지않는다.

## 사용자 추가 답변 — 집계 기준 확정

1. 해당 주에 한 번이라도 확정 참가한 고유 방·그룹을 집계한다. 이전부터 참가 중이던 항목과 주중 신규 생성/참가를 모두 포함하며 주중 탈퇴/해산해도 이용 현황에서 제외하지 않는다. 생성자는 참가와 중복 계산하지 않는다. 방은 roomUUID+주차/회차, 그룹은groupUUID 기준이다.
2. 수요일06시까지 완료 처리 없이 주차를 넘긴 이번 주 회차는 **미완료 종료**로 집계한다. 명시적으로미완료종료한회차와함께합산가능하되원천사유는구분해중복을막는다. 이전회차주간마감과다음주반복회차를구분하고통계집계가현재방membership삭제나개인완료Claim생성을직접실행하지않는다. 단순잠정/조회실패를미완료종료로단정하지않고권위있는마감대상회차를평가한다.
3. 다음주함께하기 활성 여부는 **수요일06시 주간 마감 시점** 값으로 기록한다. 완료가일찍됐더라도마감전설정변경을반영하고마감후새회차설정변경으로과거통계를덮지않는다. 주중방이해산됐다면마감이전설정/종료이력과정의된실효값을원천에서판정할수있어야한다.

세질문은답변완료다. 기존회차의정상상태전이와통계마감은같은주차경계를사용하고서버명령과중복실행/집계경쟁을검증한다. 통계의‘완료+미완료종료’는운영상종료실적이며실제게임클리어통계라는명칭을사용하지않는다.

## Backend 명세에서 필요한 경계

- 권위는서버의확정참가/방회차결과/함께하기설정이력이다. GET/클라이언트누적·수동체크·현재원정대캐릭터목록만으로과거통계를재구성하지않는다. 참가당시userUUID/room/group/cycle및필요한이벤트시각을보존해캐릭터이름변경·퇴역·탈퇴후에도기존주차집계를잃지않는다.
- 미완료종료의실제사유와마감시미완료종료분류사유를구분한다. 결과시각/회차/주차별집계기준을명시한다. 중간에탈퇴한회원이후방완료를그회원완료로자동가산하지않도록결과당시참가snapshot과주중이용현황을구분하는방향으로제안한다.
- 공개/그룹전용전환·그룹연결변경이있으면생성당시유형/그룹과결과당시유형/그룹을추적할수있는최소원천을명세한다. 현재값을과거전체에덮지않고공개/그룹분류기준과집계의합계를Backend안에서명확히제시한다. 사용자확정없이모호한경계숫자를고정하지않는다.
- 완료/미완료종료는같은방회차결과로중복가산하지않는다. 실제회차상태전이/멱등성/허용된정정에맞춘버전/수정정책이필요하다. 단순개인수동체크/해제는모집결과집계에영향없다.
- 수요일06시에사용자가접속하지않아도서버에서집계가능해야한다. 지연된배치/재시도/중복실행/서버중단후여러주재처리에도같은결과가되도록마감키/집계revision/워터마크를둔다. 정확히06시에대량동기쓰기가끝나야하는구조는강제하지않는다.
- 미구현원장/집계실패/해당주누락은0으로숨기지않는다. 잠정/확정·집계완료주차·평균분모의관찰주수(진짜0주포함/미관찰제외)를구분해향후평균산출왜곡을방지한다.
- 일반회원의통계직접쓰기/임의userID조회는금지한다. 본인조회/그룹조회/내부운영분석권한과노출범위를각각명세한다. 공개검색에개인통계나private회원명단을새로노출하지않는다. 운영분석UI/공개대시보드는추후다.
- 통계저장주기는제품요구이며현재개발자료초기화/과거자료이관을요청하지않는다. 구현이전원천이없던주의통계를임의생성하거나과거실적0으로단정하지않는다. 베타전개발DB정리·이후보존원칙유지.

## 작업 순서·완료 조건

1. 사용자3기준확정반영및Backend통계계약/최소원천이력·권한/마감재처리·공개전환경계제안.
2. #12/#13실제방·회차·회원관계명령에필요한원천을연결하고통계집계/주차별보관을독립구간으로구현·검증. 기존한도원인/회원/Claim정책을재사용하며통계가진행권한을만들지않는다.
3. 향후필요시조회/추이·평균화면을기존UI와별도협의한다. 이번엔숫자기록요구이며UI를추측구현하지않는다.
