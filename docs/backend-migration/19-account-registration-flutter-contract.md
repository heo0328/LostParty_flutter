## 연결·경계

BackendApp의 기존 Dio/AuthAccountReadSession → BackendRegistrationApi → ServerRegistrationViewModel → /account/server-management의 ServerRegistrationPage. 내 계정 하단 계정 도구 ServerAccountsPanel의 등록·관리 버튼으로 진입하며 기존 메인/부계정/도구 디자인·로컬 Repository·DB는 유지한다.

- preview POST(character_name), 등록 POST(lookup_character_name/label/is_main), PATCH(expected_version/label/is_main), DELETE(query expected_version/body없음/204), refresh POST(빈object)를 원본 계약으로 연결했다. 인증된 사용자만 호출하며 미리보기 TTL·필수 shape/중복/200명 상한·입력 캐릭터 존재를 확인한다. 등록/preview는 미인증 상태이며 서버 활동 자격을 생성하지 않는다.
- 기존 읽기 HTTP 인증/에러 경계를 request 함수로 재사용한다. ACCESS_EXPIRED401만 갱신 후 같은 key/body로1회 전송, 다른 세션401/ACCOUNT_DISABLED403은 기존 종료 정책, 업무403은 로그인 유지. UUID·positive version·응답 대상UUID·strict DTO를 확인하고 응답 형식이 잘못돼도 쓰기 성공으로 확정하지 않는다.
- 불변 command는 UUIDv4 key·회원/세션 세대·path/method·body/query·시작시각을 메모리에 보관한다. 보안 난수는 기존 newAuthSecret의 난수 바이트를 사용하고 UUID v4/variant bits를 지정한다. 연타·다른 쓰기를 차단하고 응답 유실/진행중/503은 사용자가 같은 요청을 재시도한다. Retry-After는 새 요청/재시도 모두 적용하며 timer는 UI 활성 안내만 한다. 자동 HTTP 재시도는401 갱신 외에는 없다.
- 24시간 후 같은 key 재시도는 차단한다. 멱등 충돌/만료는 GET과 사용자 확인 없이 새key로 대체하지 않는다. 서버 상태 확인은 전체 GET 성공 후 현재 목록을 보여주며 사용자가 명시적으로 요청 확인을 종료할 수 있다. 처리 중 요청이 뒤늦게 반영될 수 있음을 안내한다. 실패한 GET에서는 요청을 폐기하지 않는다.
- 명확한 입력/권한/404/429/version 충돌은 실패 안내와 현재 GET을 사용하고, 다른409/불명확 응답은 pending으로 유지한다. 성공 HTTP도 현재 목록은 GET으로 확인하며 로컬 캐릭터·빌드 자료를 서버 결과로 덮어쓰거나 삭제하지 않는다. 제거는 확인 알럿을 거치며 서버 등록 관계 제거와 로컬 삭제를 구분한다.
- command/preview는 앱 서비스 수명 동안 유지한다. 화면 재진입에서는 이어서 확인 가능하지만 저장 장치에 journal을 추가하지 않았다. 앱 재실행은 GET만 하며 쓰기를 자동 복구/새로 제출하지 않는다. 로그아웃/같은 회원 새세션·회원 전환은 이전private상태/늦은응답을 격리하고 열려 있는 수정/삭제/결과 확인 알럿과 입력도 닫거나 지운다.
