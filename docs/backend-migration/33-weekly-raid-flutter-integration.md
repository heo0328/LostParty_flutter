# 기존 주간 레이드 체크박스 서버 연결

기준: 2026-10-17 사용자 진행 승인. 카탈로그는 [#10 2번째](https://github.com/heo0328/lostparty-backend/issues/10#issuecomment-6230019531)의 d7f762f, 주간 원장은 [#11 2번째](https://github.com/heo0328/lostparty-backend/issues/11#issuecomment-6230329942)의 bce6133 게시 계약을 소비한다. 실제 파티/그룹 연결과 전체 완료는 이번 범위가 아니다. 현재 실행 결과/인계 댓글은 NEXT_WORK에 기록한다.

## 사용자가 보는 흐름

내 계정의 기존 캐릭터 카드·2/3/4열·왕관·하단 주간 체크 영역을 유지한다. 로그인 회원의 현재 소유 캐릭터에 서버 카탈로그·주차·본인 주간 상태를 연결한다. 기존 입장 가능한 레이드 추천·기본3개·최대5개/0개 숨김·표기 레이드 선택 창을 재사용한다. 숫자 표시는 정수이며 원본 입장레벨의 소수점은 비교에서 보존한다.

체크 시 기존 확인창에서 취소는 왼쪽, 완료/해제는 오른쪽이다. 개인 완료와 개인 완료 근거 해제만 실행한다. 수동·파티 완료 근거가 함께 있으면 개인 근거만 지우고 파티 완료 표시는 유지한다. 파티 근거만 있거나 참가 중인 레이드에는 서버가 허용하지 않는 변경을 제공하지 않는다. 참가 중 완료 영향 확인/탈퇴를 임의 구현하지 않는다.

조회 실패는 미완료 판정이 아니다. 상태 확인이 안 된 행은 체크 불가·확인 필요로 표시한다. 실패·저장 미확정 때만 목적이 분명한 다시 불러오기/저장 재시도/현재 상태 유지 버튼을 노출한다. 정상 상태에 상시 복구 버튼을 추가하지 않는다. 주간 서버 GET은 개인 로스트아크 키나 나이스단 자동 상세 갱신과 별개다.

2026-10-17 사용자 실제 수동 완료 성공/회귀 정정: 통신 중이라는 이유만으로 전체 행에 확인 필요/i를 붙이지 않는다. 일반 manual 완료/미완료는 체크만 표시한다. 파티 참가/파티 완료 근거 등 의미 있는 정보와 실제 실패만 안내한다. 마지막 확인 체크는 PUT/후속GET 중 보존하고 새 쓰기는 잠근다. 저장 중 편집 아이콘은 자리를 유지한 채 비활성화한다. 타이틀 AppBar 내부 하단의 높이2 진행 표시를 IgnorePointer overlay로 표시해 본문/카드/터치영역을 밀지 않는다. 정상 저장 중 pending 문구/복구 버튼은 삽입하지 않고 실패·미확정으로 작업이 끝났을 때만 노출한다. 요청의 전체 주간 GET/현재 권한 검증은 그대로며 전투력/장비 상세 전체 재조회가 아니다.

## 데이터 흐름·권한

**i 표시 최신 정정:** 위 회귀 정정의 ‘파티 완료 근거 안내’는 사용자 기존 정책과 달라 철회한다. i는 현재 모집방 참가 관계 전용이다. 미완료 대기/진행·완료 후 해산 전·다음주 함께하기 유지 관계에 표시하며, 완료근거만 있거나 탈퇴/해산된 방에는 표시하지 않는다. 체크는 주간 완료 여부로 독립이다. 현재 #11 DTO는 완료근거/participation 동시 존재 금지이므로 완료 후 잔류/반복방 관계를 충분히 표현하지 못한다. 현재 participation의 i는 유지하고 party 완료 source만으로 만든 i는 제거한다. #13에서 membership/방 수명과 주간 점유를 분리한 조회 계약을 받은 뒤 나머지를 연결한다. 미구현을 완료로 보고하거나 DTO를 임의 확장하지 않는다.

- BackendApp → BackendMemberAccount가 앱 수명의 MemberWeeklyViewModel을 소유한다. 페이지는 구독/명령만 한다. 모델의 현재 회원·서버 환경·등록/소유·canonical UUID와 기존 Bearer transport를 사용한다. 기기 공용 캐릭터 int ID/이름으로 주간 원장을 쓰지 않는다.
- 공개 `GET /v1/raid-catalog`, `GET /v1/raid-cycle`은 token 조회/갱신 없이 호출하고 리다이렉트도 따르지 않는다. 엄격 DTO·카탈로그 검증과 KST 수요일06시/UTC7일 구간을 검증한다. 서버 문자열 입장레벨은 기존 domain의 선택적 exactMinItemLevel로 보존한다.
- 본인 GET은 `character_id` 반복 query key로 최대50개씩 조회한다. 현재 소유의 표시 캐릭터와 복구가 필요한 본인 pending 대상을 읽는다. 각 배치의 캐릭터×전체 catalog raid 조합, 누락·중복·타인/미요청 ID·catalog version·cycle을 전부 확인한 뒤 한 번에 투영한다. 부분 배치를 성공 상태로 승격하지 않는다.
- 현재 소유/생명주기 revision과 현재 조회 주차·서버 허용 플래그가 일치할 때만 쓰기 가능하다. 조회 실패/캐시/계정 전환/설정 중 상태를 현재 권한으로 사용하지 않는다. 서버의 최종 CAS·권한 검증을 대체하지 않는다.
- 주차 종료까지 서버 시각과 경과 시간을 사용한다. 긴 배치 중 주차가 바뀌면 전체 결과를 쓰기 가능 상태로 게시하지 않는다. 타이머 경계에는 현재 주차를 다시 읽는다. 과거 성공 ACK를 현재 체크나 다음 주 명령으로 적용하지 않는다.

## 저장 수명·실패 복구

원정대의 ‘원정대 주간레이드수정’ 진입을 회원 화면에도 복구한다. 기존0..5 선택·취소 왼쪽/적용 오른쪽이며 현재 원정대의 유효 캐릭터 전체(표시/사용 미선택 포함)에 selectionForCount 추천을 적용한다. 입장 가능한 수까지만 설정하고0은 숨김이다. 표시 설정만 회원/환경별 secure store JSON에 한 번에 쓰며 실패하면 전체 이전 map을 복구한다. 완료 원장 GET/PUT은 하지 않는다. 열린 동안 원정대/회원·캐릭터/기본정보가 바뀌면 적용을 거절하고 다시 선택 안내한다. 개별 캐릭터 설정과 기존 완료 체크는 보존한다. 이 표시 설정은 현재 이 기기 보관이라는 기존 제한을 그대로 갖는다.

서버 원장은 회원+canonical character UUID+raid+cycle이며 난이도는 완료의 부가 정보다. 표시할 레이드 설정은 원장과 독립이다. 현 서버에는 표시 preference API가 없으므로 **회원+서버 환경별 이 기기 secure store**에만 표시 설정을 저장한다. 이 설정의 재설치/새 기기 복원을 주장하지 않는다. 완료 기록은 서버 GET으로 복원한다. 기기 공용 옛 자료 이전/병합이나 새 SQLite schema는 없다.

같은 저장소에 미확정 명령의 UUIDv4 key·불변 body·시작시각·ACK 수신 여부를 전송 전에 기록한다. 저장 실패 시 HTTP를 시작하지 않는다. 응답 유실은 같은 key/body로 복구하고, ACK가 확인된 경우에는 GET만 재시도한다. 서버 Retry-After 동안 자동 재전송하지 않으며 사용자 재시도도 잠근다. 24시간 지난 미확정 요청은 재전송하지 않는다.

CAS/주차/카탈로그/권한 등 확정 거절은 새 키를 자동 생성하지 않는다. 현재 GET을 성공한 뒤 ‘현재 상태 유지’로 원명령을 정리하고 새 의사결정을 받는다. 정리 저장이 끝날 때까지 다른 쓰기를 잠근다. 명령 전송 이후 과거 GET을 최신 상태로 간주하지 않는다. 앱 종료/회원 전환 후 미확정 명령은 원회원 저장 범위에 남고, 늦은 GET/PUT/디스크 결과로 다른 회원의 화면을 갱신하지 않는다.

## 검증·남은 범위

모의 HTTP와 실제 controller/store 경계로 공개 무인증/원본 소수값·50개 배치 반복 query·원자 GET·개인 완료/파티 근거 보존·응답 유실 재실행·ACK 후 GET 실패·전송 전 디스크 실패·Retry-After·확정 충돌·주차 변경·회원 전환·로컬 표시 설정 분리·소유/생명주기 revision·24시간 만료를 검증한다. 정상 화면 조작은 사용자의 기기 확인으로 남긴다.

사용자 확인: 기존 카드에서 체크/취소·해제 후 재진입, 파티 근거 보존, 표기 레이드 선택/0개 숨김, 같은 회원의 다른 기기에서 완료 기록 확인. 기존 로그인/장비 인증을 다시 요구하지 않는다. 실제 서버 회원의 완료 쓰기/기기 인수, 참여 중 영향 확인·실제 파티/최대8인 전체 완료는 자동 검증 통과로 대신하지 않는다. 자동 상세 갱신 flag·서버/DB/자료/키/배포·Git 통합은 이번 작업에서 변경하지 않는다.
