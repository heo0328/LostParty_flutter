## 최신 제품 범위 변경 — D10 채택 / 구현 준비

사용자는 비로그인 기본 로컬 검색만 허용하고, 로그인·미인증은 서버 조회용 저장, 인증 후 앱 사용 캐릭터/대표 선택·전투력/전체 빌드·활동으로 연결하는 흐름을 채택했다. 기존 guest 상세/전투력 기능 보존과 미인증 수동 전투력 계약은 이 범위에서 변경 대상이다. [정책09 D10](09-migration-decisions.md)·[사용자 흐름](../feature-definitions/LOSTPARTY_CORE_USER_FLOW_OVERVIEW.md)·NEXT_WORK가 우선한다. 기존 조회용 Registration/인증·회원 저장 기반은 유지한다. 아래 표/과거 결과가 새 정책 구현 완료를 의미하지 않는다.

## D 정정 결과 (2026-10-16)

현재 개발 DB·guest 키를 계속 사용하도록 AccountDatabase/SecureApiTokenStore 원래 연결을 복구했다. 잘못 추가한 BackendLocalData와 별도 namespace 전용 테스트4개를 제거했다. 과거1528PASS는 해당4개를 포함한 당시 결과이며 최신 검증은 NEXT_WORK를 따른다. 실제 DB·키·환경 삭제/복사/전환은 하지 않았다.

구 기기자료 전용 route/button 정리와 Firebase Console/Rules 전용 복구 안내 제거는 유지한다. 일반 로컬 기능·회원별 scoped 저장/키·자동 갱신·권한 경계는 그대로다. 기존 D 결과6207225790 중 별도 저장공간 채택 부분은 철회한다. 새8001 환경은 Backend가 만든 이력일 뿐 현재 필수 개발 대상으로 채택하지 않는다.

기준: 2026-10-16 사용자 지시. **앱 기능·UI/UX는 유지하고 Firebase 전용 구현·연결은 제거한다.** 이 문서는 신규 서버에 필요한 제품 의미와 현재 연결 상태만 공유한다. 이전 Firebase 구현/자료/운영 절차는 신규 서버의 설계·승계·호환 요구로 전달하지 않는다.

## 분류와 범위

- 기능·사용자 설정·UX·도메인 검증은 유지/재사용 대상이다. 과거에 구현됐다는 이유로 사용하지 않는 기능으로 판정하지 않는다.
- Firebase 전용 저장/인증/연결/배포·운영 구현은 제거·대체 대상이며 재연결하지 않는다. 과거 상세는 구현 자료로 인계하지 않는다.
- Drift/로컬 저장·정수ID·분석 mapper·화면은 그 자체로 Firebase 전용이 아니다. 구 자료 승계 의존과 현재 제품에 필요한 역할을 실제 참조로 나눠 판단한다. 기능을 유지하려면 새 API/저장 경계로 대체한 뒤 구 실행 연결을 제거한다.
- 기존 테스트자료를 새 시스템에 가져오거나 보존할 필요는 없다. 새 시스템에서 생성한 회원 자료의 저장/재로그인·새 기기 복원은 제품 기능이다. 개발/베타/운영 수명은 [정책09 D08](09-migration-decisions.md#d08-개발--베타--운영-데이터-수명--사용자-확정-2026-10-16)을 따른다.
- 메뉴/문서 정책이 있다는 것과 신규 Backend/실기기 구현 완료를 구분한다. 아래 공유는 현 계약 변경·모든 후속 기능 일괄 착수 요청이 아니다.

## 확인한 근거·현재 실행 지시

현 코드: SettingsPage/BackendApp routes·AppShell, MemberSettingsControls·MemberAccountPage, 현재 runtime와 저장 계약. 제품 정책: [23](23-nice-group-auto-refresh-design.md)·[26](26-roster-character-lifecycle-design.md)·[27](27-representative-quick-selection-ux.md)·[30](30-scoped-storage-write-contract.md), [파티 제품 규칙](../product/PARTY_PARTICIPATION_RULES.md)의 사용자/캐릭터 제약만 추출한다. 과거 문서에 남은 저장 기술·호환 원장을 새 계약으로 전달하지 않는다.

직접 실행 계획과 담당/완료 조건은 [NEXT_WORK](../project/NEXT_WORK.md), 회신·검증 이력은 DEV_LOG다. 현재는 공유·범위 정리이며 기능 코드/기기 자료 삭제·환경 전환은 시작하지 않는다. 공유 원본은 로컬 미커밋 상태이며 필요한 본문을 [Issue8 회신6206946439](https://github.com/heo0328/lostparty-backend/issues/8#issuecomment-6206946439)에 게시·재조회해 확인했다.

## Backend 검토 수용

[6207049997](https://github.com/heo0328/lostparty-backend/issues/8#issuecomment-6207049997)에서 제품 정책과 P2 계약을 대조해 방향 수용·추가 endpoint/DTO/권한/저장 계약 변경 불필요·추가 질문 없음을 회신했다. 기본/전체 인수 구분 질문도 해소됐다. 동일 정책 수신 회신을 반복하지 않고 실제 D 변경 결과나 새 계약 차이만 인계한다. live 소유/장비 증거·전체 실인수 보류와 D 미착수는 유지한다.
