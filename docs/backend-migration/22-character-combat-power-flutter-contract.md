## 연결

- BackendApp 공통 Dio/AuthAccountReadSession → 기존 등록 VM의 단일 불변 command → power POST. 기존 GET Repository/캐릭터 DTO에 필수 power_checked_at/power_status/power_reason를 추가하며 알 수 없는 필드나 불량 값/타입은 허용하지 않는다.
- POST /v1/me/game-accounts/{registration_id}/combat-power/refresh, body characters:[{server_name,character_name}] 1~20명과 UUIDv4 key. 이 path에만 receiveTimeout30초, 다른 요청의10초는 유지한다. 입력 목록/내부map은 불변이고 응답 items는 중복제거 입력순서/대상/상태/필드를 검증한다.
- 1700 이상 공통 정책으로 현재 대상 선별, missing/suspect는 제외한다. 조회 전/미처리 대상부터 최대20명을 우선하고 미처리(deferred)는 다음 명시 클릭에서만 새 요청으로 확인한다. 타임아웃/REQUEST_IN_PROGRESS·형식불량 성공은 같은 key/body의 pending복구를 유지한다. 전투력과 등록 쓰기를 동시에 실행하지 않으며 새 자동 polling은 없다.
- 성공/캐시/미제공/실패/제외/미처리 수를 안내하고 GET으로 실제 캐시 상태를 재조회한다. power_status와 stale/확인시각을 표시한다. 실패는 최초null/기존값유지, 실제0정상. 캐릭터 화면의 GET 관찰은 로컬 카드 표시 캐시에도 전달한다.

## 화면과 로컬 카드

서버 계정 등록·관리 → 캐릭터 보기의 전투력 확인 버튼 또는 내 계정 각 계정 머리글의 속도계 아이콘으로 확인한다. 내 계정 계정 도구에는 전투력 결과/재시도·현재 상태 확인 영역을 둔다. 한 요청은 최대20명이며 원정대가 크거나 deferred가 남으면 사용자가 다시 눌러 이어간다.

회원별 표시 서비스는 등록 목록과 등록별 캐릭터 GET을 순서대로 읽는 메모리 캐시다. 최초/재로그인은 GET만 하고 POST를 자동 실행하지 않는다. 로컬 서버명+캐릭터명 정확일치만 표시 매칭이며 canonical ID 자동 연결/소유·활동 권한을 생성하지 않는다. 서비스의 실패/회원 변경에서 이전 회원 캐시를 노출하지 않고 세대가 다른 늦은 GET은 폐기한다.

선호 역할이 선택된 로컬 카드는 기존 해당 역할 Snapshot의 전투력을 우선한다. 해당 역할 값이 없으면 다른 역할일 수 있는 서버현재값으로 대체하지 않는다. 선호 역할이 없는 카드는 현재 회원 서버 관찰값을 우선하고 미제공/null은 기존 로컬 값으로 돌아간다. 서버 조회 상태를 함께 표시해 이전 값/미조회/실패를 최신값으로 위장하지 않는다. 로컬 SQL/빌드Snapshot에는 서버값을 쓰지 않는다. 비로그인은 기존 로컬 표시다.

## 인수 범위

- 실제 등록한1700이상 캐릭터의 서버 전투력 확인 → 갱신/캐시 결과 수와 수치/상태·정상조회시각.
- 같은 서버·캐릭터의 로컬 내 계정 카드 값 표시. 선호 역할 Snapshot이 있는 카드는 해당 값 유지, 역할 값 없는 카드에 다른 역할값 대체 없음.
- 로그아웃에서 서버관찰 표시격리/기존로컬 유지, 같은회원 재로그인 GET캐시 확인. 등록/이름 성공시험 자체를 반복 요구하지 않는다.
- 20명/미처리나 provider실패는 단위경계테스트로 보완한다. 사용자가 만들기 어려운 강제오류·DBfixture 삽입/자동기기조작은 요청하지 않는다.

이번 변경은 앱 연결이며 Backend42+후속3검증보고를 실제provider 성공으로 확대하지 않는다. 전체Flutter검증/분석·APK와 실사용자 결과는 DEV_LOG/NEXT_WORK에 기록한다. 장비/활동·대표쓰기·서버개발·배포는 범위 밖이다.
