## 선행 범위와 계약 소유

사용자는 세부 변경/보완을 허용하면서 큰 틀의 API를 미리 구현하도록 요청했다. Backend는 제안 경로를 최종 DTO/SQL로 확정할 책임이 있으며 각 분야 이슈에 명세·요청/성공·실패 예시·구현 SHA/검증·남은 질문을 게시한다. 명세 완료/서버 구현/Flutter 연결/실기기 확인은 별도 상태다. Flutter는 회신 계약을 대조하고 실제 Router/DI 연결을 별도 승인 작업으로 진행한다.

현재 회원/원정대/캐릭터·키/설정 API는 재사용한다. 앱 회원1명/인증 원정대 여러개/실제 API 소속목록, canonical UUID와 현재 소유/활동/표시 구분, 역할별 최소 요약·정밀 원본, 회원 기준1파티1자리·일정 충돌, 주차·레이드별 난이도 교차 충돌을 공유했다. 사라진 캐릭터의 기존 회원 자리/참가 snapshot·파티원 경고와 명시 교체/탈퇴, 이름 재사용한 다른 회원의 권한 승계 금지도 #13에 포함했다. 이슈8 생명주기/분쟁은 중복 구현하지 않는다.

현재 개발환경/자료로 개발을 계속한다. 베타 직전 자료 초기화 정책을 현재 DB 폐기/새환경/기초 재인수로 확대하지 않는다. 과거 플랫폼 구현·자료 import/호환, 실시간/푸시/채팅·운영자 기능 일괄 개발, 배포/기기 조작은 이번 요청에서 제외했다.

## 미확정 사항 — 해당 기능만 분리

- 전체 완료 권한: 상세 흐름/주간 계약은 책임자 전용, 예전 MVP는 승인 멤버 누구나이다. 신규 서버가 임의 선택하지 않고 해당 명령 활성화 전 확인한다. 개인 완료/조회·기초 파티 구현은 진행 가능하다.
- 그룹 한계: 기존 상세50/50과 초기MVP 제한없음 충돌은2026-10-17 사용자 선택으로 **그룹 최대 15명·사용자 가입 그룹 최대 5개** 확정. G1 생성의 회원가입그룹수와 G2 가입의 그룹정원 검증에 같은 기준을 사용한다. 더 이상 미확정 질문이 아니다.
- 일정 종료 null: 사용자 단위 일정 충돌이 필요하지만 임의 기본 플레이 시간을 새로 만들지 않는다. 불명확 결과/확인 계약을 명세하고 확정 조건은 후속이다.
- 확장 승인/이동·스왑·반복 UX: 기존 Domain의 정책 종류와 현재 지원 범위를 명세하며 여러 정책을 임의 삭제/신설하지 않는다. 기본 승인/즉시가입과 독립해 후속으로 분리한다.

## 근거·검증

제품 흐름/파티 참가 규칙·그룹 제품·그룹장 이전·주간 완료 계약의 제품 의미, 현재 순수 Domain의 승인/구성/일정/주차 정책·그룹 한계, 정적 raid_catalog.v1.json, BackendApp의 파티/그룹 pending routes를 대조했다. 과거 저장 전용 경로나 자료 호환 설계를 새 서버 요구로 전송하지 않았다. 공개 GitHub 본문4개를 로컬 초안과 정규화 대조해 일치/open 확인했다. 문서 diffcheck와 링크·범위 검토만 수행한다. 기존 Flutter 코드/사용자 미커밋/Rules·tools·플랫폼 변경은 보존했다.
