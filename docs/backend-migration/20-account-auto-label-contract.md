# 빈 이름 자동 표시

사용자 최종 지시: 이름을 입력하지 않으면 현재 본·부계정 위치에 맞는 자동 이름을 표시하고 입력한 이름은 그대로 표시한다.

로컬은 기존 label 필드에 빈 문자열을 저장한다. schema13 유지, 새column/데이터migration/예약문자열/자동이름스위치 없음. 내계정 수정 입력란에 실제입력값만 표시하고 비워서 저장하면 자동이름이다. loadAccounts의 본계정우선·부계정id순서를 기준으로 빈값은 메인 계정/부계정 1/2/3…, 비어있지않은값은사용자이름을그대로반환한다. 서버/캐릭터ID·활동/대표/레이드계약 변경없음.

## Backend 요청

앞선 custom_label 추가·기존이름보존/migration 제안은 사용자 최종 지시로 취소합니다. 기존 사용자 데이터를 폐기하고 새로 만드는 기준이며 별도 보존/변환 기능을 요구하지 않습니다.

이번 변경은 단순합니다. 기존 label 입력값이 없으면 자동 이름, 사용자가 입력한 이름이 있으면 그대로 표시합니다. 예약문자열이나 자동이름을 저장하지 않습니다. 기존 label에 빈 문자열을 허용하는 방식이면 새 DB 필드 없이도 구현할 수 있습니다. null을 사용한다면 기존 label의 nullable 계약으로 처리하고 불필요한 필드를 추가하지 마세요.

POST/PATCH에서 이름 미입력/빈 값으로 자동 이름을 선택할 수 있도록 계약을 확정해 주세요. PATCH의 필드 생략은 이름 변경 없음, 명시 빈값은 자동으로 전환입니다. 응답은 실제 저장 이름(빈값 또는 null)을 구분해 주세요. 본·부계정 전환은 이름을 서로 교환하거나 갱신하지 않고 화면에서 현재 is_main·전체 부계정의 순서로 메인 계정/부계정 1/2/3…를 계산합니다. 번호는 전체 목록의 안정 순서를 사용하고 사용자지정이름 계정도 순서에 포함합니다.

기존 멱등 key/payload·expected_version/본계정전환 후전체조회는 유지합니다. 기존 데이터 이관/복구/자동 이름 패턴 판별·과거 이름 보호 절차·새 endpoint는 요청하지 않습니다. 필요한 요청/응답 스키마와 실제 구현 SHA를 인계해 주세요. Flutter 로컬 화면은 이 단순한 규칙으로 구현하며 서버 wire는 확정 계약 인계 후 연결합니다.

## 구현·검증 결과

로컬 단순 이름 표시 구현완료. 전체1178테스트/lib-test분석0, DB schema13·generated파일 기존상태, 이름값만저장하고표시를계산한다. 새2개 실제 Repository/메모리DB 테스트는 빈이름 본부전환·삭제후번호 및 직접이름유지/비워저장전환을 확인한다. 등록17개 경계와 기존 UI 테스트도 함께통과했다.

기존이름입력란을비워저장하면자동표시를사용한다. 현재이름이문자열로이미저장돼있으면입력값그대로표시하므로자동표시를원할때직접지우고저장한다. 별도모드스위치/패턴변환/기존데이터보존기능은없다.

[Backend최종요청](https://github.com/heo0328/lostparty-backend/issues/4#issuecomment-6163006876)의본문일치재조회완료. 서버endpoint는현재required label계약을사용하므로서버nullable/빈label요청은아직연결하지않았다. 서버구현/계약인계후 별도연결한다. 현재로컬기능/관련문서미커밋·dev미반영·미push, feature/account-backend-registration 유지. 기기인수는이름빈값/직접값·본부전환표시를사용자가확인한다.
