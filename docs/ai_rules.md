# AI Collaboration Rules - LOSTPARTY (2026)

이 문서는 LOSTPARTY 프로젝트에서 AI 도구(Cursor, ChatGPT 등)와 협업할 때 따를 규칙을 정의한다.

---

## 1. Project Intent

이 프로젝트는 일반적인 Flutter 학습 프로젝트가 아니다.

핵심 목표:
- 로스트아크 레이드 파티를 사전에 모집/지원할 수 있는 앱 구현
- AI 에이전트 기반 개발 실험
- 개발자는 직접 코딩보다 아래 역할에 집중한다:
  - 작업 분해
  - 프롬프트 설계
  - 결과 검토
  - 구조 통제
  - Git 기록 관리

중요:
- AI는 “한 번에 완성된 기능”을 만드는 것이 아니라
  “작은 단위로 나누어 구현”해야 한다.

---

## 2. Product Context

LOSTPARTY는 로스트아크 유저를 위한 앱이다.

핵심 기능:
- 캐릭터 인증 (API 한계로 인해 우회 방식 사용)
- 레이드 파티 모집
- 레이드 파티 지원
- 사전 예약 기반 파티 구성

특징:
- 캐릭터 단위 레이드 구조
- 그룹 기반 모집 가능성
- 주간 숙제 관리 기능 예정

제약:
- 로스트아크 API는 계정 소유 인증을 지원하지 않는다
- 캐릭터 인증은 인게임 상태 변경 기반으로 검증한다

---

## 3. MVP Principle (매우 중요)

초기 개발 범위는 아래로 제한한다:

- 캐릭터 인증 (간단 버전)
- 모집글 목록
- 모집글 작성
- 모집글 지원

금지:
- 알림 시스템
- 그룹 시스템
- 소셜 로그인
- 채팅
- 복잡한 필터

원칙:
- “확장 가능한 구조”는 유지
- “미리 다 구현”은 절대 금지

---

## 4. AI Usage Roles

역할 분리:

### ChatGPT
- 구조 설계
- 작업 분해
- 데이터 흐름 정의
- 프롬프트 생성

### Cursor
- 코드 생성
- 파일 생성
- 코드 수정

규칙:
- Cursor에 큰 기능 전체를 맡기지 않는다
- 한 번의 요청은 하나의 작업만 수행한다

---

## 5. General Principles

- AI가 생성한 코드는 반드시 검토 후 반영한다
- 의미 없는 자동 생성 코드는 사용하지 않는다
- 항상 “왜 이 코드가 필요한지” 설명 가능해야 한다
- 작은 단위로 점진적으로 구현한다
- 나중에 읽고 학습 가능한 코드를 유지한다

---

## 6. Architecture Principles

Flutter + MVVM 기반

- View: UI와 이벤트 전달
- ViewModel: 상태 관리 및 로직
- Repository: 데이터 처리
- API 호출은 View에서 직접 하지 않는다
- 기능 단위(feature-first) 구조 사용

---

## 7. Folder Structure

기본 구조:

lib/
  features/
    post/
      model/
      repository/
      view/
      viewmodel/

공통 요소는 core에 위치

---

## 8. Task Execution Rules

- 한 번에 큰 기능 구현 금지
- 작업은 반드시 단계별로 나눈다
- 각 단계는 테스트 가능해야 한다

좋은 예:
1. 모델 생성
2. Repository 생성
3. ViewModel 생성
4. UI 생성
5. 연결

금지:
- 한 번에 전체 기능 생성

---

## 9. Code Generation Rules

- 과도한 추상화 금지
- 읽기 쉬운 코드 우선
- 불필요한 라이브러리 추가 금지
- 기존 구조 우선 존중
- 설명 없는 대규모 변경 금지

---

## 10. Git Rules

### Branch
- 모든 작업은 작업 단위별 브랜치에서 진행한다
- 작업 시작 전에 반드시 현재 브랜치와 작업 트리 상태를 확인한다
- `main` 또는 기본 브랜치에서 직접 파일을 수정하지 않는다
- 기본 브랜치에서 작업을 시작해야 하면 먼저 작업 내용에 맞는 새 브랜치를 생성한다
- 하나의 브랜치에는 하나의 명확한 작업 범위만 포함한다
- 다른 작업 단위로 넘어갈 때는 현재 변경의 검증과 Git 상태를 확인한 뒤 별도 브랜치가 필요한지 판단한다
- Codex가 생성하는 브랜치는 기본적으로 `codex/` 접두사를 사용한다

### Commit
형식:
- type: message

예:
- feat: 모집글 목록 UI 추가
- chore: 초기 프로젝트 설정

금지:
- update code
- fix bug
- misc

---

## 11. Commit Strategy

- 한 커밋 = 하나의 의미
- 기능 단위로 나눌 것
- 구조 변경과 기능 추가 분리

---

## 12. Multi-Environment Rules

- Windows: 개발
- Mac: iOS 빌드 및 테스트

규칙:
- Mac에서 코드 수정 금지
- 변경 발생 시 diff 확인 후 판단

---

## 13. API Constraint Rules (중요)

- 로스트아크 API는 계정 인증 기능이 없다
- 캐릭터 인증은 “장비 변경 방식”을 기반으로 한다
- AI는 임의로 인증 로직을 단순화하거나 변경하지 않는다

---

## 14. Final Principle

이 프로젝트에서 AI는:

- 구현 도구이면서
- 구조 설계 보조 도구이다

최종 목표:
- AI 기반 개발 워크플로우 확립
- MVVM 구조 이해
- 유지보수 가능한 코드 확보
- 포트폴리오로 활용 가능한 프로젝트 완성
