# 원정대 재인증 — 실기기 확인 목록

2026-10-03. 전체 자동 회귀는 사용자 지시로 생략했다. 아래는 사용자 수동 확인용이며
아직 통과한 결과가 아니다. Rules 게시 결과는 DEV_LOG 최신 기록을 먼저 확인한다.
이번 운영 게시 1회는 원격 /test 503으로 실패했다. 현재는 **통합 Rules 게시 성공 확인 전 대기**다.

## 준비

- 모든 테스트 기기에 `fix/roster-reauth-isolation`의 최신 앱을 빌드·설치한다.
  초기화 시간은 사용자가 설정한 현재 값을 확인한다. 이 작업에서 시간을 바꾸지 않았다.
- 사용자 A(기기 1), 새 사용자 B(기기 2), 정상 참가자 C(기기 3)를 구분한다.
  원정대 R은 이전 대상, A의 다른 원정대 S는 보존 확인용이다.
- 이전 전 A의 R로 신청 대기·참가 중·완료/다음 주 대기 사례를 준비한다.
  서로 다른 레이드로 나누어 점유 충돌을 피한다. S에도 보존할 참가/완료 사례를 남긴다.
- 기존 그룹·방·이력은 초기화하거나 수동 삭제하지 않는다. 새 B에게 A의 그룹 가입이나
  방장 권한이 자동으로 생기는 것을 성공으로 판정하지 않는다.
- 앱 재설치 후 인증 정보가 복원돼 같은 사용자라면 소유자 이전 검증이 아니다.
  새 사용자임이 확실한 다른 기기에서 B 인증을 먼저 확인한다.

## 순서와 기대 결과

| 번호 | 실행 | 기대 결과 |
|---|---|---|
| 1 | A가 기존 R을 다시 인증 | 기존 참가/완료 상태 유지. 불필요한 소유자 이전이나 정리 없음 |
| 2 | B가 R을 인증 | 과거 방 정리를 요구하지 않고 R 사용 가능. A의 그룹·권한·과거 완료 체크는 B에게 승계되지 않음 |
| 3 | B의 R로 공개 모집 생성, 다른 방 신청→승인 또는 즉시 가입, 참가 캐릭터 변경 | A의 과거 점유/완료 때문에 막히지 않음. 현재 B가 새로 참가·완료한 상태의 중복 제한은 유지 |
| 4 | B가 필요한 그룹에 정상 가입한 뒤 그룹 모집 생성/가입/캐릭터 변경 | 새 그룹 가입 권한에 따라 동작. 이전 A의 그룹 권한을 사용하지 않음 |
| 5 | A의 이전 신청을 C가 뒤늦게 승인하고, A 기기에서 R로 이전 참가 변경/완료 시도 | 오래된 요청이 승인·새 권한으로 갱신되지 않음. 최신 정보를 다시 확인하도록 안내 |
| 6 | 완료 반복방의 무효 일반 참가자 A를 본인 또는 유효 공대장이 자격 확인→정리 | 선택한 1명만 다음 주 명단에서 제외. 완료 기록·그룹 가입·B의 새 참가/완료는 유지 |
| 7 | A가 공대장인 완료 반복방에서 유효 C가 자격 확인 | 앞순번 무효 참가자는 단건 정리 가능. 공대장 정리 시 확인한 첫 유효 후임에게 승계되고 후임의 모집 관리 가능 |
| 8 | A만 남은 완료 반복방에서 A가 자격 확인→해산 | 방/그룹 모집 목록이 종료되고 기존 완료 기록은 남음. 중복 해산으로 그룹 모집 수가 다시 줄지 않음 |
| 9 | 정리 도중 연결 중단 또는 앱 종료 후 재실행, 현황 상단 ‘참가 정리 처리 결과’ 확인 | 미확정 요청이 있으면 같은 요청으로 결과 확인/재시도. 이미 성공한 정리를 중복 적용하지 않음. 방이 목록에서 사라져도 메뉴 접근 가능 |
| 10 | B 사용 후 A가 R을 재인증(A→B→A) | 예전 A의 신청·참가가 자동 부활하지 않음. 새 이용 가능, B의 옛 요청은 최신 참가 권한으로 사용 불가 |
| 11 | A의 S, 무관한 그룹·기존 완료 기록 비교 | 인증·정리와 무관한 데이터/권한/기록 그대로 유지 |
| 12 | 정상 그룹방 탈퇴·추방·재가입, 캐릭터 변경/다른 파티 자리 이동, 개인 완료/취소 | 직전 실기기 통과 동작 유지 |
| 13 | 정상 반복방 전체 완료→다음 주 대기→주차 변경, 다른 기기에서 모집 조회/가입 | 정상 참가자만 다음 주로 이어지고 목록 표시 정상. 이전 소유권 참가자가 다시 붙지 않음 |

## 경계와 결과 기록

- 3기기로 만들 수 없는 만석 8인 전환은 **미확인**으로 남긴다. 소수 인원 성공을 8인 성공으로 확대하지 않는다.
- 연결 실패/조회 실패 시 참가자가 자동 삭제되면 실패다. 정리 요청의 ‘기기 기록 지우기’는
  서버 작업 취소가 아니므로 응답 불명 상태에서는 먼저 결과를 확인한다.
- 새 앱은 차수를 보존한다. 구버전 앱의 차수 누락 인증/참가 쓰기는 거절될 수 있으므로
  테스트 중 구버전을 섞지 않는다. 구버전 호환 전체 검증은 생략 상태다.
- 게시가 실패했다면 2–10의 신규 기능 결과를 판정하지 말고, 운영 Rules가 일치한 뒤 진행한다.
- 결과는 `번호 / 성공·실패·미확인 / 사용자·캐릭터 / 방·레이드 / 시각 / 표시 메시지`로 기록한다.
  오류가 발생한 사례만 해당 기기의 로그를 함께 확인한다.
