# NEXT WORK — 실제 push 진입의 종료 목록 복귀 기기 재확인

## 현재 상태 — 기기 재발 원인 재현·최소 수정 완료

feature/raid-recruitment-scheduling / ef4f424c 후속. 사용자 기기에서 개인 완료 후 탈퇴의 로딩 확인창/기록 상세 잔류가 재발했다. 이전258개 시험은 상세 URL 직접 진입을 사용해 일반 앱의 현황/검색→context.push를 누락했다. §37.82를 기기 해결로 보지 않으며 재발과 검증 한계는 BUG027/설계37 §37.83 및 [Issue13 정정 회신6418614101](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6418614101)에 기록했다.

원인: 종료 시 routeInformationProvider.value.uri를 현재 화면으로 오인했다. go_router의 push는 실제 표시 상세와 달리 이 값을 원래 /raid-status에 유지하므로 종료 가드가 목록 이동을 차단했고, 이후 재조회가 기록 화면으로 바꿨다. 검증된 ACK/성공 통지는 도착했다. 기존 root 확인창 소유권 수정은 유지하고, 전역 활성 leaf인 router.state.uri와 pageKey/현재 상세 route를 함께 확인하도록 최소 수정했다. 비활성 브랜치의 자체 GoRouterState만으로 판단하지 않는다.

검증: 실제 StatefulShellRoute.indexedStack의 현황→상세 push·실제 Controller의 유효한 개인 완료 후 탈퇴 ACK·root 확인창으로 수정 전 실패→후 통과를 확인했다. 후속 계정 조회를 보류한 상태에서 먼저 확인창이 닫히고 참가 중 목록으로 돌아가며, 조회 실패 뒤에도 POST1/기존 성공 유지. 다른 화면/회원 전환 무이동·직접 진입/주차 완료·기록/원요청 복구·목록 갱신의 직접 시험156개 통과, 변경 분석0·포맷/diffcheck·검토. 서버/API·원요청·계정/사용량 갱신은 변경하지 않았다.

## 다음 행동 — 사용자 기기 두 종료 흐름 재확인

1. 실제 현황 목록에서 방 카드로 진입→나혼자 완료 후 탈퇴: 승계/성공 후 확인창이 닫히고 해당 주차의 참가 중 목록으로 즉시 돌아오는지 확인한다.
2. 실제 목록에서 상세 진입→주차 완료: 기록/일정 확인 화면 대신 참가 중 목록으로 돌아오는지 확인한다.

사용자가 이미 통과한 후보/가입·조율/그래프/제안/자동 조기확정·1인탈퇴/승계·주차 독립·한도 정책은 유지한다. 재현 없는 복구 배너를 강제 기기 과제로 두지 않는다. 기기 성공은 아직 미확인이다. Backend/API·DB/자료·배포·dev/main·웹소켓·리디자인·BUG025·IF001은 제외하며 무관 dirty를 보존한다. 코드·재현시험·문서를 같은 브랜치의 한 파트로 커밋/푸시한다.
