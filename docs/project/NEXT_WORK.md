## 확정된 화면 요구사항

1. **최상단 일반/그룹 선택**: 일반 레이드와 그룹 레이드 중 하나를 선택한다. 기본값은 일반 레이드. 그룹 모드에서만 현재 가입한 유효 그룹 목록을 드롭다운으로 펼쳐 선택한다.
2. **파티장 캐릭터 + 역할 한 줄**: 캐릭터 선택에 대부분의 폭을 배정하고 역할은 작은 드롭다운으로 배치한다. 눈에 보이는 ‘파티장 역할’ 라벨과 별도 설명은 제거하되 접근성 이름은 유지한다.
3. **선호 포지션 기본 선택**: 딜러·서포터 복수 역할 직업만 역할 변경을 허용한다. 유효한 저장 선호 포지션을 먼저 선택하고, 선호값이 없거나 사용할 수 없으면 기존 유효 역할 기본 규칙을 유지한다. 단일 역할은 별도 선택을 요구하지 않으며 없는 세팅을 생성하지 않는다.
4. **모집 제목 유지**: 기존 입력 UI·사용자 입력·자동 기본 제목 동작을 보존한다. 그룹명으로 제목을 강제 변경하지 않는다.
5. **레이드 + 난이도 한 줄**: 기본적으로 절반씩 배치한다.
6. **최소 전투력 + 숙련도 한 줄**: 기본적으로 절반씩 배치한다.
7. 나머지 옵션과 검증은 유지한다. 기본 화면 순서는 일반/그룹·그룹 선택 → 캐릭터/작은 역할 → 기존 제목 → 레이드/난이도 → 최소 전투력/숙련도다. 일반 휴대폰은 한 줄 배치를 우선하고 긴 이름·큰 글꼴·좁은 화면에서는 잘림을 피한다.

## 확정 요구 — 단일 그룹 매칭

- 사용자의 최종 결정: 그룹 가입·탈퇴가 쉬우므로 한 레이드를 하나의 그룹에만 연결한다.
- 일반 레이드는 groupId=null, 그룹 레이드는 가입한 유효 그룹 하나를 드롭다운으로 선택해 저장한다. 그룹 모드에서 선택은 필수다.
- groupId 단일 필드를 유지한다. groupIds 배열·다중 체크박스·다대다 배정·다중 그룹 비용 비교는 범위에서 제외한다.
- 현재 생성 코드는 visibility=public/groupId=null을 사용하므로 선택 UI뿐 아니라 실제 그룹 저장·조회·신청 권한 연결도 필요하다.
- 목록 필터의 복수 그룹 선택 기획은 별개로 유지하며 이번 생성 화면 구현에 섞지 않는다.

- 기존 자동 제목, 캐릭터 변경에 따른 역할 재선택, 입장 조건·세팅 유효성 및 버튼 중복 요청 방지를 유지한다.

- 이 단위는 기존 일반 레이드 생성 동작을 유지하며 독립 검증한다.

### B. 최상단 일반/그룹 선택과 실제 연결

- §9.2의 단일 그룹 확정에 따라 최상단 모드와 가입 그룹 하나를 선택하는 드롭다운을 연결한다.
- 그룹 미가입/선택 없음/목록 로딩·실패/선택 후 탈퇴를 처리한다. 일반 모드에서는 그룹 선택을 숨기고 전송값에서도 제외한다.
- 최소 생성 payload·읽기·신청 권한을 함께 검토한다. UI에서 그룹을 선택했는데 실제로 public/null 일반 모집으로 저장하는 가짜 완료를 만들지 않는다.
- 그룹 전용/전체 공개·그룹 탈퇴 시 참가 자격 정책은 기존 단일 그룹 제품 계약을 보존한다.
- 실제 데이터·Rules 확장은 필요한 범위를 먼저 정리하고 독립 구현 단위로 진행한다. 전체 그룹 관리 기능과 묶지 않는다.
