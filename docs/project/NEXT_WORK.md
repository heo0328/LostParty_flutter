현재 완료된 캐시·등록/인증·관리 연결과 표시 코드를 feature/scoped-account-cache에서 커밋하고 최신 origin/dev 대조→dev 병합·push한다. 최종 전체 1,591PASS·lib/test 분석0·format/diffcheck 이후 기능 코드 변경 없음으로 해당 검증을 재사용한다. Git 통합 결과는 실제 커밋과 원격 일치를 확인한 뒤 보고한다. 별도 기존 Rules 백업 2개와 tools는 수정/삭제/추가 커밋하지 않는다. main·서버 배포·자료 초기화·Issue 종료는 범위 밖이다.

## 통합·push 후 dev에서 분석할 작업

1. **기존 관리 진입 경로 누락 조사.** 사용자가 디자인 변경 뒤 원정대 이름 변경·활동 캐릭터 선택 등에 들어가는 버튼이 사라졌다고 보고했다. 기존 기능과 실제 Router/DI/callback/flag·로컬/회원 화면을 대조해 구현 존재와 사용자 접근 가능을 구분한다. 완료 문구만으로 동작 가능하다고 판단하지 않는다. 새 화면을 선제 신설하지 않고 기존 관리 기능을 우선 복구한다.
2. **인증 버튼 배치.** 내 계정 원정대 이름 라벨 바로 오른쪽에 현재의 절반 정도 크기로 둔다. 화면 오른쪽 끝 정렬이 아니다. 긴 이름은 버튼 영역을 유지하고 두 줄로 흐르게 한다. 정확한 기존 컴포넌트와 이름 길이 제한을 확인한다.
3. **새 기기 서버→로컬 회원 캐릭터 복원.** 로그인 전 구 기기 공용 목록에 다른 원정대 자료가 있는 사례다. 서버 회원 원정대/인증 상태는 실제 표시 확인됐다. 같은 회원의 캐릭터·활동 선택/역할 요약을 어떤 로컬 저장소에 언제 읽는지, 기본 flag와 주화면에 어떤 연결이 필요한지 확인한다. 서버 데이터 복원과 구 Firebase/기기 자료의 이관·이름 기반 병합은 구분하며 후자는 수행하지 않는다.

사용자 순서 지시대로 이번에는 dev push 완료 후 위 원인/영향과 최소 수정 순서를 **분석**한다. 후속 기능 구현은 이 통합에 섞지 않는다. 기존 표시/인증·소유/회원 격리·사용자 지정 순서·1700 자격·정밀한 저장/정렬을 회귀 보호한다.

## 유지할 제품 기준

[정책09 D11](../backend-migration/09-migration-decisions.md): 사용자 1명→복수 실제 원정대→API 소속 전체 목록. 서버는 provider 결과를 저장하고 앱 활동 확인/향후 파티·그룹에 사용한다. 원정대 소속·사용자 귀속/인증·활동 선택·표시 설정을 분리한다. 인증에 쓴 캐릭터 소멸로 원정대 인증을 해제하지 않는다. 실패/부분 응답으로 삭제하지 않는다.

로그인 회원의 서버 저장 원정대와 구 기기 공용 목록을 이름으로 자동 통합하지 않는다. 기본 기능 flag/개발환경·DB/키/자료는 변경하지 않는다. 소유 이전·24시간 분쟁·live 퇴역/claim해제·파티/그룹 서버 연결은 별도 후속이다. 베타 시작 직전 자료 삭제는 현재 작업이 아니다. 실기기 설치/조작은 사용자 담당이다.
