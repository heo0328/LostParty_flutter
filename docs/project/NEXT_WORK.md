# NEXT WORK

## 현재 우선 작업 — 그룹장 정상 탈퇴·이전·해산 계약과 구현

현재 단계: **B + 그룹 전용 모집 목록 실기기 확인 및 Git 통합 완료**. 다음 작업은 그룹을 생성한 그룹장이 정상적으로 역할을 넘기고 탈퇴하거나 그룹을 해산할 수 있는 시스템이다.

- 그룹 레이드 생성(일반/그룹, 가입 그룹 하나, `그룹만 공개` 기본값)과 그룹원 레이드 모집 리스트 노출이 동작한다.
- 그룹만 공개는 `groups/{groupId}/raidListings/{recruitmentId}` Projection으로 모집 리스트에 합친다. `recruitments` list에 그룹 membership `exists`나 `visibility==group` 쿼리를 쓰지 않는다.
- 책임자·확정 멤버 본인 방은 모집 리스트에서 제외하고 레이드 현황에서 본다.
- 사용자 실기기에서 그룹만 공개 방 생성과 다른 그룹원의 레이드 모집 리스트 노출을 확인했다.

### 이번 작업의 선행 설계

- 제품 정책은 [`../product/GROUP_PRODUCT_FLOW.md`](../product/GROUP_PRODUCT_FLOW.md) §10·§13·§14를 따른다.
- 정상 그룹장은 바로 탈퇴할 수 없다. 다른 유효 그룹원에게 그룹장 이전을 완료한 뒤 일반 멤버 탈퇴를 실행하거나 그룹을 해산한다.
- 구현 전에 그룹장 이전 요청·수락, 이전과 기존 그룹장 탈퇴의 원자성, 후임자 유효성, 마지막 1인 그룹 해산, 초대·신청·초대코드·membership Projection 정리, 동시 요청과 revision 실패를 Firestore Transaction·Rules 계약으로 분리한다.
- 그룹 해산은 연결된 레이드방을 자동 해산하지 않는다. 그룹 전용 레이드의 조회·신청·기존 참가 자격 처리는 후속 그룹-레이드 자격 작업과 연결한다.

### 후속 구현 순서

1. 그룹장 정상 탈퇴·그룹장 이전·그룹 해산
2. 생성 후 `그룹만 공개 ↔ 전체 공개` 전환
3. 자리·인원·상태 변경에 맞춘 `raidListings` 갱신
4. listing이 없는 기존 그룹 레이드 보완
5. 그룹 탈퇴·추방·해산 시 그룹 전용 레이드 자격 박탈과 제한적 정리
6. 위 기능과 실기기 확인을 완료한 뒤 레이드 모집·현황 그룹 필터

### 필터 착수 게이트

- 필터 기획은 이미 [`../product/GROUP_PRODUCT_FLOW.md`](../product/GROUP_PRODUCT_FLOW.md) §8과 §15에 기록되어 있다.
- **필터 구현 직전 별도의 재확인·검토 단계를 반드시 거친다. 검토 완료 전에는 필터 코드를 수정하지 않는다.**
- 재검토에서 필터의 정의, 적용 화면, 포함 범위, 제외 범위, 복수 선택 의미, 기본값, 화면 간 공유, 앱 재시작 후 복원, 탈퇴·추방·해산 시 무효 선택 정리와 완료 조건을 다시 확정한다.
- 해당 문서와 당시 최신 모집 목록 Repository·레이드 현황 구조를 대조하고, 데이터 경계·로컬 상태 저장·테스트 계약을 확인한다.
- 기존 기획과 최신 코드가 충돌하거나 정의가 부족하면 사용자 검토를 거쳐 문서를 먼저 보완한 뒤 구현 작업 단위를 새로 확정한다.
- 필터는 표시 결과만 좁히며 조회·신청·참가 권한을 변경하지 않는다.
