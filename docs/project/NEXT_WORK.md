# NEXT WORK — 로컬 복구 완료·새 release 서명 전환 준비

## 승인·현재 상태 — 2026-11-07

사용자 지시로 PC 포맷 후 네이티브 개발 환경, 로컬 dev 서버 연동, 운영 서버·APK 배포 설정을 점검했다. 기존 Flutter 3.41.6/Dart 3.11.4/Java21과 Git 기준 설정·고정 의존성을 복구했고, GitHub CLI·Git 권한/push dry-run·IDE 확장을 확인했다. 사용자가 dev 로컬 에뮬레이터의 Google 로그인 정상 동작을 확인했다. 앱 코드 변경이나 신규 운영 배포 없이 개발 재개 기반을 복구했다. 검증·장애 경과는 DEV_LOG, 현재 공개 서명 식별표는 [Google 로그인 계약](../architecture/GOOGLE_LOGIN_CONTRACT.md#포맷-후-로컬-복구oauth-서명-식별-2026-11-07)에 둔다.

이전 v2.0.0 게시 작업은 완료됐다. 태그/서명 CI/체크섬·Backend 인계는 DEV_LOG와 docs/releases/v2.0.0.md의 기존 근거를 유지하며 다시 실행하지 않는다. 현재 main/dev 원격 소스는2fd87438이고, 복구 기록은 docs/local-development-recovery에서 보관한다. dev/main 통합은 별도다.

## 현재 파트·완료 조건

- 포함: 새 release 키 전환 결정과 물리 백업 목록·공식 출처·사용자 백업 안내 시점을 문서화한다. 기존 키 회수/유지를 기본 실행안으로 두지 않는다. 문서 내용·링크·git diff --check를 확인하고 같은 파트로 커밋·푸시한다.
- 제외: 신규 기능/오류 안내 UX 수정, 전체 앱 정상 흐름 재인수, Backend 코드/환경·Google 콘솔 변경, 키 생성/삭제, 운영서버 배포·새 APK 게시·dev/main 병합. 전체 기능2817PASS와 이번 복구의 인증 세션15PASS·분석0/debug APK 빌드 결과를 구분하며 문서 변경으로 시험을 반복하지 않는다.
- 완료: 복구 완료 기록과 유효 후속이 정합하고, 작업 브랜치 local/origin 동일 커밋·관련 미커밋 없음. 복구 후 공개 APK의 기존 파일 체크섬/승인 서명 일치도 확인했다.

## 남은 사용자 확인·다음 행동

1. **완료한 사용자 확인:** 사용자 보고로 과거 debug OAuth 클라이언트 삭제와 현재 debug.keystore 파일 복사 백업을 확인했다. 콘솔 삭제의 직접 재조회·백업 사본 접근 검증까지 에이전트가 수행한 것은 아니다. 로컬 Google 로그인 인수는 유지한다.
2. **새 release 키 전환 — 실행 전:** 포맷 전 release 원본 백업이 없으며 사용자는 새 키 생성·백업 후 이후 배포의 서명을 통일하기로 확정했다. 기존 Secret 키 회수는 이번 실행안에서 제외한다. 새 키/Secret/CI 지문/OAuth·Backend 운영 설정은 아직 변경하지 않았다. 실행 순서와 파일별 보관 원장은 [릴리즈 계약 B-1](../architecture/GITHUB_ANDROID_RELEASE_PIPELINE.md#release-key-backup)이다. CI 전용 배포에 로컬 key.properties 구성을 강제하지 않는다.
3. **에이전트 필수 안내:** 새 키 생성/전환 착수와 그 키의 첫 게시 전에 위 목록을 실제 경로·파일명으로 사용자에게 다시 안내한다. 키 파일·비밀번호/alias의 별도 보관 확인과 백업 사본 접근 검증 전에는 첫 게시 준비 완료·게시를 진행하지 않는다. 같은 키의 이후 업데이트는 기존 백업 기록을 재사용한다. 지금은 문서 기록만 수행한다.
4. **향후 실제 게시:** 새 서명 전환 버전은 기존 앱 삭제·재설치와 같은 Google 계정 재로그인, 로컬 전용 자료/미전송 작업 소실 가능성을 안내하고 서버 기존 회원·DB는 유지한다. 다음 실제 게시 지시에서 버전/build code·Backend 호환·고정 source/tag·새 승인 인증서/CI·로그인을 확인한다.2.0.1은 예시이며 게시 승인/버전 확정이 아니다. Play/iOS의 조건부 다운로드·보관 항목도 릴리즈 계약 B-1에서 착수 때 대조한다.
5. **Backend 백업 요청·회신 대기:** 사용자 명시 지시로 [Backend Issue46](https://github.com/heo0328/lostparty-backend/issues/46)을 신규 게시·본문 재조회했다. Backend가 로컬/AWS 실제 DB·키·환경/배포 자료와 기존 백업을 대조하고, 사용자 물리 파일/다운로드/담당 목록·암호화 별도 보관 방법·백업 안내 시점을 정리해 백업 진행/사용자 대기 결과를 같은 Issue에 회신한다. Native의 새 release 키 결정은 기존 Backend 인증/암호화키 교체 지시가 아니다. 다음 관련 착수 때 최신 회신을 확인하며 게시만으로 백업 완료 처리하지 않는다.

별도 제품 개선은 DETAIL_IMPROVEMENTS의 유효 범위를 따르며 이번 복구 완료를 새 기능 착수 승인으로 사용하지 않는다. 로컬 로그인 복구는 Backend 자체 에이전트와 사용자의 확인으로 마쳤고, 이후 새로 승인된 백업 협업 요청은 Issue46에서 구분해 추적한다.
