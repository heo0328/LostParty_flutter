## 2026-09-05 후속 개선 요청 — 문서화만 완료

이번 갱신에서는 아래 기능을 구현하지 않는다. 현재 `dev`의 후속 작업 범위와 판정 기준만 확정한다.

### H — 대표 전투력과 선호 포지션 정합성

- 딜러/서포터 복수 역할 Character는 사용자가 선택한 `preferredRole`의 역할별 Build Snapshot 전투력을 내 계정의 대표 전투력으로 사용한다.
- 그룹의 Character·멤버 대표 전투력도 같은 선호 역할 값을 사용한다. 마지막으로 갱신된 역할의 값이 Character 단일 `combatPower`를 덮어써 대표 표시에 노출되는 경로를 추적해 제거한다.
- 파티 생성·신청·참가·참가 Character 변경은 현재처럼 사용자가 선택한 역할의 불변 Snapshot을 사용한다. 이 경로를 대표 표시 수정과 섞지 않는다.
- 선호 역할 Snapshot이 없거나 유효하지 않으면 임의로 반대 역할 전투력을 대표값으로 확정하지 않고, 기존 유효값/미확인 처리 순서를 별도 테스트로 고정한다.

### I — 내 계정 간격과 수동 전체 갱신

- 압축된 상단 기능 구역과 `메인 계정` 시작 구간 사이에 시각적 여백을 추가한다.
- `메인 계정` 제목 행 우측에 앱 시작 1회 갱신과 같은 대상 정책을 사용하는 수동 전체 갱신 버튼을 둔다. active 소유권·인증·원정대 소속·공통 사용 레벨(현재 1700)·나이스단 설정과 기존 Coordinator를 공유한다.
- 수동 갱신은 앱 수명당 1회만 허용하는 `runOnce()` 결과를 재사용하지 않고 별도 명령으로 실행하되, 자동/수동 실행이 겹치면 single-flight로 합친다.
- 수동 전체 갱신 버튼은 요청이 수락된 시점부터 1분 쿨타임을 적용하고 실행 중·쿨타임 중 연타를 막는다. 갱신 실패도 무제한 즉시 재요청을 허용하지 않는다.

### J — 그룹 초대코드 수명주기 복구

- 현재 코드 원문은 생성 세션의 ViewModel 메모리에만 있어 앱 재실행과 방장 위임 후 표시되지 않으며, 폐기 명령도 원문 재입력을 요구한다. 이는 현재 구현의 명시된 제약이므로 UI만 바꿔서는 해결되지 않는다.
- 새 방장이 앱을 다시 열어도 활성 코드를 조회·복사·관리할 수 있도록 leader 권한으로 읽을 수 있는 활성 코드 참조/원문 저장 위치와 Rules를 다시 설계한다. 일반 그룹 공개 문서에는 코드 원문을 노출하지 않는다.
- 폐기는 코드 입력창을 제거하고 `폐기하시겠습니까?` 확인 알림만 거친 뒤, 현재 그룹의 활성 코드 식별자를 Repository가 찾아 원자적으로 삭제하도록 변경한다.
- 방장 위임 직후 기존 코드의 관리 권한, 비방장 읽기 차단, 앱 재실행 복원, 폐기 후 재사용 불가를 자동·디바이스 테스트한다.

### K — 알림 정리와 방별 가입 신청 배지

- 레이드 현황 상단 알림 목록과 읽지 않음 수에서 `applicationSubmitted`(파티 가입 신청), `memberCharacterChanged`(참가 캐릭터 변경)를 제외한다. 서버 이벤트 기록 자체는 명령 감사·호환을 위해 유지하고 알림 Projection 후보에서 제외한다.
- 가입 신청이 대기 중인 내가 만든 방에는 레이드 현황 카드에 pending 건수가 들어간 red badge를 표시한다. 승인·거절·철회로 pending 수가 바뀌면 실시간 반영한다.
- feasibility 판정: 서버에는 이미 `recruitments/{recruitmentId}/applications`가 모집방에 연결되어 있고 `watchRecruitmentApplications(recruitmentId)` 읽기 경로가 있다. 따라서 신규 서버 필드나 쓰기 변경 없이 클라이언트 구현이 가능하다.
- 단, `ActiveRaidSummary` 자체에는 신청 건수가 없으므로 단순 UI 수정만으로 끝나지 않는다. 내가 만든 활성 방에 한정해 기존 application stream을 구독·집계하고, 방 제거/화면 dispose 시 구독을 해제하는 클라이언트 작업과 읽기 비용 검증이 필요하다. 서버 스키마·Rules·인덱스 변경이 실제로 요구되면 이 항목은 즉시 중단하고 재승인을 받는다.

포함:
- 후보 화면 prefetch, 명령 직전 `ensureFresh`, 그룹/파티 UI의 갱신 확인 다이얼로그 경로를 교류 흐름에서 제거

- 공통 사용 레벨 정책의 현재 값은 1700으로 두고 나이스단 판정과 앱 실행 갱신 대상 판정에서 공유한다. 기능별 숫자 하드 코딩은 제거한다.
- 내 레이드 현황 초기 로딩과 첫 렌더링이 끝난 뒤 갱신을 시작하고, 하단 탭 바 두 번째 `내 계정` 탭에 비차단 통신 중 인디케이터를 표시한다.
- 기존 Coordinator·나이스단 로컬 설정·역할별 Snapshot·서버 최소 Snapshot 동기화 자산은 재사용 여부를 다음 작업에서 최소 변경으로 결정
- 내 계정 첫 화면의 상시 사용하지 않는 인증·계정 등록 영역을 압축한다. API 토큰 등록 안내/버튼과 게임계정 인증 버튼을 한 줄의 작은 액션 영역으로 합치고, Character명 입력과 `계정 데이터 불러오기`를 한 줄로 배치한다. `부계정 추가`는 작은 보조 버튼 또는 축약 액션으로 바꿔 실제 Character 현황이 첫 화면의 중심이 되게 한다.
