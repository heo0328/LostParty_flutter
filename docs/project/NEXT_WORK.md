# NEXT WORK — 주차별 레이드 그룹 변경·공대장 승계

## 목표·기준

2026-10-30 사용자 승인 계획을 실행한다. 현재 `feature/group-backend-integration`을 유지한다. 제품 계약은 [그룹 제품 §9](../product/GROUP_PRODUCT_FLOW.md#9-그룹-레이드-생성), 주차별 기술 계약은 [모집37](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md#cycle-group-policy), 연결 책임은 [설계39](../backend-migration/39-group-flutter-integration-design.md)다.

일반→A 연결, A→B 교체, A→일반 연결 해제를 해당 주차 공대장이 수행한다. 일반은 연결 없음+전체 공개, 그룹은 한 그룹 연결+그룹 전용이다. C/N의 그룹·공개범위는 독립이며 제목 등 무관한 방 공통값까지 분리하지 않는다. 기존 참가·신청·배정·일정·예약·완료/기록을 보존한다. 탈퇴·직접 위임의 일반 전환/승계도 한 명령으로 원자 처리한다.

## 실제 상태·담당·다음 행동

**새 정책 확정 / Backend 신규 계약·구현 인계 대기 / Flutter 신규 기능 미연결**이다. 현행 Flutter5f024e53·Backend6dac5ab2/실행2602e459/DB0034는 방 공통 그룹·최초 연결 및 연결 유지 공개 전환이다. 이를 새 정책의 완료로 보지 않는다. 기존 기기 인수는 유지하되 과거 공개 왕복 시험을 새 정책의 인수로 사용하지 않는다.

| 순서 | 담당·작업 | 완료 조건 |

정확한 새 서버 계약 전 UI만 열거나 기존 API 순차 호출로 우회하지 않는다. Backend 담당자가 서버를 구현하고 Flutter는 게시된 고정 계약을 소비한다. 기존 상세 관리 진입점과 카드 형태는 유지한다.

- 공용 조회/저장 계약을 변경하는 최종 앱 연결 상태에서 전체 flutter test·flutter analyze·포맷·diff 검토. 문서 정정만 한 구간에는 기능 시험 반복 없음.

## 사용자 기기 인수 — 새 서버·앱 준비 후

| 조작 | 기대 결과 | 현재 상태 |
|---|---|---|
| 일반 생성 후 선택 주차 상세에서 A 선택 | 해당 주차만 A전용, 상세/모집/그룹 목록 갱신 | 연결 대기 |
| A→B 변경 | A 제거·B만 연결, 참가·신청/일정/예약/기록 보존 | 연결 대기 |
| 그룹→전체 공개 | 연결 해제·일반 전환, 그룹 배지/그룹 필터에서 제외 | 연결 대기 |
| 같은 그룹 후임이 있는 공대장 탈퇴 | 표시한 후임으로 승계·해당 주차 그룹 유지 | 연결 대기 |
| 같은 그룹 후임 없음·외부 참가자 존재 | 일반 전환·연결 해제·승계·탈퇴 한 번 처리 | 연결 대기 |
| 비그룹원에게 직접 위임 | 확인 후 해당 주차 일반 전환과 위임 한 번 처리 | 연결 대기 |
| 반대 주차/다음주 개방 비교 | 반대 주차 불변·신규 설정 상속·기존 N 덮어쓰기 없음 | 연결 대기 |
| 긴 그룹명·비그룹원 시점 배지 | 실제 주차의 이름·같은 참가자 소속 표시 일치 | 기존 제보 미해결·새 계약으로 확인 |

기기 설치/조작은 사용자 담당이다. 기존 로그인·인증·그룹 관리 전체 시험을 반복 요구하지 않는다. 새 계약 전 구계약 시험으로 그룹 완료를 판정하지 않는다. 비그룹원 제보·Penpot 대기는 미완료로 보존한다.
