## dev에서 분석 완료 — 다음 수정 순서

1. **기존 관리 진입 경로 누락 조사.** 사용자가 디자인 변경 뒤 원정대 이름 변경·활동 캐릭터 선택 등에 들어가는 버튼이 사라졌다고 보고했다. 기존 기능과 실제 Router/DI/callback/flag·로컬/회원 화면을 대조해 구현 존재와 사용자 접근 가능을 구분한다. 완료 문구만으로 동작 가능하다고 판단하지 않는다. 새 화면을 선제 신설하지 않고 기존 관리 기능을 우선 복구한다.
2. **인증 버튼 배치.** 내 계정 원정대 이름 라벨 바로 오른쪽에 현재의 절반 정도 크기로 둔다. 화면 오른쪽 끝 정렬이 아니다. 긴 이름은 버튼 영역을 유지하고 두 줄로 흐르게 한다. 정확한 기존 컴포넌트와 이름 길이 제한을 확인한다.
3. **새 기기 서버→로컬 회원 캐릭터 복원.** 로그인 전 구 기기 공용 목록에 다른 원정대 자료가 있는 사례다. 서버 회원 원정대/인증 상태는 실제 표시 확인됐다. 같은 회원의 캐릭터·활동 선택/역할 요약을 어떤 로컬 저장소에 언제 읽는지, 기본 flag와 주화면에 어떤 연결이 필요한지 확인한다. 서버 데이터 복원과 구 Firebase/기기 자료의 이관·이름 기반 병합은 구분하며 후자는 수행하지 않는다.

### 확인한 원인과 영향

- 기본 `BackendAccountLifecycle.configuredEnabled`는 `BACKEND_LIFECYCLE_READS_ENABLED` 미지정 시 false다. BackendApp는 이때 회원 runtime/MemberAccountPage를 만들지 않고 로그인해도 `MyAccountPage(basicOnly:true)`를 사용한다. 실제 사용자가 설치한 빌드의 define 값을 별도로 수집한 것은 아니며 코드 기본 경로/관찰 화면의 일치로 판단한다.
- `MyAccountPage._buildAccountSection`의 basicOnly 분기는 이름·아래 인증 버튼·기본 카드만 만들고 먼저 return한다. 아래에 남아 있는 로컬 계정 수정/캐릭터 관리 버튼은 도달하지 않는다. 서버 이름 수정은 기존 `/account/server-management`의 ‘수정’에 남아 있으나 주요 화면 접근성이 부족하다.
- `MemberAccountPage`에는 owned 원정대별 ‘캐릭터 관리’, Router에는 registrationId를 받는 관리 gateway가 구현되어 있다. runtime이 null인 기본 경로에서는 관리 Router도 기본 접근 안내로 돌아간다. 따라서 **활동 선택 기능 코드 존재와 현재 기본 빌드에서 사용 가능한 상태를 구분**한다. 현재 서버 표시명은 입력/쓰기 검증 모두 40자다.
- 로그인 회원의 복원도 같은 flag에 종속된다. `MemberAccountViewModel.refresh`→`runtime.loadMemberRoster`의 전체 canonical 조회·회원 캐시 기록→`restoreCharacterPersonalData`의 역할 요약/개인 설정 복원 경로가 존재한다. 기본 OFF는 서버 등록 GET만 기존 하단 목록에 표시하므로 구 기기 공용 캐릭터와 회원 서버 캐릭터가 주화면에서 교체되지 않는다. 구 기기 DB를 이름으로 병합할 문제가 아니다.

### 다음 구현 그룹 제안

1. 기존 회원 주목록/캐시 복원·관리 진입을 실제 로그인 흐름에 연결한다. 저장된 서버 요약/설정 복원과 키 준비 후 실행되는 provider 목록·상세 1회 검사를 구분해 설계하고, 단순 flag ON으로 자동 검사까지 무심코 활성화하지 않는다. 원정대별 이름 수정·활동/대표/표시 설정 진입을 기존 화면 재사용으로 복구한다.
2. 같은 화면의 원정대 헤더에서 이름 바로 오른쪽에 축소 인증 버튼을 배치한다. 버튼 영역 고정·이름 두 줄, 현재 owned에는 재인증 버튼을 제공하지 않는 정책을 보존한다.
3. 구 기기 자료가 있는 새 기기에서 서버 회원 캐릭터/저장된 설정 복원·다른 회원 격리·키 미등록/OFF 상세 제외를 확인한다. 상세 원본이 서버에 없는 경우 기존 정책대로 새 기기 로컬 상세 조회 전까지 원본 없음으로 표시한다.

현재는 **분석·후속 기록 완료**, 후속 기능 코드/flag 변경은 하지 않았다. 기존 표시/인증·소유/회원 격리·사용자 지정 순서·1700 자격·정밀한 저장/정렬을 회귀 보호한다. 추가 Backend 선행 작업이나 새 제품 결정은 현재 확인되지 않았다.
