## 다음 작업 그룹 — 레이드 목록 Character 필터·인원/자리 로컬 정렬

### 목표

진행 중·레이드 모집 목록에서 내 Character 필터와 참가 인원·남은 자리 기준 로컬 정렬을 서버 변경 없이 제공한다. 기존 목록·필터·모집·신청 흐름에 회귀가 없도록 `ai_rules.md`의 기존 기능 회귀 방지 게이트를 먼저 적용한다.

### 선행 확인

- `ACTIVITY_CHARACTER_AND_RAID_FILTER_CONTRACT.md` §14와 현재 목록 읽기·필터 저장 구현을 대조한다.
- 기존 그룹·레이드 필터 상태 보존과 무효 선택 정리 계약을 확인한다.

### 회귀 보호 목록

- 일반·그룹 모집 생성과 Character 선택
- 동일 레이드 다른 난이도 확정 점유 후보 차단
- 과거 1회성 미완료 종료 assignment가 남은 Character의 새 주차 모집 생성·신청
- 반복방의 현재 참가 점유 유지
- 주간 완료 Claim Character 차단
- 4인 1파티의 동일 딜러 직업 차단
- 8인 2파티에서 다른 파티에 배치 가능한 동일 딜러 직업 허용
- 승인 대기 신청, 즉시 가입, 승인 시 최종 구성 재검증
- 기존 레이드 목록·현황 필터 상태 보존

### 포함 범위

- 진행 중 내 Character 필터
- 진행 중/레이드 모집의 참가 인원·남은 자리 로컬 정렬
- 표적 테스트와 문서 정리

### 제외 범위

- Firestore 스키마·Rules·Indexes 변경
- 그룹 membership Build Snapshot
- Build 별칭·시너지 UI
- 서버 정렬·쿼리 변경

### 작업 순서

1. §14 계약과 현재 목록/필터 구현 대조
2. Character 필터 상태와 적용 지점 연결
3. 인원·자리 로컬 정렬 적용
4. 회귀 보호 목록을 테스트로 고정하고 화면 연결 확인

### 중단 조건

- 로컬 정렬만으로 계약의 표시 순서를 충족할 수 없는 경우
- 서버 필드 추가 없이는 남은 자리·인원을 판정할 수 없는 경우

위 조건이 확인되면 구현 범위를 넓히지 않고 변경량과 대안을 사용자에게 다시 제시한다.

### 완료 조건

- 진행 중 목록에서 내 Character 필터가 동작한다.
- 참가 인원·남은 자리 로컬 정렬이 계약과 일치한다.
- 기존 필터·모집·신청 흐름이 회귀하지 않는다.
- 자동 검증과 문서가 갱신된다.
- 완료 보고에서 신규 흐름, 보존된 기존 흐름, 남은 실기기 확인을 분리한다.
