# NEXT WORK — 완료·탈퇴 목록 복귀 기기 재확인

## 현재 상태 — 완료·탈퇴 성공 후 즉시 목록 복귀 수정 완료

feature/raid-recruitment-scheduling / a4fc3050 후속. 사용자 승인대로 주차 완료·나만 완료 후 탈퇴·이번주/모두 탈퇴·해산은 성공 확인 후 해당 확인창만 닫고 대상 주차의 레이드 현황 '참가 중'으로 복귀한다. 기록 화면 자동 진입은 없고 기록 탭의 명시 조회/일정 확인은 유지한다. 설계37 §37.82·BUG027/DEV_LOG, [Issue13 결과6417921502](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6417921502).

실제 ShellRoute의 하위 상세와 root showDialog에서 확인창 잔류를 재현했다. 원인은 하위 Navigator만 popUntil하던 종료 처리였다. 방/주차별 root PopupRoute 표식을 추가해 해당 확인창만 닫는다. 상세가 성공 key/room/실제target를1회 소비하며 주차 완료 식별도 추가했다. 성공 이벤트는 일반 재조회/읽기 전용 전환보다 먼저 처리하되 명시적 기록·다른 화면/주차·회원 변경·복원된 과거 성공은 자동 이동하지 않는다. 목록에는 return_command_key를 전달해 같은 주차의 캐시된 기록 탭에서 돌아와도 새 성공에만 참가 중을 선택한다. 이후 수동 탭 선택은 유지한다.

서버 ACK 검증/영속 저장·원본문/key/query·영향주차/승계·계정/목록/배지 갱신은 기존 경로를 재사용했다. 조회 실패가 성공을 취소하거나 쓰기를 다시 실행하지 않는다. 활성 참가가 남은 방을 로컬에서 지우지 않는다. 직접 영향258개 통과(목록 검증의 캐시 재사용 기대를 수정한 뒤 해당3개 재확인 포함), 직접 변경 범위 분석0·포맷/diffcheck/검토. Backend 변경은 없다.

## 다음 행동 — 사용자 기기 두 항목만 재확인

1. 공대장이 '나혼자 완료처리이후 탈퇴' 실행: 성공/승계 이후 확인창이 사라지고 해당 주차 참가 중 목록으로 즉시 복귀·갱신되는지 확인한다.
2. '주차 완료' 실행: 기록 화면을 거치지 않고 같은 목록으로 복귀하는지 확인한다. 기존에 기록 탭을 열어둔 경우에도 참가 중으로 돌아와야 한다.

이미 확인한 후보 제외·즉시 참가/수락/탈퇴·조율 대기/후보없음 안내·개인표 갱신/그래프·제안/수락·조기 자동확정(다음주 목18→수18)·1인 탈퇴/승계·주차 독립은 통과 보고로 유지한다. 6/10도 같은방 C/N1개 정책임을 사용자 확인했고 정책은 현행 유지한다. 기본 출발30분 전 기한 동작을 이번 조기확정 보고로 추가 통과 판정하지 않는다. 미확인 배너는 현재 재현할 요청이 없고 원요청 복구의 자동 검증이 있으므로 사용자 뜻대로 강제 기기 과제로 남기지 않는다. 과거 제보 원ACK동일키 자체가 입증됐다는 의미로 확대하지 않는다.

서버/API·DB/자료 변경·배포·dev/main 통합·웹소켓·BUG025·IF001·기록 UI 리디자인은 제외했다. 현재 코드·검증·문서를 같은 브랜치의 한 파트로 커밋/푸시한다. 기존 무관 dirty는 보존한다.
