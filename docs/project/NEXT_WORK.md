## 다음 파트 준비

참가 명령의 앱 재시작 복구 연결을 점검한다. A의 participation 저장영역은 존재하지만 기존 Controller 원명령은 메모리 보존이므로, 실제 신청/가입·변경·일정·완료/탈퇴/해산의 pending 소유/ACK/원키와 화면 복구를 조사해 필요한 연결 범위를 먼저 기록한다. 새 정책/구자료 마이그레이션으로 확대하지 않는다. 생성/문구 PUT의 기존 영속 복구는 유지한다.

이후 관련 앱/Backend 연결과 복구 범위를 확인해 정상회원·사용자 기기의 생성→가입→방내부→완료해체→C/N 테스트를 소수 항목씩 진행한다. 이번 일정 범위의 대조를 전체 앱 모든 화면의 시각 일치 완료로 확대하지 않는다. 서버 배포/DB/자료삭제·dev/main 통합은 현재 승인 범위가 아니다.
