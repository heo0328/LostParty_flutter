# NEXT WORK — 모집 브랜치의 실행 기준 정리와 실제 앱 연결 정정

## 직전 파트 — 일정 조율 설정·다음주 개방 연결 완료

기준c3c68d7e에서 일반 앱의 일정/관리 입력을 새 계약에 연결했다. 다음주 open/reopen은 단일 날짜·기본 출발·조율 설정을 직접 입력한 뒤 동일 config를 서명 context와 명령에 사용한다. 이번주 날짜 자동복사는 없다. 원주차 plan의 용량/기간만 입력 안내에 재사용하며 비어 있는 날짜를 서버시각으로 채우지 않는다.

일정 설정은 ON/OFF·추가인원·즉시확정 동의로 단순화했다. 출발 날짜/시각 변경은 기존 제안/수락 경로의 단일 선택 입력이며 동의 없이 저장하지 않는다. 조건 설정 PUT의 숙련도/전투력/가입방식은 그대로다. 그래프/인원비교·제안 전용 전체 화면은 다음 파트다.

검증: 최종 직접13파일425PASS(신규10 포함), 개방 입력 정밀도/기본기간 보완 뒤 직접10PASS 재확인·중복 합산 없음. 변경9Dart+신규시험 분석의 코드 문제0, 시험 경고2개 수정 후 해당 시험 분석0·포맷/diffcheck·리뷰. 최신조건 변경 POST0·동일 key/body 재전송·N만 갱신·취소 PUT0·단일날짜/시간제한·원정원·조율동의와 기존 생성/참가/완료해산/IF-001·기록을 보호했다. 실제 서버회원/기기 인수는 미확인이다. 상세 설계37 §37.71/DEV_LOG.

## 다음 파트 — 공대원 시간표·일정 제안/응답 화면

승인된 Penpot03/설계37 §37.63/65/67을 기준으로 개인표 공급/내 일정 갱신·전체미설정 안내, 공대원 전체 그래프/요일별 로컬 비교와 공대장 제안/공대원 수락을 실제 화면에 연결한다. 이번 파트는 기존 입력/명령 연결이며 텍스트 시간표 알럿이 최종 UX라는 뜻은 아니다. 방별 개인표 편집은 폐기하고 시간표 밖 직접 제안/수락은 유지한다. 다음 구현의 구체 범위/검증을 먼저 기록하되 이미 확정된 제품 기준을 다시 협의하지 않는다.

신청메모/저장문구·검색필터 등 유효 후속은 아래와 같다. 관련 전체 앱/Backend 준비 후 사용자 수동1~5구간 인수를 진행한다. 현재 섹션에서 서버/DB 배포·자료초기화·dev/main 통합은 하지 않았다.
