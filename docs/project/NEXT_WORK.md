# NEXT WORK — 레이드 모집 현재 구간 완료·차후 재착수 항목

## 현재 상태 — 모집 1차 구현·기기 인수 마감 / dev·main 통합

앱 구현 기준은 `cf75ea75`, 문서 기준은 `bd3b6e58`와 이후 사용자 보류 정정이다. `feature/raid-recruitment-scheduling`의 일반 앱 연결과 보고된 정상 흐름 기기 확인을 마쳤다. 상세 인수표는 [설계37](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md#recruitment-status-20261027)에 모았다. 완료된 기능을 다시 대기로 두거나 추가 전체 기기 시험을 요구하지 않는다.

2026-10-27 사용자가 최신 모집 브랜치의 dev/main 병합을 명시 지시했다. 최신 origin/dev·origin/main을 확인하고 현재 작업 브랜치→dev 일반 merge→main 순서로 이력을 보존해 통합한다. 통합 코드 tree가 기기 확인된 원브랜치와 같고 충돌/코드 변경이 없으면 기존 직접 자동검증과 사용자 인수를 재사용한다. 문서 diff/참조·조상관계·tree·local/origin 동일 SHA를 확인한다. 무관 미커밋 문서/생성파일·미추적 자료는 통합 대상에서 제외하고 임시 보관 후 복원한다. 기존 작업 브랜치는 삭제하지 않는다.

[Issue13 최신 인수 회신](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6437933418)·[사용자 보류 정정](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6437976324)을 유지한다. Backend는 [사용자 승인 마감](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6438046779)으로 Issue13을 completed 종료했다. 현재 신규 서버 작업 대기는 없고, 차후 API/UX 범위가 생기면 해당 구간에서 별도 협의한다.

이번 통합은 Git 반영이다. 새 release/tag·빌드 배포·서버/DB·개발자료 삭제를 실행하지 않는다. 아래 보완/개선은 현재 실행하거나 완료로 바꾸지 않으며 별도 재착수 대상으로 보관한다.

## 차후 보완 — 제안의 시간 정밀도 판정 1건 (현재 착수 안 함)

- 근거: Backend는 실제 대상 `BetaSchedule.session_id`를 기준으로 분 단위 출발을 허용한다. 현재 Native `cycle_schedule.dart`의 제출 검증과 `schedule_command_page.dart`의 입력/정책은 `plan.betaData != null`만으로 정밀도를 구분한다.
- 착수 조건: 사용자가 차후 네이티브 보완 구간을 다시 시작할 때 최신 계약·코드를 대조한 뒤 실제 대상 세션 판정을 보완한다. 현재 작업/다음 즉시 작업/현재 베타 인수의 선행 조건으로 두지 않는다. 미수정 기록은 유지하되 지금 설계·구현·추가 시험을 시작하지 않는다.
- 보호/완료: 사용자가 통과한 일반 비5분 제안·수락/확정, 개인 시간표·자동 탐색/진행시간의 5분, 원요청/ACK/복구를 유지한다. 불일치·값 없음·대상 변경 등 직접 경계를 자동 검증하고, 실제 정상 UX에 영향이 있을 때만 좁은 기기 확인을 안내한다. 지금 전체 모집 재시험은 요구하지 않는다.

## 생성 관련 잔여 확인·미채택 확장

동시(묶음) 레이드 생성은 앱 공통 일행 최대4명(딜러3·서포터1)으로 구현 완료이며 미작업에 포함하지 않는다. 초기 완료/미정 기록은 [DEV_LOG](DEV_LOG.md#recruitment-document-reconciliation-20261028)로 이관했다.

- 과거 제보·현재 재현 미확인: 내 계정 변경 후 생성 화면 복귀 시 캐릭터 후보 최신화. Flutter가 현행 조회/수명·갱신 연결을 조사하고 재현 여부부터 판별한다. 이번 문서 정리로 수정 완료나 추가 필수 기기 시험으로 바꾸지 않는다.
- 미채택 확장: 기존 생성방 병합, 레이드별 캐릭터 교체·부분 참가. 사용자 결정과 별도 설계 후 착수한다.
- 항목별 담당·다음 행동·완료 조건은 [생성 후속 대장](../product/DETAIL_IMPROVEMENTS.md#모집-생성--남은-확인과-확장-후보)에 둔다. 다일/미정 생성은 제품 제외 상태를 유지한다.
