# NEXT WORK — 2주 레이드 현황 계약 보완과 구현 준비

기준: 2026-10-21. `feature/raid-recruitment-scheduling`을 재사용한다. 이번 사용자 승인은 **2주차 기획 재점검·문서 최신화·커밋/작업 브랜치 푸시**다. 새 기능 구현·서버/DB 변경·배포는 포함하지 않는다. 진행 중인 기능 브랜치의 복구 지점이며 dev/main 통합 완료가 아니다.

## 1. 현재 상태와 단일 기준

- 제품 계약: [설계37 현재 기준·§36](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md). §36.7의 기존 참가자 바로 참가/충돌 복구, §36.9의 주차별 공대장 정책이 우선한다.
- 사용자 흐름 지도: [핵심 사용자 흐름](../feature-definitions/LOSTPARTY_CORE_USER_FLOW_OVERVIEW.md). 구현 여부는 기획 채택과 구분한다.
- 현재 커밋 기반은4198f1a(개인표6ecb81d·계정UI4198f1a 포함), 로컬/원격dev는6d3f617이다. 모집 생성/기본 상세·시간 제한·입장 정책 복구 코드는 기존 미커밋 작업으로 남아 있다. 이번 문서 커밋에 임의 포함하지 않는다. 플랫폼 생성파일/DevTools/백업/tools와 통계35의 별도 미커밋 검토도 보존한다.
- 실제 Router는 모집 생성/상세의 v1 어댑터를 사용하고 목록은 Pending이다. **2주차 선택·주차별 공대장·다음주 참가 기능은 미구현**이다. 저장될 문서만 보고 실행 API가 준비됐다고 판단하지 않는다.

## 3. 다음 행동 — Backend 계약 보완 수신

최신 확인은 [Backend73 설계1판6296309772](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6296309772), [Flutter 검토6296514170](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6296514170), [주차별 공대장 정정6297004407](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6297004407)이다. 2026-10-21 이번 점검에서도 최신 댓글은6297004407이다. 새 회신이 없는 상태를 반복 댓글로 게시하지 않는다.

Backend 담당 대기:

1. T별 책임자/권한·revision과 N 개방+최초 공대장 참가의 원자 계약. 충돌 대체 선택·이미 열린 N 재전송 멱등.
2. N 탈퇴/참가 순서 자동 승계·직접 위임의 context/후보/CAS/동시성. 마지막1인 N 종료·보존/재개·한도 회복의 정확한 영향표.
3. 주차별 공대장이 달라질 때 전역 제목/공개범위/그룹/해산 관리권. N 위임으로 C 권한을 덮지 않음.
4. 기존 C 완료/미완료종료/좌석 취소에 따른 특례 자격, 충돌 B방 제목의 권한 내 출처, 실제 참가와 일정 확인/예약 분리.
5. core JSON 밖의 생성/검색/상세/신청/일정/관리 전체 DTO·OpenAPI·v1 호환/이행·성능 근거. /v2 분리는 기술 제안이며 최종 실행 계약 아님.

제품 미정: 이후 매주 새 N 자동 개방 여부, 마지막1인 종료 세부·공통 자원 권한, 사전참가 후 주차 시작 전 취소 통계(#19). 확정된 주차별 승계/위임이나 수10시 완료 정책을 다시 미정으로 돌리지 않는다.
