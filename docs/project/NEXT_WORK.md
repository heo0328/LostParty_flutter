# NEXT WORK — 레이드 모집 그룹 연결·표시 디바이스 인수

## 현재 작업·기준

현재 브랜치 feature/group-backend-integration을 유지한다. 기존 그룹 잔여 기능은 사용자 전체 정상 보고로 인수했다. 이번 범위는 생성 그룹 선택→그룹 전용 기본값, 일반 모집의 최초 그룹 연결, 카드 서버 그룹명, 비그룹원의 참가자 소속 표시 네 항목이다. 기존 통과를 반복 시험 조건으로 되돌리지 않는다.

생성은 기존 생성 API 한 번, 생성 후 사용자의 명시적 최초 연결은 기존 공통설정 API 한 번으로 연결+공개범위를 원자 처리한다. 사전 조회/검토와 동일 원본문·키 복구는 별개다. [공통 단일 명령 원칙](ai_rules.md#6-architecture-principles), [그룹 제품 §9](../product/GROUP_PRODUCT_FLOW.md), [모집37](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md), [연결39](../backend-migration/39-group-flutter-integration-design.md)를 따른다. A→B 교체/연결해제·방복제·이중 원장은 제외한다.

## 다음 행동 — 사용자 디바이스 테스트 순서

대상 앱은5f024e53(생성 기본값9d1baa39 포함) 또는 이를 포함한 후속 문서 커밋으로 빌드한 앱이다. 사용자가 설치·조작한다. 서버는 위 반영 인계 기준이며 새 배포를 실행하는 단계가 아니다. 기존 그룹에 속한 회원과 해당 그룹 밖 회원으로 같은 모집을 비교한다. 최초 연결은 공통설정 권한이 유효한 공대장으로 진행하며 그룹장 지위만으로 권한을 가정하지 않는다.

| 순서 | 조작 | 기대 결과 | 결과 |
|---|---|---|---|
| 1 | 생성에서 그룹 선택. 필요하면 전체 공개를 명시 선택해 생성 | 선택 직후 그룹 전용이 기본값. 명시 전체 공개로 바꿔도 연결 그룹은 유지 | 미실시 |
| 2 | 그룹 없이 생성한 방→상세→공통설정→내 그룹 선택→선택 그룹·영향 주차 확인→저장 | 최초 그룹 연결과 그룹 전용 전환이 함께 반영되고 상세·모집 목록·그룹 레이드 목록이 갱신 | 미실시 |

결과는 이 표를 통과/실패/미확인으로 갱신한다. 실패하면 해당 순서·계정의 그룹 소속·기대/실제 결과를 기준으로 원인을 좁혀 순차 수정하고 영향 구간만 재확인한다. 아직 테스트 결과 보고가 없으므로 통과로 기록하지 않는다. 사용자 결과는 DEV_LOG와 필요한 기존 Issue12/16에 회신한다. 기존 로그인·인증 및 이미 통과한 그룹 정상시험은 반복하지 않는다.

기기 확인 후 남은 차이를 해소하고, Penpot 도구 제공 시 기존03 섹션/흐름 설명을 실제 화면에 맞춰 갱신·시각 검수한다. 기기 인수와 디자인 검수 모두 끝나기 전에는 전체 완료나02 이관으로 판정하지 않는다.

## 보호·검증·완료

원본문/멱등키·과거 ACK/새membership·성공 후 조회실패·회원/환경/늦은응답, 기존 C/N 참가/신청/배정/일정/예약/완료를 보존한다. 실패한 연결에 부분 상태가 남지 않아야 한다. 그룹 선택/공통설정 성공 뒤 목록·상세·필터/context·그룹 레이드 자료를 갱신한다.

자동시험은 최초 연결 동시성/현재 권한·revision·원자성, 응답 유실·원ACK, 조회자별 같은 소속 표시·그룹명/null 경계에 집중한다. Flutter 구현 검증은5f024e53에서 전체 시험2,707PASS·전체 분석 오류/경고0(기존 미추적 도구 info3)·포맷/diff검토를 완료했다. 코드가 바뀌지 않은 이번 문서 정리에서는 반복 실행하지 않는다. 기기는 변경된 생성 기본값·일반 방 최초 연결·공개 왕복·비그룹원 배지·카드 긴 이름만 확인한다. 기존 로그인/인증·그룹 정상시험은 반복하지 않는다.

공통 단일 명령 원칙과 기존 사용자 인수 기록은9d1baa39에 보관했다. 이번 코드·시험·관련 문서는5f024e53으로 보관·푸시했다. 통계35와 기존 미추적 사용자 자료는 보존한다. 소분류 보관은 작업 브랜치 local/origin 일치로 판단하고 전체 완료/서버 반영/기기 인수와 구분한다.

## 다른 작업 탭 인계 — 베타 전 기술 진단·개선 순서

사용자는 종합 개선 작업을 다른 탭에서 이어갈 수 있도록 기록·커밋·푸시를 요청했다. 다음 탭은 AGENTS의 필수 진입 순서 후 [기술 진단·개선 인계](../product/DETAIL_IMPROVEMENTS.md#technical-review-handoff)를 읽고 두 저장소 최신 기준 커밋·구조·기존 진단 근거부터 확인한다. 첫 행동은 미확인 후보의 근거 재확인과 우선순위/작업 그룹 확정이며, 이 인계만으로 전면 리팩터링이나 모든 개선의 일괄 구현을 시작하지 않는다. 이번 턴은 문서 인계만 수행한다.

공통 문서 운영은 양측 반영·상호 대조 완료로 대기가 해소됐다. 근거는 DEV_LOG의 Issue29 완료 이력이다. 기존 그룹 기기 순서1~5와 Penpot 대기는 별도 미완료로 유지하며 진단을 시작하기 위한 재시험 조건으로 삼지 않는다. 다음 탭에서 실제 구현 그룹이 확정되면 이 실행 항목을 해당 목표·범위·보호 흐름·완료 조건으로 교체한다. 동일 작업 트리를 다른 탭과 동시에 수정하지 않도록 최신 Git 상태와 작업 소유를 먼저 확인한다.
