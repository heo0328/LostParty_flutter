## 1. 복구키를 통한 기존 앱 사용자 복구 — 설계 필요

### 목적과 현재 합의

같은 사람의 앱 재설치·데이터 삭제·기기 변경을 해결한다. 새 익명 로그인에서 복구키를 검증한 뒤
기존 앱 사용자(Player)에 다시 연결하여 현재 유효한 원정대·그룹·레이드 관계를 사용한다.
현재 authBindings의 Auth UID→playerId 구조를 활용하는 방향이며, Firebase 익명 계정 자체 이전과 구분한다.

복구 시 원정대를 무조건 미인증으로 만들지 않고 서버의 현재 인증·소유권 상태를 따른다.
이미 다른 사용자에게 넘어간 원정대는 이전 복구키로 소유권을 되돌릴 수 없어야 한다.

### 구현 전에 결정할 사항

복구키 발급·저장·검증·재발급·폐기와 유출/분실 처리, 신뢰된 서버 검증 방식,

원정대 인증만으로 기존 Player 전체를 복구하는 방식은 채택하지 않는다.
