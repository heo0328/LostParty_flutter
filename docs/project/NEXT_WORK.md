# NEXT WORK — 그룹 초대 검색 결과 안내 설계

## 현재 작업 — 검색 결과 없음 안내 (2026-11-02)

사용자가 기획·설계 착수를 지시했다. 이번 파트는 조사와 문서 설계까지이며 기능 코드는 수정하지 않는다. 작업 브랜치는 `fix/group-invite-search-feedback`이며, 이 대단원의 종료 조건은 확정 문구의 빈 결과 안내 구현·직접 경계 검증·필요한 사용자 화면 확인이다. 구현은 후속 지시에서 진행한다.

### 근거·데이터 흐름

- 일반 경로: BackendApp의 그룹 초대 Router → BackendGroupPage → BackendGroupViewModel.searchInvites → GroupRepository.get → GET /v1/groups/{group_id}/invite-candidates (`character_name` trim, `reader_profile=group-display-1`) → 계약 검증 → inviteCandidates → 후보 카드다. 검색은 서버 저장자료 조회이며 클라이언트에서 Lost Ark API를 호출하지 않는다.
- 현재 searchInvites는 성공 시 후보 목록만 대입하고 빈 결과 안내 상태를 설정하지 않는다. invite 화면도 후보 카드 반복만 렌더링하므로 정상 빈 응답에 안내가 없다. 사용자 운영서버 제보를 설명하는 코드 경로이며 당시 실제 응답·네트워크 오류를 재현 확인한 것은 아니다.
- 검색 결과는 해당 화면·검색 세대·회원/환경에 속하는 일시 상태다. 영속 저장·회원 존재 원장·초대 권한으로 사용하지 않는다. 초대 쓰기의 대상 UUID/revision·서버 권한·원자성·멱등 처리는 변경하지 않는다.
- [Issue12 최신 마감](https://github.com/heo0328/lostparty-backend/issues/12#issuecomment-6553673419)을 확인했다. 기존 그룹 연결·인수는 완료이며 현재 새 Backend 변경/재시험 요청은 없다. 이 수정은 Flutter 빈 결과 표시로 한정하고 서버 계약 차이가 확인될 때만 별도 협의한다.

### 확정 UX·상태 설계

| 상태/행동 | 표시·처리 |
|---|---|
| 초기 진입·검색 전 | 결과 없음 안내를 표시하지 않는다. 기존 입력·검색 버튼을 유지한다. |
| 검색 진행 | 기존 busy·중복 방지 유지. 이전 후보와 빈 결과 상태를 지운다. |
| 유효 성공 응답·0건 | 검색 버튼 아래 기존 후보 결과 영역에 `앱 사용 회원의 캐릭터명이 아닙니다.`를 표시한다. 화면 이동·확인 알럿·추가 버튼은 만들지 않는다. |
| 유효 성공 응답·1건 이상 | 기존 후보 카드·선택·초대 확인/전송을 유지하고 빈 결과 안내를 표시하지 않는다. |
| 통신·인증·권한·형식 실패 | 기존 실패 안내를 유지하고 회원 아님으로 바꾸지 않는다. 빈 입력/잘못된 입력도 정상 빈 결과로 취급하지 않는다. |
| 입력 변경·화면 재조회/복귀·회원/환경 변경 | 후보 무효화와 함께 검색 완료/빈 결과 상태를 초기화한다. 이전 검색 문구를 새 입력에 남기지 않는다. |
| 입력 무효화·회원/환경 전환 뒤 늦은 성공/실패 | 기존 _inviteEpoch/readScope/observation/dispose 경계로 폐기하며 빈 안내도 되살리지 않는다. |

후보가 비었다는 사실만으로 미검색·실패와 구분할 수 없으므로 VM에 검색 완료 여부의 최소 상태를 둔다. 별도 오류를 합성하거나 공용 notice를 재사용해 입력 변경 뒤 안내가 남는 방식은 피한다. 기존 clearInviteCandidates 경로에서 함께 초기화하고 현재 검색의 유효 성공에서만 완료 상태를 확정한다. 페이지는 그 상태·빈 목록·실패 없음에 맞춰 결과 영역을 표시한다. 서버 검색 자격/일치 규칙은 바꾸지 않으며 이 안내로 게임 내 캐릭터의 존재 여부를 판정하지 않는다.

### 포함·제외·구현 순서

1. VM의 최소 검색 완료 상태와 초기화/유효 응답 반영을 수정한다.
2. 기존 invite 결과 영역에 확정 문구를 연결한다. 입력·후보 카드 배치·초대 단계는 보존한다.
3. 기존 직접 경계 시험을 보강하고 포맷·diff 검토·분석 후 사용자에게 변경 화면 확인 항목을 전달한다.

포함 파일은 backend_group_view_model.dart·backend_group_page.dart와 관련 직접 시험이다. Lost Ark API 조회·서버/DB/DTO 변경·검색 자격 확대·초대 명령 변경·전체 오류 UX 정비·Penpot 수정·릴리즈/배포·dev/main 통합은 제외한다.

### 회귀 보호·완료 조건

- 기존 정확 이름 trim/profile 검증, 양성 후보 표시·초대 명령, 검색 연타 방지, 새 검색/실패 시 과거 후보 제거를 보존한다.
- 자동 검증은 test/features/group/backend_group_test.dart의 검색 수명 시험을 확장해 초기/정상 빈 성공/양성 성공/실패, 입력 초기화·회원전환 후 늦은 빈 응답의 상태를 구분한다. 정상 화면 문구의 별도 자동 UI 시험은 기본으로 추가하지 않는다.
- 구현 후 표적 시험과 변경 Dart 분석·포맷·git diff --check를 수행한다. 공용 Router/DI·저장 계약을 바꾸지 않으므로 전체 Flutter 시험 반복은 기본 조건으로 두지 않는다. 현재는 모두 실행 전이다.
- 사용자 확인은 실제 앱에서 미등록 이름 검색 시 문구 표시, 입력 수정 시 이전 안내 제거에 한정한다. 양성 회원 자료가 없는 운영환경에 테스트 회원 추가나 기존 정상 초대 전체 재인수를 요구하지 않는다. 통신 실패·늦은 응답 구분은 자동 경계로 보완한다.
- 설계 파트 완료는 코드 근거·범위·상태/검증 기준 문서화와 문서 diff 검토다. 구현 완료·운영서버 원인 재현·기기 인수로 확대하지 않는다.

## MCP 재개 원칙

이번 두 번의30초 응답 시간 초과는 실제 연결 단절로 확정할 근거가 아니었고, 재조회에서 변경이 완료된 것을 확인했다. 한 명령을 화면/섹션 단위로 분할한다. 시간 초과 뒤에는 읽기로 반영 상태를 확인해 중복 실행/생성을 피한다. 실제 연결 단절·읽기 불능이 확인되면 중단하고 사용자에게 재연결 확인을 요청한다. Chrome 직접 제어로 전환하지 않는다.
