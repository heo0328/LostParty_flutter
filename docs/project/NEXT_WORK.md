# NEXT WORK — 로그인·세션 인수 검증과 테스트 전환

갱신: 2026-10-14. 기획 브랜치: `feature/google-login`. 사용자 요청으로 기존 구현·기획을 dev에 통합한다. 다음 실행 시 현재/기존 목적 브랜치 상태를 다시 확인한다.
상태: 기획 완료, 실행 대기. 이번 요청에서는 문서만 작성하며 코드·테스트·CI를 변경하지 않는다.

## 1. 목표와 확정 결정

다음 단일 작업 그룹은 **로그인·세션 인수 검증과 Firebase 테스트 정리**다. 신규 인증의 유지·종료 경계를 확인하고, 현재 제품과 신규 서버를 검증하는 테스트 기준을 정리하면 종료한다.

- Firebase를 폐기하고 FastAPI/PostgreSQL을 빈 데이터로 시작한다는 결정은 확정됐다. 과거 사용자·서버 데이터·테스터 데이터는 이관하지 않는다.
- Firebase 전용 테스트는 활성 저장소에서 제거하고 Git 이력에 보존한다. 테스트를 `legacy/`로 이동하거나 일괄 skip하는 방식을 기본으로 사용하지 않는다.
- 계속 유효한 로컬 기능·제품 정책 테스트는 유지한다. Firebase 구현에 묶여 있는 유효한 정책은 구현 의존성을 분리하거나 신규 계약에 맞게 이식한다.
- 신규 API의 서버 권한·원자성 검증은 Backend 저장소가 소유한다. Flutter는 HTTP 계약 소비·세션·저장·화면 연결 경계를 검증한다.
- 이전 서버 데이터 폐기와 기기의 로컬 캐릭터·빌드·설정 삭제는 다르다. 로컬 원본은 보존하며 과거 ID를 신규 회원 소유권으로 인정하지 않는다.

정책 기준: [Google 로그인 계약](../architecture/GOOGLE_LOGIN_CONTRACT.md), [빈 데이터 신규 서버 결정](../backend-migration/09-migration-decisions.md). 완료 이력과 이전 검증은 [DEV_LOG](DEV_LOG.md)를 따른다.

## 2. 현재 근거와 회귀 보호

- 새 진입점은 BackendApp이며 Firebase 초기화·익명 로그인 대신 로컬 기능과 신규 인증을 연결한다. 기존 MyApp/Router·Firebase 구현 소스가 남아 있어 프로젝트에서 Firebase 제거가 완료된 상태는 아니다.
- 사용자가 에뮬레이터 Google 로그인 성공을 확인했다. 실제 계약 커밋/OpenAPI 고정, 유지 선택별 재실행·만료·로그아웃 인수는 남아 있다. Backend 로컬 구현과 원격 저장소 상태를 동일하게 취급하지 않는다.
- 로그인 화면 복귀 및 로딩 배경 연결을 수정했다. 배경·Glow·별 반짝임 유지, 중앙 Shine 제거는 자동 검증됐고 최신 빌드의 사용자 확인은 남아 있다.
- `test/`의 `*_test.dart` 파일은 조사 시점 218개다. Firebase 직접 참조 검색은 후보 추출이며 삭제 목록이나 최종 분류가 아니다.
- `.github/workflows/party-group-cutover-rules.yml`, `party-join-v3-proof.yml`, `party-scalability-proof.yml` 등 Firestore 검증 실행 경로도 분류한다. Android release workflow는 별도로 검토하여 관련 없는 빌드·서명·배포 흐름을 보호한다.
- 이전 전체 테스트에서 기존 기준과 같은 109개 실패를 확인했다. 이후 화면·로딩 수정은 표적 검증만 실행했다. 현재 전체 통과로 보고하지 않으며 실패 자체를 제거 근거로 사용하지 않는다.
- 전체 분석에는 과거 `coverage/` 실험 사본 문제 등이 있었다. 활성 소스 결함과 생성물 문제를 구분하여 기록하고, 제외 설정으로 활성 결함을 감추지 않는다.

보호 목록: 비로그인 로컬 계정·캐릭터·빌드·설정, 로그인 강제 없는 진입, 보호 기능 알럿, 로그인 후 원래 화면 복귀와 쓰기 자동 제출 없음, 로컬 데이터 보존, 계정별 세션 격리, 기존 로딩 배경, debug URL 선택 및 release HTTPS 경계.

공개 모집·그룹·원정대 본 API는 아직 후속 계약 대상이다. 준비 안내가 있는 화면과 실제 서버 기능이 구현된 화면을 구분해 인수한다.

## 3. 포함·제외 범위

포함: 인증 계약 대조, 로그인·세션 인수 체크리스트, 테스트 전수 분류, 관련 helper/fixture 및 CI 실행 경로 검토, Firebase 전용 테스트 제거, 필요한 공통 테스트 이식, 이번 인증 경계의 직접 결함 수정, 검증 결과·문서·Git 정리.

제외: 모집·그룹·원정대 API 신규 구현, 데이터 마이그레이션, 로컬 데이터 초기화, Firebase 콘솔·원격 데이터 삭제, SDK·플랫폼 설정·레거시 기능 소스 전체 제거, 운영 배포, 별도 리팩터링. Firebase 소스·의존성 최종 제거는 테스트 목록과 참조 조사 결과를 인계해 후속 작업으로 진행한다.

## 4. 테스트 분류 기준

| 분류 | 판단 기준 | 실행 시 처리 |
|---|---|---|
| 유지 | 현재 로컬 기능·제품 정책·신규 인증을 검증하며 폐기된 구현이 필요 없음 | 기존 테스트 유지, 중복 정상 UI 테스트 추가 최소화 |
| 이식 | 유효한 정책을 검증하지만 Firebase UID·DTO·Repository·Rules에 결합 | 정책/계약을 확인한 뒤 Flutter 또는 Backend에 필요한 경계 검증 연결 |
| 제거 | 익명 인증, Firestore Rules·경로·문자열·폐기 전용 mapper/adapter 등 사용 종료된 구현만 검증 | 추적 이력 확보 후 테스트와 전용 helper/fixture 제거, 호출 경로 함께 정리 |
| 판단 대기 | 현재 제품 적용 여부·Backend 계약·대체 검증 소유가 미확정 | 근거·담당·후속 작업 명시, 무조건 삭제/skip하지 않음 |

예비 후보: `anonymous_auth_initializer_test.dart`와 Rules 문자열 계약 테스트는 제거 검토 대상이다. `test/features/auth/`, 로컬 DB·빌드·카탈로그·Lost Ark API 테스트는 유지 검토 대상이다. AccountRepository·공용 Validator·Write Plan·기존 Router 테스트는 정책과 저장 구현을 분리해 판단한다. 파일 이름에 Firestore가 있거나 테스트가 실패한다는 이유만으로 제거하지 않는다.

실행 단계에서 파일별 분류 대장을 작성한다. 필수 칼럼은 `경로 / 검증 책임·현재 호출 여부 / 분류 / 판단 근거 / 유지·대체 테스트 위치와 소유 저장소 / 계약 의존성 / Git 보존 근거 / 처리·검증 상태`다. 혼합 파일은 테스트 케이스별로 분리한다. 모든 테스트 파일과 실행되는 Node/Rules 검증의 누락 여부를 확인한다.

## 5. 실행 순서

1. **시작 상태 고정:** 현재 브랜치·dirty 파일·local/origin 상태를 확인한다. 이미 작성된 인증 코드·테스트와 별도 Rules 실험/백업의 소유를 구분한다. 추적되지 않은 파일은 Git 이력에 없으므로 임의 삭제하지 않는다. 제거 전 해당 원본이 커밋 이력에 있는지 확인하고 필요한 복구 지점을 남긴다.
2. **계약 대조:** 실제 실행 서버의 OpenAPI·오류 DTO·nonce 및 세션 수명을 합의된 6API와 비교하고 서버 revision 또는 문서 hash를 기록한다. Backend 로컬 미커밋 상태라면 그 사실과 재현 가능한 계약 근거를 함께 남긴다. 토큰·인증정보를 기록하지 않는다.
3. **분류 대장 작성:** 테스트·helper·fixture·CI·실행 스크립트를 조사하고 유지/이식/제거/판단 대기를 확정한다. 신규 서버에 남겨야 할 권한·동시성 정책은 대체 검증 위치 또는 후속 인계 항목을 기록한다.
4. **인증 경계 검증:** 기존 인증 자동 테스트를 근거로 부족한 핵심 경계만 보완한다. 갱신 single-flight, 동일 request ID의 제한 재전송, 저장 원자성, 늦은 응답 무효화, 계정·origin 격리를 확인한다. Backend 서명·nonce·재사용·만료 검증은 서버 측 증거로 확인한다.
5. **테스트 전환:** 확정된 Firebase 전용 테스트와 사용처 없는 전용 보조 파일을 제거한다. 유효한 혼합 테스트는 필요한 부분을 유지·이식한다. Firebase 검증만 실행하는 workflow/명령도 활성 검증 경로에서 정리하되 다른 빌드 job을 보존한다. 미추적 과거 실험·백업을 일괄 삭제하지 않는다.
6. **사용자 인수:** 아래 체크리스트를 전달한다. 사용자 기기 결과에서 발견된 직접 결함만 최소 수정한다. 신규 서버 기능 부재는 인증 결함과 구분한다.
7. **최종 검증·정리:** format·diff 확인, 표적 검증, 전환 후 전체 `flutter test`와 `flutter analyze`를 실행한다. 남은 실패·경고를 활성 결함/후속 계약/생성물별로 설명한다. 완료된 단위별 코드·테스트·문서를 함께 기록하고 프로젝트 Git 규칙에 따라 최종 dev 통합·push 상태를 확인한다.

## 6. 사용자 인수 체크리스트

사용자가 설치·조작한다. 서버 만료·폐기 조건이 필요하면 Backend에서 안전한 재현 방법을 준비하며 운영 데이터를 조작하지 않는다.

| 항목 | 기대 결과 | 현재 상태 |
|---|---|---|
| Google 로그인 | 서버 교환 완료 후 앱 로그인 성공 | 사용자 성공 확인 |
| 보호 기능·취소·복귀 | 알럿 취소 시 유지, Google 취소 시 오류 없음, 성공 시 복귀, 쓰기 자동 실행 없음 | 인수 대기 |
| 유지 해제 후 새 실행 | 비로그인, 로컬 데이터 유지 | 인수 대기 |
| 유지 선택 후 새 실행 | 저장 세션 확인·복원, origin 변경 시 다른 서버 credential 사용 없음 | 인수 대기 |
| 백그라운드·재진입 | 단순 화면 이동/일시 백그라운드로 로그아웃하지 않음 | 인수 대기 |
| 만료·정지·통신 장애 | 만료/폐기는 재인증, 일시 장애는 credential 즉시 삭제 없음 | 인수 대기 |
| 로그아웃·계정 전환 | 현재 세션 종료, 재실행 복원 없음, 로컬 데이터 유지, 이전 응답 섞임 없음 | 인수 대기 |
| 시작 화면·비로그인 회귀 | 배경/별 효과 유지·Shine 제거, debug URL 적용, 로컬 계정/빌드/설정 접근 | 최신 빌드 인수 대기 |

서버 응답 유실·재전송·동시 요청은 자동 경계 검증을 우선하며 정상 UI와 같은 자동 테스트를 관성적으로 추가하지 않는다.

## 7. 완료 조건과 인계

- 테스트·보조 파일·CI 실행 경로의 분류 대장과 변경 근거가 기록되고 폐기 테스트가 기본 검증에 실행되지 않는다.
- 유지/이식 테스트가 현재 계약을 검증한다. 서버로 옮겨야 할 중요 정책의 검증 책임·증거 또는 미완료 의존성이 명시된다. 테스트 수 감소만으로 품질 개선을 주장하지 않는다.
- 인증 인수 결과, 보존한 로컬 흐름, 미확인 기기·서버 항목, 실행 명령과 실패 원인이 기록된다. 알려진 활성 결함이나 미확인 필수 인수를 남긴 채 전체 완료로 선언하지 않는다.
- 전체 검증 실패를 skip/광범위 exclude로 덮지 않는다. 별도 작업이 필요하면 범위를 확장하지 않고 후속 작업과 완료 제한을 기록한다.
- 관련 문서 최신화, 최종 diff 검토와 Git 정리를 완료한다. 구간 종료는 dev/origin 동기화·깨끗한 작업 트리 기준이며 무관한 미커밋 변경이 있으면 소유/보존 상태를 별도 보고한다.
- 다음 인계 후보: Firebase 실행 코드·SDK·플랫폼 설정 최종 제거, 공개 모집 API 연결. 현재 그룹에서 함께 구현하지 않는다.
