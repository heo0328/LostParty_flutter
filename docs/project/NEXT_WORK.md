# NEXT WORK — 전체 빌드 자동 갱신 시작 순서 설계

2026-10-15. 회원 키 등록·복원·기기 저장과 호출 제한 UX 연결은 구현/자동 검증 및 현재 구간 사용자 정상 동작 보고를 마쳤다. 소비 Backend는 `9e1a255b87b430bca314e8f718fb4176bfe322c8`. 완료 내역은 [연결 계약25](../backend-migration/25-member-lostark-key-request.md)와 DEV_LOG에 보관한다. 같은 정상 흐름을 다시 인수 대기로 두지 않는다. 적용 커밋/통합은 Git 이력과 이슈7 최종 회신으로 추적한다.

## 다음 착수 범위 — 설계부터

회원 개인 키 선행 작업을 마쳤으므로 중단했던 전체 Armory 빌드 자동 갱신의 시작 순서 설계를 재개할 준비가 됐다. 이 문서는 다음 착수 기준이며 이번 Git 마무리에 자동 갱신 코드를 추가하지 않는다. [설계23](../backend-migration/23-nice-group-auto-refresh-design.md),[DB24](../backend-migration/24-database-design-review.md),[후속대장14](../backend-migration/14-my-account-flutter-integration-plan.md).

1. 현재 BackendApp의 인증·회원설정·원정대 전체 목록/캐릭터·키 metadata/restore 및 로컬 요약 조회 시작 흐름을 대조한다. 과거 3+N 요청 수는 회원 키 추가 전 관찰 기준이므로 현재 흐름으로 다시 산출한다. 앱 복귀·페이지 진입 시 재확인과 실제 외부 호출을 구분한다.
2. 회원/세션 확정 + 회원설정 GET 성공 + 전체 대상 roster 준비 + 해당 실행 경로에서 필요한 개인 키 준비를 선행 조건으로 둔다. 설정 미조회/실패를 OFF로 간주하거나 실행 1회를 소진하지 않는다.
3. 전체 등록 원정대에 나이스단 정책을 적용하고 서버 설정 true/false를 사용한다. 현재 OFF 기본값과 캐릭터 관리 화면의 즉시 서버 저장 UX를 유지한다. 회원/키/설정 버전 변경·로그아웃/늦은 결과·중복 실행 경계를 정리한다.
4. 실패/부분 성공·설정/키 준비 지연·호출 제한 뒤 명시 재시도와 실행 1회 처리 방식은 사용자와 기능 UX를 협의한다. 사용자 합의 전 구현하지 않는다. 전체 빌드/역할 Snapshot 서버 저장이 필요한지는 현재 로컬 직접 조회 범위를 먼저 대조하고 필요한 Backend 변경만 새 Issue로 요청한다.
5. 설계·포함/제외·회귀 보호·최소 검증과 완료 조건을 확정한 다음 구현 구간을 정한다. 기존 Google 세션/개인 키·원정대 관리/수동 전투력·회원설정 흐름을 재작성하지 않는다.

## 별도 후속·미확인 범위

- 전체 앱 사용자 안내 문구 점검: 사용자 요청으로 후속 보관. 이번에는 연결 화면의 문의 UUID 노출과 일부 개발 표현만 정리했다.
- 재설치/별도 디바이스·실provider 응답 헤더·운영 TLS는 조건별 추가 인수다. 사용자의 현재 기능 정상 보고를 이들 상세 통과로 확대하지 않으며, 이미 확인한 정상 기능 반복 시험/실제100회 소진/키 원문 제출을 요구하지 않는다.
- DB-03 로컬 삭제 정합성·회원별 전체 환경 복원·역할 저장/장비 인수 보류 해제/활동 대표 연결은 각 후속이다. Firebase/테스터 자료이관은 없다.
- Backend Issue7은 구현·자동/사용자 결과와 실제 Flutter 게시 SHA를 인계하며, 명시적 종료 지시 없이 닫지 않는다. Backend 추가 수정/반복 시험 요청은 현재 없다. Backend 작업브랜치 push/로컬0006·API 반영은 보고 기준이며 dev/main 통합은 Backend 소유다.
