# NEXT WORK — 자동 빌드 갱신 시작 순서 설계

2026-10-15. 사용자 순차 진행 지시의 첫 그룹인 시작 등록 목록 중복 조회 개선은 구현/검증 완료했다. 사용자 Git 지시에 따라 feature/account-backend-read를 커밋·dev에 일반 병합·push한다. 이 브랜치에 남은 구현/검증 항목은 없다. 다음은 별도 설계 그룹이며 자동 갱신 기능을 임의로 연결하지 않는다.

## 완료한 조회 구간

등록 패널과 전투력 표시 VM의 초기 목록 GET만 같은 회원/세션의 진행 Future로 공유한다. 명시 재조회와 쓰기 후 확인은 새 GET을 유지한다. 정상 단일 페이지·토큰 유효/오류 없음 기준 Backend 시작 요청은4+N에서3+N으로감소했다. 신규7개포함전체1227테스트·제품lib/test분석0/포맷·diffcheck완료. 이후코드불변으로같은검증/기기시험을반복하지않는다. Backend계약/DB/UI변경없음.

## 다음 설계 목표와 순서

1. 로그인 상태·회원/세션을 확정하고, 회원 설정 GET 성공과 전체 대상 원정대 준비를 기다린 뒤 나이스단/허용값을 판정한다. 미조회/실패는 OFF가 아니며 실행1회를 소진하지 않는다.
2. 앱 실행1회의 범위, 처음 비로그인에서 로그인한 경우·같은회원 재로그인·회원변경·탭 재진입/백그라운드 복귀를 정의한다. 해당 UX는 사용자와 협의한다.
3. 설정/원정대 조회 실패·도중 설정 변경·일부 빌드 실패의 표시와 재시도, 현재 화면을 막지 않는 실행 방식을 협의한다. 준비 실패와 실행 후 실패를 구분한다.
4. 전체Armory 수집 주체·회원 설정/원정대 기준·역할Snapshot 저장/표시·전투력cache의책임을확정한다. 현재로컬경로/옛소유ID·설정예외false fallback을그대로재연결하지않는다. 필요한서버계약만별도요청한다.
5. 설계/범위·Router/DI·상태전이와검증조건을문서에확정한뒤다음구현그룹을시작한다.
