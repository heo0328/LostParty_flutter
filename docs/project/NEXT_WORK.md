## 현재 상태 — 문서 최신화 / 정상 흐름 기기 인수 완료

현재 브랜치는 `feature/raid-recruitment-scheduling`, 앱 구현 기준은 `cf75ea75`다. 일반 앱 연결과 사용자가 보고한 모집 정상 흐름의 기기 확인을 마쳤다. 상세 인수표·협업 근거는 [설계37 현재 구현·인수 상태](../backend-migration/37-raid-scheduling-and-multi-raid-planning.md#recruitment-status-20261027)에 모은다. 완료된 생성·가입·일정·완료/탈퇴·주차별 관리·오류/시계 표시를 다시 대기로 두지 않는다.

이번 문서 파트는 이전 기기 확인 기록을 묶어 현재 상태·비활성 범위·유효 후속을 최신화한다. 기능 코드·API·권한·화면 배치는 수정하지 않는다. 문서 내용/참조·Git diff를 검토하고 같은 브랜치에 한 파트로 커밋·푸시한다. Flutter 시험/분석을 반복하지 않는다. 무관 미커밋 자료는 보존한다.

## 다음 코드 보완 — 제안의 시간 정밀도 판정 1건

- 근거: Backend는 실제 대상 `BetaSchedule.session_id`를 기준으로 분 단위 출발을 허용한다. 현재 Native `cycle_schedule.dart`의 제출 검증과 `schedule_command_page.dart`의 입력/정책은 `plan.betaData != null`만으로 정밀도를 구분한다.
- 다음 행동: 실제 대상 세션과 연결된 베타 일정인지 공통 판정으로 맞추는 최소 보완을 설계·구현한다. 이번 문서 최신화에서 코드를 변경하지 않는다.
- 보호/완료: 사용자가 통과한 일반 비5분 제안·수락/확정, 개인 시간표·자동 탐색/진행시간의 5분, 원요청/ACK/복구를 유지한다. 불일치·값 없음·대상 변경 등 직접 경계를 자동 검증하고, 실제 정상 UX에 영향이 있을 때만 좁은 기기 확인을 안내한다. 지금 전체 모집 재시험은 요구하지 않는다.
