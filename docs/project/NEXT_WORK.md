- 새로운 기능 작업은 아직 지정되지 않았다. 다음 작업을 임의로 시작하지 않는다.

## 다음 작업 시작 절차

1. git status, 현재 브랜치와 최근 커밋, 원격 main 상태를 확인한다. 미커밋 변경이 있다면 보존한다.
2. 사용자에게 지정받은 다음 단일 작업을 기준으로 포함·제외 범위와 완료 조건을 정한다.
3. 최신 main에서 별도 codex/ 작업 브랜치를 만들고 해당 범위만 구현한다.

과거 R0~R6 Rules 최적화·전체 재설계 대기 기록을 현재 작업으로 자동 재개하지 않는다. 그룹 전용 모집 등 후속 후보도 새 사용자 지시 없이 구현하지 않는다.

## 유지할 정상 기준

- 사용자 확인 기준 레이드 모집·탈퇴·완료 체크, 그룹 생성·초대·탈퇴·초대코드 생성·가입 및 Rules 배포는 정상이다.
- 이번 전투력 수정은 로컬 저장 세팅 fallback, 소유 Character별 서버 표시 전투력 보강, membership 숫자 보존, 동기화 실패 안내·중복 요청 차단을 포함한다.
- 소유자가 갱신된 앱에서 그룹을 열어야 로컬 전투력이 공유된다. 로컬 프로필/저장 세팅에 값이 없으면 임의로 만들어내거나 대표 전투력을 다른 캐릭터에 복사하지 않는다.
- 그룹원 간 전투력 정상 표시를 확인한 것이며, 개별 네트워크 실패·권한 실패·동시성 시나리오까지 모두 실기기 검증했다고 확대하지 않는다.
- 전투력 수정에서는 Rules·배포 설정·인덱스·레이드 코드를 바꾸지 않았다. 다만 main 병합에는 기반 계보의 기존 Rules 정리 25f88ff와 보존 사본도 포함된다. Git 병합과 Firebase 배포는 별개이며 이번에 배포는 하지 않는다.
- 409 원인은 동일 내용 중복으로 단정하지 않는다. 다음 실제 Rules 변경 시 재배포 결과를 확인한다.
