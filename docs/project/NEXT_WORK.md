### J — 그룹 초대코드 수명주기 복구

상태: 2026-09-05 구현·자동 검증 완료.

- 현재 코드 원문은 생성 세션의 ViewModel 메모리에만 있어 앱 재실행과 방장 위임 후 표시되지 않으며, 폐기 명령도 원문 재입력을 요구한다. 이는 현재 구현의 명시된 제약이므로 UI만 바꿔서는 해결되지 않는다.
- 초대코드는 민감한 인증 비밀이 아닌 단순한 그룹 가입 수단으로 취급한다. 신규 코드는 **6자리**로 생성해 전달하기 쉽게 하고 기존 20자리 활성 코드는 폐기 전까지 계속 허용한다.
- 새 방장이 앱을 다시 열어도 활성 코드를 조회·복사·관리할 수 있도록 현재 구조에서 가장 단순한 저장·조회 방식을 적용한다. 잘못 가입한 사용자는 추방하고 코드를 폐기·재생성할 수 있다는 제품 정책을 우선한다.
- 폐기는 코드 입력창을 제거하고 `폐기하시겠습니까?` 확인 알림만 거친 뒤, 현재 그룹의 활성 코드 식별자를 Repository가 찾아 원자적으로 삭제하도록 변경한다.
- 문자 집합은 전달 오류를 줄이기 위해 혼동되는 `0/O`, `1/I`를 제외한 영문 대문자와 숫자를 사용하고 충돌 시 다시 생성한다.
- 방장 위임 직후 기존 코드 표시, 앱 재실행 복원, 6자리 신규 생성, 기존 20자리 호환, 확인만으로 폐기, 폐기 후 가입 불가를 테스트한다.
- 그룹 문서의 선택 필드 `activeJoinCode`와 코드 문서를 한 Transaction에서 함께 생성·폐기하도록 Rules를 고정했다. J 표적 테스트 74개가 통과했다. 당시 남았던 해산 안내 문구 테스트 기대값을 통합 구간에서 현재 UX로 정정했고 전체 회귀에 포함해 통과했다.

### K — 알림 정리와 방별 가입 신청 배지

상태: 2026-09-05 구현·자동 검증 완료.

- 레이드 현황의 진행 중 카드별로 현재 사용자가 읽지 않은 `applicationSubmitted`(가입 신청), `memberKicked`(추방), `memberJoined`(참가), `memberCharacterChanged`(참가 Character 변경) 이벤트 수를 좌상단 숫자 red badge로 표시한다. 이는 pending 신청 건수가 아니라 **읽지 않은 이벤트 수**다.
- 사용자가 해당 모집방 상세에 진입하면 히스토리 팝업을 열지 않아도 그 방의 위 네 유형 이벤트를 모두 읽음 처리하고 카드 red badge를 제거한다.
- 모집 상세의 처음 보이는 `파티 구성` 제목 행 우측에 알림 아이콘을 둔다. 누르면 해당 모집방의 이벤트 히스토리를 팝업으로 보여주며 항목 터치 이동 동작은 제공하지 않는다.

- 팝업은 방 전체 감사 로그가 아니라 **현재 사용자에게 전달된 이벤트 히스토리**다. 기존 이벤트 생성·보관 방식은 바꾸지 않는다. 구현 중 서버 저장 규칙·스키마·인덱스 변경이 필요하다고 확인되면 히스토리 리스트업은 중단하고 별도 승인을 받는다.

## 확정 방향 (다음 구현의 단일 기준)

파티 모집·그룹 생성·가입·상세 등 **지금 걸어 둔 모든 교류 시점 자동 갱신 조건을 철회**한다. 자동 갱신은 **앱 실행 시 1회**로 정정한다.

포함:
- 후보 화면 prefetch, 명령 직전 `ensureFresh`, 그룹/파티 UI의 갱신 확인 다이얼로그 경로를 교류 흐름에서 제거

- 공통 사용 레벨 정책의 현재 값은 1700으로 두고 나이스단 판정과 앱 실행 갱신 대상 판정에서 공유한다. 기능별 숫자 하드 코딩은 제거한다.
- 내 레이드 현황 초기 로딩과 첫 렌더링이 끝난 뒤 갱신을 시작하고, 하단 탭 바 두 번째 `내 계정` 탭에 비차단 통신 중 인디케이터를 표시한다.
- 기존 Coordinator·나이스단 로컬 설정·역할별 Snapshot·서버 최소 Snapshot 동기화 자산은 재사용 여부를 다음 작업에서 최소 변경으로 결정
- 내 계정 첫 화면의 상시 사용하지 않는 인증·계정 등록 영역을 압축한다. API 토큰 등록 안내/버튼과 게임계정 인증 버튼을 한 줄의 작은 액션 영역으로 합치고, Character명 입력과 `계정 데이터 불러오기`를 한 줄로 배치한다. `부계정 추가`는 작은 보조 버튼 또는 축약 액션으로 바꿔 실제 Character 현황이 첫 화면의 중심이 되게 한다.

### H~K 통합 디바이스 체크리스트

상태: 결과 보류 — 실제 기기와 여러 사용자 계정으로 테스트해야 함.

1. 앱을 완전히 종료한 뒤 실행한다. 내 레이드 현황 첫 로딩·첫 렌더링을 방해하지 않고 이후 내 계정 탭 인디케이터가 표시되는지 확인한다.
2. 탭 이동과 백그라운드 복귀로 시작 갱신이 중복 실행되지 않는지 확인한다. 1700 미만·미인증·원정대 이탈 Character가 대상에서 제외되는지 확인한다.
3. 내 계정 상단 압축 UI의 360dp급 화면 오버플로와 기능 동작을 확인한다. 수동 갱신 확인 후 나이스단 제외 대상의 진행 수가 증가하고 완료 뒤 10초 빨간 카운트다운·확인 비활성·재활성화가 동작하는지 확인한다.
4. 딜러/서포터 복수 역할 Character에서 선호 역할을 각각 바꾸고, 반대 역할을 최근 갱신해도 내 계정과 그룹의 대표 전투력이 선호 역할 Snapshot을 유지하는지 확인한다. 파티 지원·모집은 선택한 역할 Snapshot을 유지해야 한다.
5. 신규 그룹 초대코드가 6자리로 생성되는지 확인한다. 앱 재실행과 그룹장 위임 뒤에도 같은 코드가 표시·복사되며, 코드 재입력 없이 확인만으로 폐기되고 폐기한 코드로 가입할 수 없는지 확인한다. 보유 중인 기존 20자리 코드가 있다면 가입 호환도 확인한다.
6. 가입 신청·추방·참가·참가 Character 변경을 서로 다른 계정에서 발생시킨다. 수신자의 진행 중 해당 방 카드 좌상단 숫자 배지가 정확히 증가하고 전역 알림 목록에는 네 유형이 나오지 않는지 확인한다.
7. 배지가 있는 방 상세에 진입하는 것만으로 읽음 처리되는지 확인한다. `파티 구성` 우측 알림 아이콘에서 현재 사용자에게 전달된 해당 방 이벤트만 시간순으로 보이고, 항목을 눌러도 이동하지 않는지 확인한다. 목록 복귀 시 해당 방 배지가 사라지고 다른 방 배지는 유지돼야 한다.
8. 바드·홀리나이트·발키리·도화가를 포함한 여러 실제 사용자 계정에서 역할·아이템 레벨·전투력·보석 표기를 최종 확인한다.

자동 테스트 통과만으로 직업별 실제 표기 검증 완료 처리하지 않는다.

### 2026-09-05 실기기 갱신·그룹 생성 장애 대응

- Android 실기기 2대에서 앱 시작 자동 갱신이 진행되지 않고 수동 갱신도 대상 전체가 실패하는 현상을 확인했다. 디바이스 테스트 결과는 더 이상 단순 보류가 아니라 **실패 확인 후 수정·재검증 대기** 상태다.
- 원인은 역할 판별과 직접 관계없는 보석 효과 분류 미확인 또는 아크 그리드 조건 미충족까지 갱신 전체 실패로 처리하던 Coordinator 검증 경계였다. 이 두 항목은 기존 Mapper 계약대로 경고로 보존하고 저장을 막지 않도록 정정한다.
- 지원하지 않는 직업, 역할 판별 불가·모호, 선택 역할과 일치하는 T4 노드 부재처럼 역할별 Snapshot을 확정할 수 없는 경우는 계속 실패 처리한다.
- 수동 갱신 완료 안내에는 실패한 Character명과 원인을 최대 3건 표시하고, 시작 자동 갱신의 Character별 실패 원인은 디버그 로그에 남겨 실계정 재검증 시 구분할 수 있게 한다.
- 그룹 생성의 `그룹 생성 권한을 확인하지 못했습니다` 오류는 신규 그룹 문서의 `activeJoinCode` 필드를 허용하는 저장소 Rules와 운영 배포본의 불일치 증상으로 판단한다. 최신 Firestore Rules를 `lost-party` 프로젝트에 배포한 뒤 재검증한다.
- 자동 회귀 896개 통과. 갱신과 그룹 생성은 수정본 설치 후 동일한 실기기 2대 및 여러 실제 계정으로 다시 테스트해야 하며, 재검증 전 완료로 기록하지 않는다.

H 대표 전투력, I 내 계정/수동 갱신, J 초대코드, K 방별 알림을 완료했다. 다음은 통합 자동 회귀 정리 → 디바이스·다양한 실계정 검증 순서다. 디바이스 테스트는 H~K 통합 체크리스트로 한 번에 진행한다.

## 검증 완료 기준

- 자동 테스트 통과는 코드 회귀와 실행 경계를 확인하는 조건이며 직업별 실제 표기 검증을 대신하지 않는다.
