# NEXT WORK — 레이드 모집 연결 후 기기 확인

## 현재 상태 — 즉시 참가 후보·조율 안내·활성방 배지 연결 완료

현재 feature/raid-recruitment-scheduling, 기반63afb3a7. Backend172 source1800160d·개발반영e4137073 및 join690f36f의 실행 계약을 일반 main→BackendApp→DI/Router 경로에 연결했다. Backend 구현/반영 대기는 해소됐다. [Flutter 구현 회신6414804154](https://github.com/heo0328/lostparty-backend/issues/13#issuecomment-6414804154), 상세 설계37 §37.81. 앱 연결·자동 검증 완료이며 실회원 기기 통과는 아직 아니다.

- 즉시 참가도 서버 후보 전페이지/역할 자격을 사용한다. 기존 캐릭터 자료는 원정대/대표/선호역할 표시에만 재사용하며 신청·변경과 같은 검증 기반을 쓴다. join의 메모 없음·버튼·성공/원요청 복구는 유지한다.
- 현재 상세·시간표 조회만 조율 대기 이유를 요청해 기존 카드에 표시한다. 안내를 일정 동일성/CAS/제안 자료에서 분리했다. 기록/반대주차 보조조회·목록·쓰기에는 선택 인자를 추가하지 않는다.
- 현황 탭 우상단의 사용량/한도는 서버 GET 원본이다. C/N 목록을 로컬 합산하지 않는다. 실패·미확인은 사용자 선택대로 —/—. 앱 소유 Controller가 로그인/진입·수동 갱신/복귀/본인 참가 집합 변경 ACK를 묶어 갱신하며 계정·환경·주차·늦은 응답을 격리한다. 그룹 배지는 이번에 구현하지 않았다.
- 검증: 모집/셸 고유1195개 통과(신규 합성자료 2건 수정 뒤 해당 묶음8개 재확인 포함), 복구/셸41개는 갱신 콜백 assertion 보강 후 통과. 직접 변경 범위 분석0·포맷·diffcheck/검토. 공용 영향이 모집/셸 범위로 설명되어 전체 앱 시험은 반복하지 않았다.

## 다음 행동 — 사용자 기기 소수 확인

1. 즉시 참가 방에서 입장 레벨 미달 캐릭터가 후보에 없는지 확인한다(기존 제보:4막하드1720 대비1704). 가능한 캐릭터로 실제 즉시 참가 후 메모/승인 대기 없이 해당 상세에 반영되는지 확인한다.
2. 조율 중 방의 상세·공대원 일정 전체 확인에서 인원 부족/더 이른 공통시간 없음 안내를 확인한다. 그래프 비교·일정 제안이 기존처럼 작동하는지도 함께 본다.
3. 현황 탭 배지와 이번주/다음주 실제 참가방 합집합이 맞는지 확인한다. 같은 방 양 주차는1개이며 한 주차만 탈퇴해 다른 주차가 남으면 유지, 양쪽 모두 종료하면 감소한다. 다른 기기 변경은 현황 진입/새로고침으로 확인한다. 제보 당시3/10을 현재 기대값으로 고정하지 않는다.
4. 기존 내 일정 갱신의 미확인 요청이 남았다면 원요청의 '같은 요청 다시 확인' 흐름으로 결과를 확인한다. 원자료/key를 삭제하거나 새 요청으로 대체하지 않는다. 잔여 일정/4완료·해체/5주차 독립 인수는 직접 영향과 함께 이어간다.

기기 빌드/설치/조작은 사용자 담당이다. 기존 통과한 생성·신청/승인·메모·직업중복/완료 제외·참가후 검색 제외를 무조건 재시험하지 않는다. 새 차이가 있을 때 대상 주차·화면·code/request_id로 원인을 좁힌다.

서버/DB 배포·개발자료 삭제/이전·dev/main 통합·웹소켓·BUG025·IF001·리디자인은 제외했다. 무관 dirty(통계35·플랫폼 생성물·devtools/백업/tools)는 보존한다. 현재 파트 코드·검증·문서를 한 커밋으로 작업 브랜치에 푸시하고 브랜치를 유지한다.
