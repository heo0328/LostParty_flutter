## 향후 Firebase 수동 알림 연결 원칙

- 모집 내용 변경이나 참가 캐릭터 변경만으로 전체 참가자에게 자동 푸시를 보내지 않는다.
- 파티장과 확정 파티원이 필요할 때 수동으로 알림 전송을 요청한다.
- 클라이언트가 FCM 서버 자격 증명이나 다른 사용자의 토큰을 직접 다루지 않는다.
- 서버 명령이 요청자의 모집 참가 여부, 수신 대상, 모집 상태, 쿨다운 및 중복 요청 키를 검증한다.
- 서버는 사용자별 활성 FCM 토큰으로 푸시를 전송하고 전송 요청 이력을 저장한다.
- 알림을 누르면 해당 모집 상세 화면으로 이동할 수 있도록 `recruitmentId`와 알림 종류를 데이터에 포함한다.
- 자기 자신을 수신 대상에서 제외하고, 알림 권한 거부나 만료 토큰은 정상적인 부분 실패로 처리한다.
- FCM 연결 전 로컬 구현은 실제 전송 성공으로 오인되지 않도록 준비 중 또는 미연결 상태를 명확히 표시한다.

- 후보의 역할별 아이템 레벨·전투력은 모집 생성, 지원 및 파티 내 캐릭터 변경에서 같은 표시 모델을 사용한다.
- 전투력 등 큰 숫자는 공용 숫자 포매터로 소수점을 버리고 천 단위 쉼표를 적용한다.

#### 구현 상태

- 모집 생성, 지원 및 파티 내 캐릭터 변경 후보가 공용 세팅 표시 모델을 사용한다.
- 역할별 아이템 레벨과 전투력을 소수점 없이 천 단위 쉼표 형식으로 표시한다.
- 전투력 없음과 최소 전투력 미달 안내를 동일한 표현으로 제공한다.
- 자동 제목은 난이도 표시 별칭, 숙련도와 최소 전투력 조건을 순서대로 반영한다.
- 수동 제목은 조건 변경으로 덮어쓰지 않으며, 제목을 모두 삭제하면 자동 제목 모드로 복귀한다.
- 최소 전투력의 빈 값과 `0`은 제한 없음으로 정규화한다.
- 관련 단위·위젯 테스트와 전체 정적 분석 및 자동 테스트가 통과했다.

### 작업 그룹 2. 전체 모집 수정

현재 작업 브랜치: `codex/full-recruitment-edit`

#### 목표

- 상세 화면의 제한적인 레이드·난이도 팝업을 기존 모집 정보를 초기값으로 사용하는 전체 화면 `모집 수정` 흐름으로 교체한다.
- 모집 생성과 수정이 같은 입력 모델, 검증, 자동 제목 및 숫자 정규화 규칙을 사용한다.

- 파티장, 확정 파티원과 pending 신청자의 영향 사유를 변경 확정 전에 표시
- 입장 불가능한 참가자 자동 퇴장 및 pending 신청 자동 종료 금지

- 파티장 캐릭터 및 저장 역할 변경
- 참가자 퇴장·교체, 모집 종료·삭제와 이미 처리된 신청 상태 변경

4. Repository와 Command를 제목·Metadata·지원 정책 통합 수정 명령으로 확장한다.
5. 파티장, 확정 파티원 및 pending 신청자의 변경 영향 계산 모델을 구현한다.
6. 변경 전후 값과 영향 대상을 표시하는 검토 화면을 연결한다.
7. revision 충돌, 구성 불가와 저장 실패를 구분하고 기존 상태를 보존한다.
8. Domain, Widget, 전체 회귀 테스트와 정적 분석을 실행한다.

- 사용자가 모집 제목을 입력하지 않았을 때만 자동 제목을 적용한다.
- 조합 순서는 `난이도별 게임 내 별칭 → 숙련도 → 최소 전투력 → 모집`이다.
- 게임 내 별칭은 레이드 카탈로그 난이도의 `displayAlias`를 사용한다.
- 설정되지 않은 숙련도와 최소 전투력은 제목에서 생략한다.
- 최소 전투력은 천 단위 쉼표를 적용하고 별도의 `이상` 문구 없이 숫자만 표시한다.
- 최소 전투력의 빈 값과 `0`은 동일하게 제한 없음으로 처리하며 제목에서 생략한다.
- 제목을 직접 편집했더라도 최종적으로 모두 삭제한 경우에는 자동 제목 규칙을 다시 적용한다.
- 예: 세르카 하드, 추가 조건 없음 → `하르카 모집`
- 예: 세르카 나이트메어, 반숙, 최소 전투력 5,000 → `나르카 반숙 5,000 모집`
