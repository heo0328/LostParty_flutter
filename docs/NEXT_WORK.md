## 다음 작업 그룹: 본계정·부계정 등록 및 관리

현재 데이터 모델과 조회 계약은 여러 소유 계정을 지원하지만, 사용자가 앱 화면에서 본계정과 부계정을 구분해 추가·관리하는 기능은 없다. 다음 작업에서는 계정 등록·구분·수정 UI와 저장 흐름을 구현한다.

권장 기능 브랜치명: `codex/account-management`

## 포함 범위

- 본계정 1개와 부계정 여러 개의 등록·구분·표시
- 계정 추가, 표시명 수정 및 계정 구분 변경
- 대표 캐릭터와 계정별 표시 캐릭터 관리 흐름 연결
- 기존 단일 계정 데이터의 마이그레이션과 호환성 검증
- 모집 생성·지원·캐릭터 변경 후보에서 계정 구분 표시 검증
- 관련 자동 테스트와 사용자 실기기 체크리스트

## 구현 순서

1. 기존 계정 Entity·Drift 스키마·Repository의 다계정 지원 범위를 확인한다.
2. 본계정 유일성 및 부계정 등록 규칙을 Domain에 정의한다.
3. 저장 계층과 기존 데이터 마이그레이션을 구현한다.
4. 내 계정 화면에 계정 추가·수정·구분 UI를 연결한다.
5. 모집 관련 캐릭터 선택 화면의 계정 표기를 검증한다.
6. 관련 테스트 후 `flutter analyze`와 전체 `flutter test`를 실행한다.
7. 실기기 체크리스트 결과를 기록하고 문서를 갱신한다.

## 후속 작업 그룹

1. 캐릭터 아이템 레벨에 따른 입장 가능 레이드·난이도만 표시하고, 가능한 최고 난이도를 기본 선택
2. 모집 생성 및 지원 캐릭터 화면의 전투력 표시 규칙 통일과 빈 제목 기본값 `파티모집합니다.` 적용
3. 사용자가 선택한 경우에만 디바이스 로컬에 최근 레이드 조건을 기억하고 다음 생성·지원에 재사용
4. `DETAIL_IMPROVEMENTS.md`에 기록된 모집 상세 위치·가입 조건 변경과 시너지 조건·필터 작업

## 완료 조건

- 사용자가 본계정과 부계정을 직접 구분해 등록하고 수정할 수 있다.
- 본계정 유일성과 기존 데이터 호환이 보장된다.
- 모집 관련 후보 화면에서 계정 구분이 일관되게 표시된다.
- 관련 테스트, `flutter analyze`, 전체 `flutter test`가 통과한다.
- 실기기 검증 결과와 다음 작업이 문서에 기록된다.
