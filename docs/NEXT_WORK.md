## 이번 작업 그룹의 목표

정적 `GameCatalogRepository`와 기존 `CharacterBuildAnalysisMapper`를 연결하여 Lost Ark API 응답에서 캐릭터의 깨달음 계열과 역할을 감지한다.

첫 연결은 기존 바드 전체 fixture를 사용한다. `진실된 용맹`과 `템페스트 필드`를 근거로 계열 통칭 `딜바드`와 감지 역할 `dealer`를 산출하는 흐름을 검증한다.

---

## 결정된 설계 원칙

- 직업은 Lost Ark API의 `CharacterClassName`으로 카탈로그에서 찾는다.
- 계열은 깨달음 1티어 노드를 주 기준으로 감지한다.
- 관련 추가 노드는 계열 감지 결과를 보강하는 근거로 사용한다.
- 감지 역할은 추천과 경고를 위한 분석 결과이며 저장 역할을 자동 확정하지 않는다.
- 실제 스냅샷 저장 위치는 사용자가 선택한 `CharacterBuildRole`을 계속 우선한다.
- `GameCatalogRole`과 `CharacterBuildRole`은 합치지 않고 연결 경계에서 명시적으로 변환한다.
- 감지 실패나 지원하지 않는 직업은 저장을 막는 예외가 아니라 표현 가능한 분석 결과로 다룬다.
- 정적 카탈로그, API 원본 JSON, 분석 결과 및 사용자 선택값의 소유 경계를 유지한다.
- 기존 로컬 스냅샷을 새 분석 결과 구조에서도 읽을 수 있도록 역호환성을 유지한다.

## 구현 범위

### Domain

- 카탈로그 기반 계열 및 역할 감지 결과 구조 정의
- 감지 성공, 미지원 직업, 계열 미감지 및 모호한 감지를 구분할 상태 정의
- 다음 정보를 결과에 포함:
  - 카탈로그 버전
  - 직업 식별자
  - 계열 식별자
  - 계열 표시 이름
  - 감지 역할
  - 일치한 깨달음 1티어 노드
  - 일치한 관련 패시브 노드
- 카탈로그 역할에서 캐릭터 세팅 역할로의 명시적 변환

### 분석 연결

- `ArmoryProfile.CharacterClassName`으로 직업 기준정보 조회
- `ArkPassive.Effects`에서 활성 패시브 노드 추출
- 깨달음 1티어 노드와 카탈로그 계열 비교
- 단일 계열 일치 시 계열 통칭과 역할 산출
- 관련 패시브 노드 일치 결과 기록
- 기존 룬, 보석 및 아크그리드 분석 결과와 결합

### 저장 경계

- 카탈로그 감지 결과를 세팅 분석 결과와 함께 저장하고 다시 읽을 수 있게 구성
- 기존 분석 JSON에 새 필드가 없어도 로딩 가능하도록 처리
- 사용자가 선택한 역할과 감지 역할이 달라도 사용자 선택 역할 위치에 저장

### 테스트

- `진실된 용맹` → `true_courage` → `딜바드` → `dealer`
- `템페스트 필드`가 관련 감지 근거에 포함됨
- `완벽한 화음` → `perfect_harmony` → `바드` → `support`
- 카탈로그에 없는 직업
- 직업은 있지만 깨달음 계열이 감지되지 않는 응답
- 둘 이상의 계열이 일치하는 모호한 입력
- 과거 분석 JSON 역직렬화
- 감지 역할과 선택 역할이 다른 경우에도 선택 역할로 저장
- 기존 룬, 보석 및 아크그리드 분석 테스트 회귀 방지
