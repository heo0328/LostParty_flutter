모집 생성 및 지원에서 선택 캐릭터가 입장할 수 없는 레이드·난이도를 노출하지 않고, 입장 가능한 최고 난이도를 기본값으로 제공한다. 파티장은 모집 수정 화면에서 레이드·난이도를 변경할 수 있으며, 변경 결과 입장할 수 없게 된 참가자를 명확히 확인할 수 있어야 한다.

## 포함 범위

- 선택 캐릭터의 저장 세팅 아이템 레벨을 기준으로 입장 가능 여부 판정
- `minItemLevel`을 충족하는 활성 레이드·난이도만 선택지에 표시
- 입장 가능한 난이도 중 `displayOrder`가 가장 높은 난이도를 기본 선택
- 파티장 또는 지원 캐릭터 변경 시 현재 레이드·난이도 유효성 재검증
- 기존 선택이 무효가 되면 임의의 캐릭터로 교체하지 않고 사용자에게 재선택 안내
- 모집 생성과 지원 화면에서 동일한 입장 가능 판정 규칙 사용
- 파티장 모집 수정 화면에서 레이드·난이도 변경 지원
- 수정된 레이드·난이도의 `minItemLevel`을 기준으로 파티장, 신청자 및 확정 파티원 재검증
- 입장 불가능해진 참가자에 경고 아이콘과 사유를 표시하고 변경 확정 전에 영향 대상 안내
- 입장 불가능한 참가자를 자동 퇴장시키거나 다른 캐릭터로 임의 교체하지 않음
- 파티장과 확정 파티원이 사용할 수 있는 수동 알림 보내기 버튼의 UI 및 도메인 경계 정의
- 알림 버튼 최초 터치 시 `참가 인원에게 알림을 보냅니다.` 확인 알럿 표시
- 확인 후 연속 터치와 중복 요청을 막는 전송 중 상태 및 쿨다운 적용
- 관련 Domain, ViewModel/Widget 테스트와 사용자 실기기 체크리스트

## 향후 Firebase 수동 알림 연결 원칙

- 모집 내용 변경이나 참가 캐릭터 변경만으로 전체 참가자에게 자동 푸시를 보내지 않는다.
- 파티장과 확정 파티원이 필요할 때 수동으로 알림 전송을 요청한다.
- 클라이언트가 FCM 서버 자격 증명이나 다른 사용자의 토큰을 직접 다루지 않는다.
- 서버 명령이 요청자의 모집 참가 여부, 수신 대상, 모집 상태, 쿨다운 및 중복 요청 키를 검증한다.
- 서버는 사용자별 활성 FCM 토큰으로 푸시를 전송하고 전송 요청 이력을 저장한다.
- 알림을 누르면 해당 모집 상세 화면으로 이동할 수 있도록 `recruitmentId`와 알림 종류를 데이터에 포함한다.
- 자기 자신을 수신 대상에서 제외하고, 알림 권한 거부나 만료 토큰은 정상적인 부분 실패로 처리한다.
- FCM 연결 전 로컬 구현은 실제 전송 성공으로 오인되지 않도록 준비 중 또는 미연결 상태를 명확히 표시한다.

## 후속 모집 제목 기본값 규칙

- 사용자가 모집 제목을 입력하지 않았을 때만 자동 제목을 적용한다.
- 조합 순서는 `난이도별 게임 내 별칭 → 숙련도 → 최소 전투력 → 모집`이다.
- 게임 내 별칭은 레이드 카탈로그 난이도의 `displayAlias`를 사용한다.
- 설정되지 않은 숙련도와 최소 전투력은 제목에서 생략한다.
- 최소 전투력은 천 단위 쉼표를 적용하고 별도의 `이상` 문구 없이 숫자만 표시한다.
- 예: 세르카 하드, 추가 조건 없음 → `하르카 모집`
- 예: 세르카 나이트메어, 반숙, 최소 전투력 5,000 → `나르카 반숙 5,000 모집`
