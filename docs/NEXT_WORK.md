## 이번 작업 그룹의 목표

캐릭터 세팅 갱신 시 `CharacterBuildDraft`의 분석 결과와 저장 역할을 사용자가 확인한 뒤 승인한 경우에만 commit하는 미리보기 흐름을 구현한다.

감지 역할과 사용자가 선택한 저장 역할이 다르면 안내하되 특수 세팅 저장을 허용한다.

---

## 결정된 설계 원칙

- 세팅 갱신 버튼은 즉시 저장하지 않고 draft를 생성한다.
- draft 생성 중 기존 프로필과 역할별 스냅샷을 유지한다.
- 미리보기는 프로필, 계열 통칭, 감지 역할, 선택 저장 역할 및 주요 경고를 표시한다.
- 지원 직업은 dealer/support 저장 역할을 선택할 수 있고 일반 직업은 dealer로 제한한다.
- 감지 역할과 선택 역할이 다르면 안내하지만 commit을 차단하지 않는다.
- 사용자가 취소하면 draft를 폐기하고 DB를 변경하지 않는다.
- 승인 후 commit이 성공한 경우에만 저장된 스냅샷 목록을 다시 로드한다.

## 구현 범위

### ViewModel

- draft 조회, 미리보기, commit 진행 상태 분리
- 현재 draft와 저장 역할 선택 상태 관리
- 취소 시 draft 폐기
- 승인 시 `commitCharacterBuildDraft` 호출 및 스냅샷 새로고침
- API 조회 오류와 commit 오류를 기존 사용자 메시지 체계로 처리

### UI

- 상세 화면에서 세팅 갱신 후 미리보기 다이얼로그 또는 화면 표시
- 캐릭터 프로필과 카탈로그 계열/감지 역할 표시
- 룬, 보석, 아크그리드 분석 경고 요약 표시
- 지원 직업의 저장 역할 선택 및 역할 불일치 안내
- 취소와 승인 동작 제공

### 테스트

- 갱신 요청 후 commit 전 기존 스냅샷 유지
- 미리보기에서 draft 분석 결과 표시
- 취소 시 DB 및 화면 스냅샷 유지
- 승인 시 선택 역할로 commit
- 역할 불일치 안내 후에도 승인 가능
- 중복 조회 및 중복 commit 방지
- API 오류와 commit 오류 회귀 방지
