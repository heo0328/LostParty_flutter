## 2. 이전 소유자에게 남은 원정대 고아 관계 처리 — 설계 필요

### 목적과 기존 정책

다른 사용자가 원정대를 인증한 경우, 새 인증자는 기존 사용자의 그룹·참가·완료를 승계하지 않고
과거 기록에 막히지 않게 이용한다. 이 정책은 유지한다. 동시에 기존 방의 무효 참가가 방을 막거나
동일 캐릭터의 이전·새 참가를 모두 정상 인원으로 취급하지 않도록 처리한다.
새 사용자가 과거 방을 찾아 정리해야만 이용할 수 있게 만들지 않는다.

### 조사·결정 범위

이전 신청의 승인 차단, 진행 중 방의 참가 정리, 공대장 권한 상실 시 승계, 완료 반복방의 다음 주
제외, 마지막1인 해산, 동일 방 중복 가입을 연결해서 조사한다. 정리 시점·실행 주체·확인 UI·동시 요청
처리와 조회 실패 상태를 설계로 확정한다. 인증 시 모든 방 일괄 순회·삭제를 기본안으로 가정하지 않는다.
현재 완료 반복방의 단건 정리/복구 기능은 재사용 후보이며 활성방 전체 문제를 해결한 것으로 보지 않는다.
다른 원정대·정상 그룹 가입·과거 완료 이력·새 소유자의 새 참가 데이터는 보존한다.

### 근거와 완료 기준

재인증 후 동일 캐릭터가 같은 방에 두 명으로 보인 사용자 관찰을 대표 조사 사례로 삼는다.
새 사용자 이용과 남은 참가자의 방 정상 이용을 모두 확인해야 완료다. 실제 중복 데이터가 어떤
소유권 차수/참가 상태인지 확인 전 자동 교체나 삭제 방법을 확정하지 않는다.
기존 반복방 자격 확인 버튼의 오류는 이 조사에서 실패 단계와 권한을 구분한다.

## 두 작업 외 관찰·검증 한계의 취급

그룹 반복방 동일 직업 자리 교환 오류는 재가입 후 성공했고 원인은 미확정이다. 별도 구현 작업으로
착수하지 않고 재발 시 조사할 관찰로 보존한다. 기존 반복방 확인 버튼의 13시 이후 결과는 미보고다.
이전 전체 테스트22건 실패/analyze51건 및 수동 인증 만료 취소 정책 기대 불일치는 기존 참고 기록으로
남기며 해결로 바꾸지 않는다. 이것들을 현재 예정 기능 두 개와 혼합하거나 숨기지 않는다.
테스트 실행 목록은 사용자 요청에 따라 문서에 추가하지 않고 채팅에서 제공한다.
